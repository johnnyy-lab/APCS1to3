Q-08-01-R01串列元素索引原地修改與負向下標輸出追蹤 運行追蹤

對應 單元 8.1

下列 Python 程式執行後，畫面上會印出什麼結果？

nums = [10, 20, 30, 40, 50]
nums[1] = nums[0] + nums[-1]
nums[-2] = nums[1] // 2
print(nums[1], nums[3])
🎉 答對了！標準答案是 (A)
⚡ 速解

串列具備「可變性（Mutable）」，可直接透過索引修改元素值。nums[0] 為 10，nums[-1]（最後一項）為 50，兩者相加指派給 nums[1] 使其變為 60；隨後 nums[-2] 指向倒數第二項（即 nums[3]），被更新為 $60 // 2 = 30$。最終輸出為 60 30，秒選 (A)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作執行步驟追蹤：
  • 初始建立串列：nums = [10, 20, 30, 40, 50]，長度為 5。
  • 正負索引對照表：

```text

元素值: 10 20 30 40 50

正向索引: 0 1 2 3 4

負向索引: -5 -4 -3 -2 -1

```

  • 執行第一行指定運算：nums[1] = nums[0] + nums[-1]
  • nums[0] 讀取索引 0 的數值：10。
  • nums[-1] 讀取倒數第 1 個數值：50。
  • 運算 $10 + 50 = 60$。
  • 將數值 60 寫入索引 1，此時串列狀態更新為：[10, 60, 30, 40, 50]。
  • 執行第二行指定運算：nums[-2] = nums[1] // 2
  • nums[-2] 對應正向下標 $5 - 2 = 3$（原本數值為 40）。
  • 讀取已更新的 nums[1]（值為 60），計算整數除法 $60 // 2 = 30$。
  • 將數值 30 寫入索引 3（nums[-2]），此時串列狀態更新為：[10, 60, 30, 30, 50]。
  • 執行輸出：print(nums[1], nums[3])
  • 依序印出 nums[1]（值為 60）與 nums[3]（值為 30），以空格分隔顯示為 60 30。故選 (A)。
  1. 選項逐項診斷：
  • (A) 精準掌握串列元素原地指定與負索引 -2 對應下標 3 之更新歷程。
  • (B) 誤以為 nums[-2] 修改的是別的元素，使得 nums[3] 仍保持原本的 40。
  • (C) 負向索引計算錯誤，誤將最後一個元素當作 40。
  • (D) 輸出變數順序看反。
  1. APCS 考場心法與常見陷阱：
  • 串列與字串的最大差異：字串不可變（執行 s[1] = 60 會引發 TypeError），而串列是可變物件（Mutable），可隨時透過中括號索引指定新數值！在追蹤題中，務必隨時記錄串列各格位的最新數值狀態。

Q-08-01-R02串列相鄰元素差值走訪累加輸出追蹤 運行追蹤

對應 單元 8.1

下列 Python 程式執行後，畫面上會印出什麼結果？

data = [3, 7, 2, 8]
diff_sum = 0
for i in range(len(data) - 1):
    diff_sum += data[i + 1] - data[i]
print(diff_sum)
🎉 答對了！標準答案是 (B)
⚡ 速解

這是數學上的「望遠鏡級數（Telescoping Sum）」對消求和！走訪相鄰差值 $(data[1]-data[0]) + (data[2]-data[1]) + (data[3]-data[2])$，中間所有項次全數正負抵消，最終結果必定剛好等於「最後一項減去第一項」：$data[3] - data[0] = 8 - 3 = 5$，秒選 (B)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作迴圈迴圈走訪推導：
  • 串列 data = [3, 7, 2, 8]，長度為 4。
  • range(len(data) - 1) 即 range(3)，產生的走訪索引 $i$ 依序為 0, 1, 2。
  • 初始累加器：diff_sum = 0。
  • 第 1 次迴圈（$i = 0$）：
  • 計算差值：data[1] - data[0] = 7 - 3 = 4。
  • 累加更新：diff_sum = 0 + 4 = 4。
  • 第 2 次迴圈（$i = 1$）：
  • 計算差值：data[2] - data[1] = 2 - 7 = -5。
  • 累加更新：diff_sum = 4 + (-5) = -1。
  • 第 3 次迴圈（$i = 2$）：
  • 計算差值：data[3] - data[2] = 8 - 2 = 6。
  • 累加更新：diff_sum = -1 + 6 = 5。
  • 迴圈結束，印出最終結果 5。故選 (B)。
  1. 選項逐項診斷：
  • (A) 僅計算了第一次迴圈的差值。
  • (B) 正確追蹤完整迴圈累加或運用對消性質求得答案。
  • (C) 誤將最後一個元素本身輸出。
  • (D) 誤將所有元素全部相加（$3+7+2+8=20$ 且計算錯誤）。
  1. APCS 考場心法與常見陷阱：
  • 走訪「相鄰兩元素」時，迴圈上限必須嚴格設定為 len(data) - 1，否則在存取 data[i + 1] 時必定會踩到索引越界 IndexError 的地雷！
  • 此外，記住對消求和模型：$\sum_{i=0}^{n-2} (a_{i+1} - a_i) = a_{n-1} - a_0$，在考試中能節省大量手算時間。

Q-08-01-F01enumerate 同步走訪索引與元素程式填空 程式填空

對應 單元 8.1

小明想走訪同學成績串列 scores = [85, 92, 78, 96]，並依序印出每位同學的座號（由 1 開始起算）與成績。預期輸出格式如下：

No.1: 85
No.2: 92
No.3: 78
No.4: 96

請問空格處 ______ 應填入下列哪一個內建函式呼叫？

scores = [85, 92, 78, 96]
for idx, val in ______:
    print(f"No.{idx}: {val}")
🎉 答對了！標準答案是 (C)
⚡ 速解

Python 中能同時拆解「計數序號」與「元素本體」的標準內建函式是 enumerate()；第二個參數傳入 1 代表起始編號由 1 開始，即 enumerate(scores, 1)，秒選 (C)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作語法機制與功能剖析：
  • 需求目標：在 for 迴圈中同時解包出兩個變數：座號編號 idx（1, 2, 3, 4）與成績 val（85, 92, 78, 96）。
  • 內建函式 enumerate() 解析：
  • 基本語法：enumerate(iterable, start=0)
  • 它會將可迭代物件包裝為產出 (index, value) 元組的疊代器。
  • 第二個參數可指定計數起始值（預設為 0）。
  • 傳入 enumerate(scores, 1) 時：
  • 第 1 輪產出 (1, 85) $\to$ idx=1, val=85
  • 第 2 輪產出 (2, 92) $\to$ idx=2, val=92
  • 第 3 輪產出 (3, 78) $\to$ idx=3, val=78
  • 第 4 輪產出 (4, 96) $\to$ idx=4, val=96
  • 完美匹配題幹輸出格式。故選 (C)。
  1. 選項逐項診斷：
  • (A) range(scores)：range() 的參數必須是整數，傳入串列會直接引發 TypeError: 'list' object cannot be interpreted as an integer。
  • (B) zip(scores)：只傳入一個參數時每次僅產出單一元素元組 (85,)，無法解包成兩個變數，且無自動序號功能。
  • (C) 正確使用 enumerate 並設定起始下標為 1。
  • (D) list() 只接受一個參數進行型態轉換，傳入兩個參數會引發 TypeError。
  1. APCS 考場心法與常見陷阱：
  • 許多初學者常寫出不夠簡潔的代碼：for i in range(len(scores)): print(f"No.{i+1}: {scores[i]}")。雖然也能運作，但使用 enumerate() 不僅程式碼優美可讀，且完全避免了手寫索引查找的錯誤風險！

Q-08-01-F02固定長度乘法預先配置統計串列程式填空 程式填空

對應 單元 8.1

某問卷評分滿意度為 1 到 5 分。程式欲建立一個長度為 6 的串列 count_table，初始值全為 0，使得索引 1 到 5 可以分別用來累加各評分出現的次數。請問空格處 ______ 應填入何者最適當？

# 建立長度為 6 且初值全為 0 的串列
count_table = ______
ratings = [5, 3, 5, 2, 4, 5]
for r in ratings:
    count_table[r] += 1
print(count_table[5])  # 輸出: 3
🎉 答對了！標準答案是 (C)
⚡ 速解

建立包含 $N$ 個預設值的串列，標準乘法展開語法為 [預設值] * N。欲建立 6 個 0 的串列應寫為 [0] * 6，秒選 (C)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作語法結構與功能剖析：
  • 題目需求：評分為 1~5，欲將評分數值直接當成下標存取（例如 count_table[5]），因此串列的合法索引必須涵蓋到 5。
  • 包含索引 0~5 的串列長度必須為 $5 + 1 = 6$。
  • 各統計位置初始計數必須為 0，即期望得到 [0, 0, 0, 0, 0, 0]。
  • **串列乘法語法 [元素] * 次數**：
  • [0] * 6 代表將包含單一元素 0 的串列重複串接 6 次。
  • 得到 [0, 0, 0, 0, 0, 0]，長度為 6。
  • 後續走訪各評分 r 時，直接以 count_table[r] += 1 執行常數時間的計數統計：
  • 走訪完 [5, 3, 5, 2, 4, 5] 後，5 出現了 3 次，count_table[5] 準確累加為 3。故選 (C)。
  1. 選項逐項診斷：
  • (A) [0 * 6]：括號內是整數乘法 $0 \times 6 = 0$，結果只是長度為 1 的串列 [0]，存取 count_table[r] 會立刻引發 IndexError。
  • (B) [6] * 0：將串列重複 0 次，結果為空串列 []。
  • (C) 正確透過序列乘法建立長度為 6 的數值計數串列。
  • (D) list(6)：list() 只能將可迭代物件轉為串列，傳入整數 6 會引發 TypeError: 'int' object is not iterable。
  1. APCS 考場心法與常見陷阱：
  • 計數排序法（Counting Sort）與頻率統計基礎：

在 APCS 處理範圍有限的整數計數時，預先配置 table = [0] * (MAX_VAL + 1) 是最經典、查詢效率最快（$O(1)$ 存取）的高分技巧！

Q-08-01-D01元素走訪與索引下標混淆誤用除錯 測試除錯

對應 單元 8.1

觀察下列 Python 程式碼，執行時會發生什麼情況？

nums = [10, 20, 30]
# 希望將串列中每個數值放大為 2 倍印出
for x in nums:
    print(nums[x] * 2)
🎉 答對了！標準答案是 (B)
⚡ 速解

for x in nums: 是「直接走訪元素」，變數 x 本身就已經是 10, 20, 30！寫成 nums[x] 就會變成 nums[10]，但串列長度只有 3，合法下標僅有 0, 1, 2，必定引發 IndexError，秒選 (B)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作錯誤原因剖析：
  • 串列 nums = [10, 20, 30]，長度為 3。
  • 合法正向索引為 0, 1, 2。
  • 檢視迴圈敘述：for x in nums:
  • 這是 Python 的「元素迭代（Element Iteration）」語法。
  • 迴圈第 1 輪取出的是第一個元素本身：x = 10（而非索引 0）。
  • 檢視迴圈主體：print(nums[x] * 2)
  • 直譯器嘗試計算 nums[10]。
  • 因為最大合法索引只有 2，直譯器立即拋出嚴重執行階段錯誤：

IndexError: list index out of range。

  • 程式當場中斷崩潰，根本無法印出任何內容。
  • 正確修改方式：
  • 方式甲（推薦）：直接使用元素 print(x * 2)。
  • 方式乙（若真要用下標）：改寫為 for i in range(len(nums)): print(nums[i] * 2)。
  • 因此 (B) 的分析完全正確。故選 (B)。
  1. 選項逐項診斷：
  • (A) 誤以為 x 是索引 0, 1, 2，落入初學者最常見的走訪盲點。
  • (B) 正確指出元素與下標混淆導致的 IndexError 越界錯誤。
  • (C) 串列可以在迴圈內任意讀取，不會有型態錯誤。
  • (D) 乘法與 print 皆完全相容。
  1. APCS 考場心法與常見陷阱：
  • 走訪兩大流派切換口訣：
  • for x in nums: $\to$ x 是「值」，直接用 x，絕不要再包一層 nums[x]！
  • for i in range(len(nums)): $\to$ i 是「編號」，必須用 nums[i] 取值！
  • 牢記這兩者的分野，考場上絕不犯低級失誤！

Q-08-01-D02相鄰比較迴圈邊界越界 IndexError 排查 測試除錯

對應 單元 8.1

小明寫了下列程式碼，想檢查串列 nums 中有哪些元素比其「緊鄰的下一個元素」還要大，並將其印出。

nums = [4, 7, 1, 9]
for i in range(len(nums)):
    if nums[i] > nums[i + 1]:
        print(nums[i])

請問這段程式執行後的結果為何？

🎉 答對了！標準答案是 (B)
⚡ 速解

串列長度為 4，最大合法索引為 3。當迴圈跑到最後一輪 $i = 3$ 時，nums[i + 1] 存取了 nums[4]，造成嚴重的索引超界崩潰（IndexError），秒選 (B)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作迴圈邊界追蹤：
  • 串列 nums = [4, 7, 1, 9]，len(nums) = 4。
  • 合法正向下標集合為：{0, 1, 2, 3}。
  • 迴圈設定為 range(len(nums))，即 $i$ 依序為 0, 1, 2, 3。
  • 執行歷程追蹤：
  • $i = 0$：比較 nums[0] > nums[1]（$4 > 7$ 為 False）。
  • $i = 1$：比較 nums[1] > nums[2]（$7 > 1$ 為 True），印出 7。
  • $i = 2$：比較 nums[2] > nums[3]（$1 > 9$ 為 False）。
  • $i = 3$（地雷引爆）：
  • 直譯器嘗試評估條件式：nums[3] > nums[3 + 1]。
  • 存取 nums[4]，但串列最大下標僅為 3！
  • 立即引發 IndexError: list index out of range，程式異常終止。
  • 正確修正方式：
  • 相鄰比較時，迴圈終點應保留 1 格緩衝：for i in range(len(nums) - 1):。
  • 因此 (B) 精準指出錯誤所在。故選 (B)。
  1. 選項逐項診斷：
  • (A) 比較同串列元素語法完全合法，絕非語法錯誤。
  • (B) 準確指出末尾元素下標加一越界引發 IndexError。
  • (C) 雖然中間有印出 7，但程式最終引發崩潰，並非「無任何錯誤正常結束」。
  • (D) Python 串列存取絕對不會自動循環回繞（Wrap-around）。
  1. APCS 考場心法與常見陷阱：
  • 「查相鄰必減一」！只要迴圈內出現 i + 1，range 的長度上限就必須減 1（len(a) - 1）；如果出現 i + 2，上限就必須減 2。這是歷屆 APCS 學科題目最常設計的越界除錯考點！

Q-08-01-P01串列單一索引隨機存取時間複雜度分析 效能分析

對應 單元 8.1

已知串列 nums 包含 $N$ 個整數。在 Python 直譯器中，執行任意單一索引讀取或修改指令（例如 val = nums[k] 或 nums[k] = val，其中 $0 \le k < N$），其底層時間複雜度量級為何？

🎉 答對了！標準答案是 (A)
⚡ 速解

Python 串列底層是以「連續記憶體動態陣列」實作。只要給定下標 $k$，CPU 藉由簡單的基底乘加定址 $\text{Address} = \text{Base} + k \times \text{Size}$ 便能瞬間直達記憶體單元，因此隨機存取的時間複雜度為嚴格的 $O(1)$ 常數時間，秒選 (A)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作底層資料結構與硬體定址剖析：
  • 在 Python（CPython）中，list 物件底層並非鏈結串列（Linked List），而是由連續記憶體區塊（Contiguous Array of Pointers）實作。
  • 串列在記憶體中的儲存架構如下：

$$\text{記憶體位址}(nums[k]) = \text{BaseAddress} + k \times \text{PointerSize}$$

  • 定址與存取機制：
  • BaseAddress 是陣列首項在記憶體中的固定起點。
  • PointerSize 是指向物件指標的固定長度（64 位元架構下為 8 位元組）。
  • 無論 $N$ 是一萬還是一億，CPU 都只需執行一次極速的加法與乘法硬體指令，便能直接算出記憶體實體位址並讀寫資料。
  • 存取耗時完全獨立於串列大小 $N$，亦完全獨立於索引 $k$ 的大小！
  • 因此，隨機存取（Random Access）的時間複雜度為 $O(1)$。故選 (A)。
  1. 選項逐項診斷：
  • (A) 精確符合連續陣列 $O(1)$ 隨機存取的理論與底層規範。
  • (B) $O(\log N)$ 是二元搜尋樹或二分搜尋的量級，單純下標讀取無需二分。
  • (C) $O(N)$ 是鏈結串列走訪或線性搜尋的量級。
  • (D) 鏈結串列（Linked List）存取第 $k$ 個節點才需要 $O(k)$ 步，Python 串列是陣列結構故非 $O(k)$。
  1. APCS 考場心法與常見陷阱：
  • 牢記常見操作的大 $O$ 複雜度：
  • 索引隨機讀取 / 指定：nums[k] $\implies O(1)$
  • 末端加入元素：nums.append(x) $\implies O(1)$
  • 線性走訪：for x in nums: $\implies O(N)$
  • 成員搜尋：x in nums $\implies O(N)$

Q-08-01-P02元素走訪 vs 索引查表走訪效能與機制對比 效能分析

對應 單元 8.1

在 Python 中，考慮下列兩段走訪包含 $N$ 個整數之串列 nums 的程式寫法：

# 寫法甲：直接迭代元素走訪
for x in nums:
    process(x)

# 寫法乙：透過下標索引查表走訪
for i in range(len(nums)):
    process(nums[i])

有關這兩種走訪方式在時間複雜度與直譯器底層操作上的對比，下列敘述何者**最正確**？

🎉 答對了！標準答案是 (C)
⚡ 速解

走訪全部 $N$ 個元素兩者都是 $O(N)$。但寫法甲是原生疊代器直接依序指派指標，寫法乙每圈都要「算 range、拿索引、串列查表、界限安全檢查」，常數項開銷較大。因此寫法甲更簡潔、更快且更符合 Pythonic 風格，秒選 (C)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作底層虛擬機位元碼（Bytecode）對照分析：
  • 時間複雜度評估：
  • 兩者都必須恰好巡訪串列中的所有 $N$ 個元素各一次。
  • 因此兩者在漸近時間複雜度上均嚴格為 $O(N)$。
  • 底層常數效率與操作差異：
  • 寫法甲（for x in nums）：
  • CPython 虛擬機直接使用底層 C 語言指標疊代器（GET_ITER 與 FOR_ITER）。
  • 指標循序向後滑動，直接獲取元素參考，完全無需透過 Python 層級傳遞整數下標。
  • 寫法乙（for i in range(len(nums))）：
  • 每一輪迴圈都必須先產生整數物件 i。
  • 執行 nums[i] 時，虛擬機必須執行 BINARY_SUBSCR 指令：
  1. 檢查 i 是否為整數。
  2. 檢查 i 是否超出陣列邊界（Bound Checking）。
  3. 計算偏移量取出指標。
  • 多了大量額外的直譯器操作負擔。
  • 因此寫法甲在實務效能與代碼乾淨度上皆優於寫法乙。故選 (C)。
  1. 選項逐項診斷：
  • (A) 遍歷 $N$ 個元素不可能達到常數時間 $O(1)$。
  • (B) 寫法甲絕非平方級 $O(N^2)$。
  • (C) 完整切中漸近時間同為 $O(N)$ 但底層疊代器省去下標開銷之精準對比。
  • (D) Python 3 的 range() 是惰性求值序列物件，佔用 $O(1)$ 常數記憶體，絕不會複製串列。
  1. APCS 考場心法與常見陷阱：
  • 什麼時候該用寫法甲？只需要元素值時（90% 的情境，程式碼最乾淨且速度最快）。
  • 什麼時候該用寫法乙？需要同時知道目前下標、或需要修改原串列元素、或需要比對相鄰前後項時。

Q-08-01-L01串列元素對稱交換 Swap 原地反轉邏輯分析 計算邏輯

對應 單元 8.1

下列 Python 程式執行後，畫面上會印出什麼結果？

arr = [10, 20, 30, 40]
arr[0], arr[-1] = arr[-1], arr[0]
arr[1], arr[2] = arr[2], arr[1]
print(arr)
🎉 答對了！標準答案是 (D)
⚡ 速解

第一步將首尾兩端元素（10 與 40）互換，得到 [40, 20, 30, 10]；第二步將內層中間兩元素（20 與 30）互換，得到 [40, 30, 20, 10]。整個串列恰好由外而內完成原地（in-place）全體反轉，秒選 (D)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作多元指定與交換邏輯追蹤：
  • 初始串列：arr = [10, 20, 30, 40]，下標 0~3 分別為 10, 20, 30, 40。
  • 第一階段指定：arr[0], arr[-1] = arr[-1], arr[0]
  • Python 多元指定機制：先在右側將 (arr[-1], arr[0]) 打包成臨時元組 (40, 10)。
  • 接著同時解包指定至左側：
  • arr[0] 被寫入 40。
  • arr[-1]（即 arr[3]）被寫入 10。
  • 此時串列內容變更為：[40, 20, 30, 10]。
  • 第二階段指定：arr[1], arr[2] = arr[2], arr[1]
  • 右側取當前數值 (arr[2], arr[1]) 打包為 (30, 20)。
  • 解包指定：
  • arr[1] 被寫入 30。
  • arr[2] 被寫入 20。
  • 此時串列內容變更為：[40, 30, 20, 10]。
  • 執行 print(arr)，印出 [40, 30, 20, 10]。故選 (D)。
  1. 選項逐項診斷：
  • (A) 誤以為多元指定無效。
  • (B) 只執行了第一階段外層交換，遺漏第二階段中間交換。
  • (C) 數值順序錯亂。
  • (D) 完整正確推導兩階段交換後串列的最終狀態。
  1. APCS 考場心法與常見陷阱：
  • 經典雙指針原地反轉核心思想：

本題示範了不使用額外記憶體、將陣列逆序反轉的經典演算法。在一般情況下，以迴圈 left = 0, right = len(a) - 1，每次執行 a[left], a[right] = a[right], a[left] 並向中間靠攏（left += 1; right -= 1），即可在 $O(N)$ 時間與 $O(1)$ 空間內完成反轉！

Q-08-01-L02原地累加動態計算前綴和陣列邏輯分析 計算邏輯

對應 單元 8.1

下列 Python 程式執行後，畫面上會印出什麼結果？

a = [2, 3, 5, 1, 4]
for i in range(1, len(a)):
    a[i] = a[i] + a[i - 1]
print(a[3], a[-1])
🎉 答對了！標準答案是 (D)
⚡ 速解

這是「原地計算前綴和（Prefix Sum）」！每一格 a[i] 加上前面已經算好的累加總和 a[i - 1]：前 4 項和 $2+3+5+1 = 11$（即 a[3]），前 5 項總和 $11 + 4 = 15$（即 a[-1]）。輸出為 11 15，秒選 (D)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作前綴和原地推導歷程：
  • 初始陣列：a = [2, 3, 5, 1, 4]，長度為 5。
  • 迴圈從 $i = 1$ 開始運行至 $i = 4$（共 4 輪）：
  • $i = 1$：
  • a[1] = a[1] + a[0] = 3 + 2 = 5
  • 陣列更新為：[2, 5, 5, 1, 4]
  • $i = 2$：
  • a[2] = a[2] + a[1] = 5 + 5 = 10
  • 陣列更新為：[2, 5, 10, 1, 4]
  • $i = 3$：
  • a[3] = a[3] + a[2] = 1 + 10 = 11
  • 陣列更新為：[2, 5, 10, 11, 4]
  • $i = 4$：
  • a[4] = a[4] + a[3] = 4 + 11 = 15
  • 陣列更新為：[2, 5, 10, 11, 15]
  • 迴圈結束後，串列 a 成功轉化為前綴和陣列。
  • a[3] 代表前 4 個原始數字的和：$2 + 3 + 5 + 1 = 11$。
  • a[-1]（即 a[4]）代表全部 5 個數字的總和：$11 + 4 = 15$。
  • 輸出為 11 15。故選 (D)。
  1. 選項逐項診斷：
  • (A) 誤以為只加了相鄰項而沒有連鎖累加效果。
  • (B) 計算偏移失誤。
  • (C) 最後一項計算錯誤。
  • (D) 準確計算連鎖累加後之正確前綴數值。
  1. APCS 考場心法與常見陷阱：
  • APCS 必考必殺技：前綴和（Prefix Sum）：

若要多次查詢區間 $[L, R]$ 內所有數字的總和，若每次都用迴圈求和需要耗費 $O(N)$；但若先花 $O(N)$ 建構前綴和陣列，任意區間總和即可透過減法常數時間秒殺：

$$\text{區間和}(L, R) = \text{prefix}[R] - \text{prefix}[L - 1]$$

此技巧在 APCS 觀念題與實作題皆極為關鍵！

Q-08-02-R01基礎切片與負步長反向跳取輸出追蹤 運行追蹤

對應 單元 8.2

下列 Python 程式執行後，畫面上會印出什麼結果？

lst = [10, 20, 30, 40, 50, 60]
a = lst[1:4]
b = lst[::-2]
print(a, b)
🎉 答對了！標準答案是 (A)
⚡ 速解

lst[1:4] 左閉右開取索引 1, 2, 3，得到 [20, 30, 40]；lst[::-2] 步長為 -2，從最末端字元（索引 5 的 60）開始倒退嚕跳步走訪，依序取出索引 5, 3, 1 的元素，得到 [60, 40, 20]。輸出為 [20, 30, 40] [60, 40, 20]，秒選 (A)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作執行步驟追蹤：
  • 串列 lst = [10, 20, 30, 40, 50, 60]，長度為 6，索引對照如下：

```text

元素值: 10 20 30 40 50 60

正向下標: 0 1 2 3 4 5

```

  • 第一個切片 a = lst[1:4]：
  • 起點 start = 1，終點 end = 4。
  • 遵守「左閉右開（含起點不含終點）」原則，取下標區間 $[1, 4)$，即索引 1, 2, 3。
  • 對應元素為 [20, 30, 40]。
  • 第二個切片 b = lst[::-2]：
  • 語法格式為 lst[start:end:step]。
  • 步長 step = -2（小於 0，代表由右向左倒退走訪）。
  • 省略起點 start：當步長為負時，直譯器預設從串列最末端元素開始（即索引 5）。
  • 省略終點 end：預設一路走訪到最左端且包含索引 0。
  • 走訪的索引序列為：$5, 5 - 2 = 3, 3 - 2 = 1$（下一項 $1 - 2 = -1$ 已過頭停止）。
  • 依序取出索引 5 (60)、索引 3 (40)、索引 1 (20)。
  • 得到串列 b = [60, 40, 20]。
  • print(a, b) 輸出為 [20, 30, 40] [60, 40, 20]。故選 (A)。
  1. 選項逐項診斷：
  • (A) 正確掌握常規切片區間與負步長省略邊界的倒退跳步規則。
  • (B) 誤將 lst[1:4] 的起點算成索引 0。
  • (C) 誤將負步長切片的起點當作倒數第二個元素 50。
  • (D) 誤將 lst[1:4] 當成包含終點 4 的雙閉區間。
  1. APCS 考場心法與常見陷阱：
  • 負步長切片起訖口訣：

當 step < 0 且前後冒號皆留空時（如 lst[::-k]）：

  • 起點「永遠是最後一個元素」！
  • 走訪方向「一律向左倒退」！
  • 只要先寫出最末端下標（len - 1），再每次扣除步長絕對值，便能神速且零失誤列出所有選取元素。

Q-08-02-R02串列切片指派不等長替換與長度動態變化追蹤 運行追蹤

對應 單元 8.2

下列 Python 程式執行後，畫面上會印出什麼結果？

nums = [1, 2, 3, 4, 5]
nums[1:4] = [99]
print(nums, len(nums))
🎉 答對了！標準答案是 (B)
⚡ 速解

這是串列專屬的「切片指派（Slice Assignment）」！nums[1:4] 選中了索引 1, 2, 3（元素 2, 3, 4），賦值時會將這整段區間一口氣「切除」，並原地填入右側串列中的所有元素 99。原串列縮水為 [1, 99, 5]，長度變為 3，輸出 [1, 99, 5] 3，秒選 (B)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作切片賦值底層機制剖析：
  • 初始串列：nums = [1, 2, 3, 4, 5]，長度為 5。
  • 分析左側切片目標：nums[1:4]
  • 起點 1，終點 4，選取的子串列為區間內的元素 [2, 3, 4]（佔據 3 個格位）。
  • 分析右側替換序列：[99]（長度為 1 的串列）。
  • 切片指派（Slice Assignment）兩步驟：
  • 步驟一（掏空）：直譯器將原串列中被切片選中的所有元素（2, 3, 4）完全剔除。
  • 步驟二（平鋪填入）：將右側可迭代物件（Iterable）中的元素，逐一拆解平鋪（Unpack）插入到掏空處，而非當成巢狀子串列塞入！
  • 因此，掏空後的空間僅填入單一元素 99。
  • 串列最終狀態變更為：[1, 99, 5]。
  • 元素總個數 len(nums) 由原先的 5 縮減為 3。
  • print(nums, len(nums)) 輸出為 [1, 99, 5] 3。故選 (B)。
  1. 選項逐項診斷：
  • (A) 誤以為會將 [99] 整包當成子串列插入（那是單一索引賦值 nums[1] = [99] 的行為，切片賦值會自動拆解平鋪）。
  • (B) 正確理解切片指派之區間取代與長度動態伸縮特性。
  • (C) 誤以為切片賦值只會修改單一格位。
  • (D) 誤以為右側單一元素會自動廣播（Broadcast）填滿 3 個格位。
  1. APCS 考場心法與常見陷阱：
  • 單一索引指派 vs 切片指派大對決：
  • nums[1] = [99] $\implies$ 索引 1 變成子串列：[1, [99], 3, 4, 5]（長度不變）。
  • nums[1:4] = [99] $\implies$ 區間被替換平鋪：[1, 99, 5]（長度縮短！）。
  • 透過切片指派，我們甚至能一行代碼完成「區間刪除」（nums[1:4] = []）或「任意位置插入多個元素」（nums[1:1] = [10, 20]），威力強大且是 APCS 的高頻核心陷阱！

Q-08-02-F01全切片獨立淺拷貝避免連帶修改程式填空 程式填空

對應 單元 8.2

小華撰寫了一段成績管理程式，希望保留一份歷史最高分串列的備份 backup。然而當後續新分數更新 scores[0] = 100 時，他不希望備份資料被意外連帶竄改，期望 backup[0] 依然能忠實保留原本的分數 90。請問空格處 ______ 應填入何者最適當？

scores = [90, 85, 78]
backup = ______
scores[0] = 100
print(backup[0])  # 期望輸出: 90
🎉 答對了！標準答案是 (C)
⚡ 速解

若直接寫 backup = scores 只是複製記憶體位址（參考別名），改一個兩個都會變！使用全切片語法 scores[:] 會建立一個包含所有元素之「全新獨立串列物件（淺拷貝）」，互不干擾，秒選 (C)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作記憶體物件參照分析：
  • 若填入 (A) backup = scores（物件別名陷阱）：
  • Python 中的變數是標籤（Reference）。
  • 此賦值僅讓 backup 與 scores 指向同一塊記憶體位址中的同一個串列實體。
  • 當執行 scores[0] = 100 時，因為實體被修改，print(backup[0]) 也會跟著變成 100，備份完全失效！
  • 若填入 (C) backup = scores[:]（切片獨立複製）：
  • scores[:] 省略起點與終點，代表對整條串列進行切片。
  • Python 切片操作必定會向作業系統申請一塊全新的記憶體空間，建立一個全新的串列物件，並將舊串列的所有元素參考複製過去。
  • 此時 backup 與 scores 分屬兩個不同的實體物件（backup is not scores）。
  • 後續修改 scores[0] = 100 僅影響原串列，backup 內的元素依然維持原本的 [90, 85, 78]。
  • print(backup[0]) 順利印出 90。故選 (C)。
  1. 選項逐項診斷：
  • (A) 造成變數參考共用（Alias），無法達到獨立備份目的。
  • (B) scores[0] 只取出單一整數數值 90，backup 不再是串列，後續若存取 backup[0] 會引發 TypeError: 'int' object is not subscriptable。
  • (C) 正確運用全切片建立獨立拷貝。
  • (D) scores[0:1] 只會切出包含單一元素的串列 [90]，遺失了後續的分數資料。
  1. APCS 考場心法與常見陷阱：
  • 複製一維串列最快三大正宗解法：
  1. 全切片：backup = scores[:]
  2. 內建轉型：backup = list(scores)
  3. 物件方法：backup = scores.copy()
  • 在 APCS 題型中，切片 scores[:] 是最簡短且跨版本最廣為認可的淺拷貝寫法！

Q-08-02-F02等差步長切片提取奇數索引位置元素程式填空 程式填空

對應 單元 8.2

給定一個資料串列 arr = [10, 20, 30, 40, 50, 60]。某演算法需要取出其中**所有奇數索引位置**（即索引 1, 3, 5）的數值，組成一個新的子串列 odds = [20, 40, 60]。請問空格處 ______ 應填入下列哪一個切片運算式？

arr = [10, 20, 30, 40, 50, 60]
odds = ______
print(odds)  # 輸出: [20, 40, 60]
🎉 答對了！標準答案是 (C)
⚡ 速解

奇數下標序列為 1, 3, 5...，公差（步長）為 2，起點必須設定為 1。省略終點到底，步長設為 2，即為 arr[1::2]，秒選 (C)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作切片運算式結構推導：
  • 觀察串列元素與索引對應：

```text

下標: 0 1 2 3 4 5

數值: 10 20 30 40 50 60

```

  • 目標抽取元素為：20（索引 1）、40（索引 3）、60（索引 5）。
  • 選取的索引序列為：$1, 3, 5$。
  • 切片語法三要素推導：
  • 起點 start：首個奇數索引為 1。
  • 終點 end：一路取到串列結尾，故直接省略。
  • 步長 step：每次增加 2，故設定為 2。
  • 綜上所述，標準運算式為 arr[1::2]。
  • 執行結果得到 [20, 40, 60]，完全符合題意。故選 (C)。

Q-08-02-P01串列切片之時間與額外記憶體空間複雜度分析 效能分析

對應 單元 8.2

已知串列 nums 包含 $N$ 個整數。執行切片運算式 sub = nums[A:B]（其中 $0 \le A < B \le N$，且切片選取的區間長度為 $K = B - A$）。請問在 Python 直譯器中，建立該子串列 sub 的時間複雜度與額外記憶體空間複雜度分別為何？

🎉 答對了！標準答案是 (D)
⚡ 速解

在 Python 中，串列切片並非單純建立檢視（View），而是必須配置一塊剛好容納 $K$ 個元素的新記憶體空間，並逐一複製這 $K$ 個元素的指標。因此時間複雜度為 $O(K)$，額外空間複雜度亦為 $O(K)$，秒選 (D)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作底層實作與複雜度推導：
  • 設切片區間包含的元素數量為 $K = B - A$。
  • 時間複雜度分析：
  • 直譯器執行切片時，先向作業系統申請大小為 $K$ 的記憶體區塊。
  • 接著必須循序走訪這 $K$ 個格位，將指標由原串列依序拷貝至新串列中。
  • 複製次數精準正比於切片長度 $K$。
  • 因此時間複雜度為 $O(K)$。
  • 空間複雜度分析：
  • 切片會建立一個完全實體化的全新 list 物件。
  • 該物件需要額外佔用容納 $K$ 個指標的記憶體空間。
  • 因此額外輔助空間複雜度為 $O(K)$。
  • 綜合兩者，時間與空間複雜度皆為 $O(K)$。故選 (D)。
  1. 選項逐項診斷：
  • (A) $O(1)$ 時間與空間是部分語言（或 NumPy 陣列視圖 View）的特性，原生 Python 串列切片是完整拷貝，絕非 $O(1)$。
  • (B) $O(N)$ 只有在切片長度 $K$ 逼近全體長度 $N$（如 nums[:]）時才成立；若僅切取 3 個元素（$K=3$），耗時僅為常數，與總長度 $N$ 無關。
  • (C) 切片為連續記憶體操作，不存在對數時間。
  • (D) 精準以切片長度 $K = B - A$ 表達時間與記憶體配置量級。
  1. APCS 考場心法與常見陷阱：
  • 許多同學常在迴圈內部寫切片：

```python

for i in range(n):

sub = nums[i:] # 每輪花費 O(N - i)

```

如果串列長度為 $N$，在迴圈中不斷切片會導致總時間複雜度暴增至 $O(N^2)$！在需要高效處理區間問題時，應盡量以雙指針索引下標代替直接切片複製。

Q-08-02-P02切片指派刪除前端元素之記憶體搬移成本分析 效能分析

對應 單元 8.2

已知串列 nums 的長度為 $N$。若執行切片賦值指令 nums[:1] = []（作用為將串列的第一個元素切除刪除），在 Python 動態陣列的底層實作中，該操作的時間複雜度為何？

🎉 答對了！標準答案是 (C)
⚡ 速解

Python 串列是連續動態陣列，一旦刪除最前面的首項元素，後續剩餘的 $N - 1$ 個元素指標全部都必須在記憶體中集體「向前平移一格」以填補空缺，因此時間複雜度為線性時間 $O(N)$，秒選 (C)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作連續陣列平移模型分析：
  • 串列 nums 在記憶體中是以連續位址存放指標：

```text

記憶體格位: [ 0 ] [ 1 ] [ 2 ] ... [ N-1 ]

原本指標: ptr0 ptr1 ptr2 ... ptrN-1

```

  • 執行 nums[:1] = [] 刪除索引 0 的元素。
  • 陣列長度必須從 $N$ 縮小為 $N - 1$。
  • 為維持連續記憶體特性，原本位於索引 1 到 $N - 1$ 的所有元素，必須依序往前挪移：
  • ptr1 移動至格位 0
  • ptr2 移動至格位 1
  • ...依此類推，總共需要進行 $N - 1$ 次指標搬移操作。
  • 搬移操作次數與長度 $N$ 成嚴格正比，故時間複雜度為 $O(N)$。故選 (C)。
  1. 選項逐項診斷：
  • (A) 只有在佇列（如 collections.deque）或鏈結串列中刪除首項才能達到 $O(1)$。
  • (B) 動態陣列無對數時間之搬移操作。
  • (C) 正確指出刪除前端導致後續所有元素平移之 $O(N)$ 成本。
  • (D) 只搬移一輪平移，非平方量級。
  1. APCS 考場心法與常見陷阱：
  • 串列頭尾操作效能對比：
  • 在尾端增刪：nums[-1:] = [] 或 nums.pop() $\implies O(1)$
  • 在前端增刪：nums[:1] = [] 或 nums.pop(0) $\implies O(N)$
  • 在 APCS 模擬佇列（Queue，先進先出 FIFO）時，若頻繁在 list 開頭刪除元素，會導致執行超時（TLE）！

  • nums.append(val) 運作機制：
  • CPython 動態陣列具備超額預先配置空間機制（Over-allocation）。
  • 大多數情況下，陣列末端已有閒置的預留格位，直接寫入指標並將長度計數器加 1 即可，耗時僅為 $O(1)$。

  • 目標是在索引 0 插入新元素。

  • 騰出第 0 格後才能將 val 寫入。
  • 耗時精準正比於當前長度 $N$，時間複雜度為 $O(N)$。
  • 效能影響對比：
  • 若在長度為 $N$ 的迴圈中連續呼叫 append，總耗時為 $N \times O(1) = O(N)$。

Q-08-04-P01串列長度查詢 len(lst) 之時間複雜度與底層快取機制 效能分析

對應 單元 8.4

已知串列 nums 包含 $N$ 個整數（例如 $N = 10^7$）。在 Python 直譯器中呼叫內建函式 len(nums) 取得串列長度，其時間複雜度量級為何？為什麼？

🎉 答對了！標準答案是 (C)
⚡ 速解

Python 串列物件在 C 底層的結構體自帶 ob_size 欄位，在增刪元素時隨時動態維護。呼叫 len(lst) 只是讀取一個整數變數，耗時嚴格為 $O(1)$ 常數時間，秒選 (C)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作 CPython 底層結構體解析：
  • 在 CPython 原始碼中，串列由 PyListObject 結構體定義：

```c

typedef struct {

PyObject_VAR_HEAD

PyObject **ob_item;

Py_ssize_t allocated;

} PyListObject;

```

  • 其中 PyObject_VAR_HEAD 巨集中包含了一個名為 ob_size 的整數欄位：
  • 當執行 append() 或切片賦值增加元素時，ob_size 自動加 1。
  • 當執行 pop() 刪除元素時，ob_size 自動減 1。
  • len(nums) 的執行過程：
  • 當 Python 程式碼呼叫 len(nums) 時，直譯器只需直接讀取記憶體中 nums->ob_size 的整數數值並回傳。
  • 過程中完全不需要走訪或掃描任何串列內的元素！
  • 無論串列長度是 10 個、10 萬個還是 10 億個，讀取耗時完全相同。
  • 因此，時間複雜度為嚴格的 $O(1)$ 常數時間。故選 (C)。
  1. 選項逐項診斷：
  • (A) 誤以為像 C 語言的 strlen()（遇 \0 結束）一樣需要遍歷。
  • (B) 串列不是樹狀結構。
  • (C) 精確指出 C 語言物件結構體維護 ob_size 欄位達成 $O(1)$ 快取讀取的本質。
  • (D) 長度讀取與內部元素內容或型態完全無關。
  1. APCS 考場心法與常見陷阱：
  • 哪些容器的 len() 是 $O(1)$？
  • Python 的所有內建序列與容器：list、str、tuple、dict、set，其 len() 通通都是 $O(1)$！
  • 因此在迴圈條件中放心寫 len(lst)，完全不必擔心會產生重複走訪計算長度的效能浪費！

Q-08-04-P02迴圈內部重複呼叫 count 統計頻率之效能退化分析 效能分析

對應 單元 8.4

考慮下列用來檢查串列 nums 中是否含有任何重複元素的程式碼：

# 檢驗串列中是否有任何重複元素
has_duplicate = False
for x in nums:
    if nums.count(x) > 1:
        has_duplicate = True
        break

已知串列 nums 的長度為 $N$。在最壞情況下（串列中所有元素皆不重複時），這段程式的時間複雜度量級為何？

🎉 答對了！標準答案是 (D)
⚡ 速解

外部 for 迴圈跑 $N$ 輪；內部每一次呼叫 nums.count(x) 都要重新把整個串列掃描一遍（花費 $O(N)$）。雙重疊加下總耗時達到 $N \times N = O(N^2)$ 平方時間，秒選 (D)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作最壞情況運算步數推導：
  • 串列長度為 $N$。
  • 假設最壞情況：串列中所有元素各不相同（例如 [1, 2, 3, ..., N]）。
  • 迴圈必須從第 1 個元素一路檢查到最後第 $N$ 個元素，才會結束。
  • 外部迴圈次數：總共執行 $N$ 次迭代。
  • 內部操作開銷：
  • 在每一輪迭代中，直譯器呼叫 nums.count(x)。
  • list.count() 方法的底層實作是從頭到尾線性比對 $N$ 個元素，耗時為 $O(N)$。
  • 總運算步數計算：

$$\text{總步數} = \sum_{i=1}^N O(N) = N \times O(N) = O(N^2)$$

  • 當 $N = 10^5$ 時，$N^2 = 10^{10}$ 次運算，在評測系統（通常上限每秒約 $10^7 \sim 10^8$ 次）中必定引發嚴重的執行超時（TLE）！
  • 因此最壞情況時間複雜度為 $O(N^2)$。故選 (D)。
  1. 選項逐項診斷：
  • (A) 常數時間與長度無關，顯然不符。
  • (B) $O(N)$ 忽略了每次 count() 都要完整掃描全陣列。
  • (C) $O(N \log N)$ 是先排序再相鄰比較的複雜度。
  • (D) 精準計算雙重線性掃描疊加之平方級時間複雜度。
  1. APCS 考場心法與常見陷阱：
  • 「迴圈裡面千萬別寫 count 或 index」！

在 for 迴圈裡寫 nums.count(x) 或 nums.index(x) 或 x in nums，表面上只有一層迴圈，但背後其實隱藏了第二層 $O(N)$ 掃描，實質上等同於「雙重巢狀迴圈」！

  • 考場遇到統計頻率或查重問題，應利用排序（$O(N \log N)$）或集合/計數陣列（$O(N)$）解決。

Q-08-04-L01移除單一極值元素後原串列結構與總和變化解析 計算邏輯

對應 單元 8.4

下列 Python 程式執行後，畫面上會印出什麼結果？

data = [10, 40, 20, 40, 10]
data.remove(max(data))
data.remove(min(data))
print(data, sum(data))
🎉 答對了！標準答案是 (A)
⚡ 速解

max(data) 是 40，remove(40) 只刪除第一個 40，串列變為 [10, 20, 40, 10]；min(data) 是 10，remove(10) 只刪除第一個 10，串列變為 [20, 40, 10]；剩餘總和為 $20 + 40 + 10 = 70$。輸出為 [20, 40, 10] 70，秒選 (A)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作各階段執行歷程剖析：
  • 初始建立：data = [10, 40, 20, 40, 10]。
  • 第一階段：data.remove(max(data))
  • max(data) 求得串列中的最大值為 40。
  • 執行 data.remove(40)：
  • 直譯器從左至右搜尋數值 40。
  • 在索引 1 找到第一個 40，並將其刪除。
  • 後續索引 3 的第二個 40 完好保留！
  • 串列狀態更新為：[10, 20, 40, 10]。
  • 第二階段：data.remove(min(data))
  • 此時 min(data) 求得當前串列中的最小值為 10。
  • 執行 data.remove(10)：
  • 直譯器從左至右搜尋數值 10。
  • 在索引 0 找到第一個 10，並將其刪除。
  • 最末尾的第二個 10 完好保留！
  • 串列狀態更新為：[20, 40, 10]。
  • 第三階段：計算總和並輸出
  • sum(data) = 20 + 40 + 10 = 70。
  • print(data, sum(data)) 印出 [20, 40, 10] 70。故選 (A)。
  1. 選項逐項診斷：
  • (A) 完整精確追蹤 remove 只刪首個匹配值後串列的真實保留狀態與總和。
  • (B) 誤以為 remove 會把所有的 10 與所有的 40 全部刪光，只剩下 20。
  • (C) 誤將最後一個 10 也一併刪除。
  • (D) 元素保留順序錯誤。
  1. APCS 考場心法與常見陷阱：
  • 本題將 remove 的「單次匹配特性」與 max()、min() 完美揉合。
  • 在追蹤包含重複元素的刪除操作時，切記「只刪第一個，後者不動」，絕不被多餘的重複值干擾！

Q-08-04-L02統計大於平均值之元素個數邏輯解析 計算邏輯

對應 單元 8.4

下列 Python 程式執行後，畫面上會印出什麼結果？

nums = [10, 50, 40, 20, 30]
avg = sum(nums) / len(nums)
above_count = 0
for x in nums:
    if x > avg:
        above_count += 1
print(avg, above_count)
🎉 答對了！標準答案是 (D)
⚡ 速解

總和為 $10 + 50 + 40 + 20 + 30 = 150$，長度為 5，浮點平均值 avg 為 30.0。嚴格大於 30.0 的元素有 50 與 40 兩個（30 等於平均值，不符合嚴格大於），計數為 2。輸出為 30.0 2，秒選 (D)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作平均值計算與條件比對追蹤：
  • 串列 nums = [10, 50, 40, 20, 30]，長度 len(nums) = 5。
  • 平均值計算：
  • sum(nums) = 150。
  • avg = 150 / 5 = 30.0（除法運算子 / 產生浮點數）。
  • 計數走訪歷程：
  • 初始：above_count = 0。
  • 元素 10：$10 > 30.0$ 為 False。
  • 元素 50：$50 > 30.0$ 為 True $\implies above\_count = 1$。
  • 元素 40：$40 > 30.0$ 為 True $\implies above\_count = 2$。
  • 元素 20：$20 > 30.0$ 為 False。
  • 元素 30：$30 > 30.0$ 為 False（嚴格大於 > 不包含等於）。
  • 迴圈結束，計數器最終值為 2。
  • print(avg, above_count) 印出 30.0 2。故選 (D)。
  1. 選項逐項診斷：
  • (A) 誤將等於 30 的元素也算入（誤當作大於等於 >=）。
  • (B) 少算了一個大於平均值的數值。
  • (C) 平均值計算錯誤。
  • (D) 正確計算浮點平均值與嚴格大於之統計個數。
  1. APCS 考場心法與常見陷阱：
  • 邊界符號細節：
  • 題目問「高於 / 大於」$\implies$ 嚴格大於 >。
  • 題目問「不低於 / 達平均」$\implies$ 大於等於 >=。
