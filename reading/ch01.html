Q-01-01-R01大小寫敏感（Case Sensitivity）與變數追蹤 運行追蹤

對應 單元 1.1

下列 Python 程式執行後，畫面上印出的結果為何？

score = 80
Score = 95
SCORE = 100
print(Score)
🎉 答對了！標準答案是 (B)
⚡ 速解

Python 嚴格區分大小寫，score、Score 與 SCORE 是三個完全獨立的變數。題目印出的是首字大寫的 Score，直接鎖定第 2 行賦值，秒選 (B) 95。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 記憶體參照模型：
  • 第 1 行 score = 80：建立全小寫名牌 score，參照整數物件 80。
  • 第 2 行 Score = 95：建立首字大寫名牌 Score，參照整數物件 95。
  • 第 3 行 SCORE = 100：建立全大寫名牌 SCORE，參照整數物件 100。
  • 這三個變數在直譯器的命名空間中各自獨立，互不干擾、互不覆蓋。
  1. 選項逐項診斷：
  • (A) 80：誤看成全小寫變數 score。
  • (B) 95：正確。第 4 行精確呼叫 Score。
  • (C) 100：誤看成全大寫變數 SCORE，或誤以為後續賦值會覆蓋同名不同大小寫的變數。
  • (D) SyntaxError：合法變數名稱，大小寫英文字母皆屬合法識別字字元。
  1. APCS 考場心法與常見陷阱：
  • 在紙本識讀測驗中，出題常利用肉眼視覺盲區微調大小寫。建議在試題紙上將變數的首字圈起來，立刻破除干擾。

Q-01-01-R02底線命名與變數參照複製 運行追蹤

對應 單元 1.1

下列 Python 程式執行後，畫面上印出的結果為何？

_data = 10
data_1 = _data
_data = 20
print(data_1)
🎉 答對了！標準答案是 (A)
⚡ 速解

純量賦值 data_1 = _data 是將當前數值複製給新變數。後續 _data = 20 重新賦值不會影響已完成賦值的 data_1，秒選 (A) 10。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 執行流程拆解：
  • 第 1 行：以底線開頭的 _data 合法宣告並指向整數 10。
  • 第 2 行：data_1 = _data 為純量數值的指定操作，此時 data_1 取得當前 _data 所參照的數值 10。
  • 第 3 行：_data = 20 將變數 _data 重新指向新的整數 20。這項重新指定動作並不會連帶改變先前已完成賦值的 data_1。
  • 第 4 行：print(data_1) 印出 data_1 的值，結果為 10。
  1. 選項逐項診斷：
  • (A) 10：正確答案。
  • (B) 20：誤以為 Python 整數賦值具有雙向指標聯動效果。
  • (C) _data：誤以為印出變數名稱字面值。
  • (D) NameError：底線開頭為合法的識別字，不會引發 NameError。
  1. 常見陷阱：
  • 在不可變物件（整數、浮點數、字串）中，賦值僅為參照指向，無連動更新機制。

Q-01-01-F01合法識別字命名規範 程式填空

對應 單元 1.1

程式欲宣告一個儲存使用者年齡的變數並印出數值 18。下列空格中填入哪一個變數名稱是合法的 Python 變數命名，且不會產生語法錯誤？

____ = 18
print(____)
🎉 答對了！標準答案是 (C)
⚡ 速解

識別字只能由英數底線組成、不得數字開頭、不得為關鍵字。(A) 有減號、(B) 數字開頭、(D) 是關鍵字 def，僅有 (C) user_age_2 完全合法，秒選 (C)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. Python 識別字命名四大鐵律：
  • 僅限英文字母（A-Z, a-z）、數字（0-9）、底線（_）。
  • 開頭第一個字元絕對不能是數字。
  • 嚴禁撞名 Python 保留關鍵字（Keyword，如 def, class, if, for 等）。
  • 不得包含任何運算符號（如 -, +, *）或空白。
  1. 選項逐項診斷：
  • (A) user-age：連字號 - 被判定為減法運算子，引發 SyntaxError: cannot assign to expression。
  • (B) 2nd_age：以數字 2 開頭，嚴重違規，拋出 SyntaxError: invalid decimal literal。
  • (C) user_age_2：由英文字母、底線與數字組成，以字母開頭，完全合法。
  • (D) def：為定義函式的保留關鍵字，不可作為變數名稱，會引發 SyntaxError: invalid syntax。
  1. 考場盲點：
  • 學生極常混淆底線 _ 與連字號 -。請記住：Python 只有「地板底線（underscore）」，沒有「半空中連字號（hyphen）」。

算有幾個 = 指派動作。第 1、2、3、4 行各進行 1 次變數賦值，第 5、6 行是 print 輸出非賦值，共 4 次，秒選 (C)。

  • 行 3：gamma = alpha（第 3 次賦值，建立變數 gamma 並指向 10）
  • 行 4：alpha = 30（第 4 次賦值，變數 alpha 重新指向 30，覆蓋舊值）

  • 行 6：print(beta)（標準輸出，非賦值）

  1. 觀念延伸：
  • 賦值運算子 = 在直譯器底層對應 STORE_NAME 或 STORE_FAST 指令，每次執行皆算一次獨立賦值操作。

Q-01-01-L01變數覆蓋（Overwrite）之記憶體模型語意 計算邏輯

對應 單元 1.1

閱讀下列 Python 程式碼片段，選出對變數 box 狀態與記憶體參照邏輯最精確的描述：

box = 5
box = 12
box = 99
🎉 答對了！標準答案是 (C)
⚡ 速解

純量變數多次賦值是「覆蓋（Overwrite）」舊值，最終只保存最後一次指定的 99，秒選 (C)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 記憶體參照邏輯：
  • Python 變數為指向物件的名牌。當執行 box = 5，box 指向 5；隨後 box = 12，名牌改貼到 12；最後 box = 99，名牌改貼到 99。原本的 5 與 12 失去引用後由記憶體回收機制自動管理。
  1. 選項逐項診斷：
  • (A) 自動形成清單：錯誤，純量賦值不會自動轉為串列 list。
  • (B) 重複指定語法錯誤：錯誤，Python 允許隨時重新指定變數。
  • (C) 正確。舊值被覆蓋，只保留最後一次的 99。
  • (D) 自動加總：錯誤，等號不是累加運算。
  1. 觀念延伸：
  • 若要累加必須顯式撰寫 box = box + 12 或 box += 12（1.4 節內容）。

Q-01-02-R01右側先算與自我更新追蹤 運行追蹤

對應 單元 1.2

下列 Python 程式執行後，畫面上印出的結果為何？

a = 10
b = 20
a = a + b
b = a - b
print(a, b)
🎉 答對了！標準答案是 (A)
⚡ 速解

先算右邊再存左邊。第 3 行 a 變成 10 + 20 = 30；第 4 行算右邊 a - b（此時 a 已經是 30，30 - 20 = 10），存入 b，b 變成 10。印出 30 10，秒選 (A)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 執行流程拆解：
  • 第 1 行：變數 a 賦值為整數 10。
  • 第 2 行：變數 b 賦值為整數 20。
  • 第 3 行 a = a + b：右式先求值 10 + 20 = 30，將 30 賦值給 a，覆蓋舊值，此時 a = 30。
  • 第 4 行 b = a - b：右式求值時使用最新的 a（30）與原本的 b（20），計算 30 - 20 = 10，賦值給 b，此時 b = 10。
  • 第 5 行：print(a, b) 印出 30 10。
  1. 選項逐項診斷：
  • (A) 30 10：正確答案。
  • (B) 10 20：誤以為賦值未生效。
  • (C) 30 20：誤以為第 4 行 b 沒有被更新。
  • (D) 30 -10：誤把第 4 行的減法順序看反或誤用原本舊的 a（10 - 20 = -10）。
  1. APCS 考場心法：
  • 逐行追蹤時，紙筆隨手將變數舊值劃掉改寫新值，嚴防引用到被覆蓋前的舊變數值。

Q-01-02-R02運算優先級與變數覆蓋 運行追蹤

對應 單元 1.2

下列 Python 程式執行後，畫面上印出的結果為何？

x = 3
y = 4
z = x + y * 2
x = z - x
print(x, z)
🎉 答對了！標準答案是 (A)
⚡ 速解

先乘除後加減。右式 y * 2 = 8，加 x（3）得 z = 11。下一行 z - x（11 - 3 = 8）存入 x。輸出 8 11，秒選 (A)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 執行流程拆解：
  • 第 1 行：x = 3。
  • 第 2 行：y = 4。
  • 第 3 行 z = x + y * 2：依運算子優先順序，乘法先算 4 * 2 = 8，再加 x（3）得 11，存入 z。
  • 第 4 行 x = z - x：右式 11 - 3 = 8，覆蓋更新 x = 8。
  • 第 5 行：print(x, z) 輸出 8 11。
  1. 選項逐項診斷：
  • (A) 8 11：正確答案。
  • (B) 11 11：誤以為 x 直接被賦值為 z。
  • (C) 14 14：誤以為由左至右先加再乘（(3 + 4) * 2 = 14）。
  • (D) 8 14：誤將第 3 行算成 14。
  1. 考場陷阱：
  • Python 的運算子優先順序與數學完全相同，乘除永遠高於加減。

Q-01-02-F01計數器累加更新空格填空 程式填空

對應 單元 1.2

在開發記分板程式時，初始分數為 score = 10。程式希望在發生得分事件時，讓 score 的數值在原本的基礎上增加 5 分，最終印出 15。下列哪一個選項填入空格後能完全符合此需求？

x + 10 = 25

⚡ 速解

  1. 語法錯誤本質：
  • 許多初學者會將數學方程式（如 $x + 10 = 25$）直接照抄到程式中。但在 Python 中，= 是「指定動作」而非「方程式求解器」。直譯器要求 = 的左側必須是可被指定的目標（Target），不能包含加減乘除運算子，否則拋出 SyntaxError: cannot assign to expression here. Maybe you meant '==' instead of '='?。

  • (C) 10 + x = 25 左側依然是運算式，同樣引發 SyntaxError。
  • (D) 改為 == 只是比較運算，在 x 未定義時會引發 NameError，且無法達成將 15 存入 x 的目標。
  1. 常見陷阱：
  • 程式語言不是代數解題器，所有運算過程必須由人類自行移項整理到等號右邊，交由電腦計算後存入左邊變數。

total = total + 100
print(total)

下列關於此錯誤的原因分析與除錯建議，何者最為精確？

🎉 答對了！標準答案是 (B)
⚡ 速解

先算右邊 total + 100，但 total 還沒生出來，拋出 NameError！必須先給初值 total = 0，秒選 (B)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 賦值順序與 NameError 成因：
  • 賦值運算的黃金順序是「先算右邊，再存左邊」。
  • 當直譯器執行第 1 行 total = total + 100 時，首先對右側運算式 total + 100 進行求值。此時直譯器在命名空間中尋找變數 total 的數值，但在此之前從未賦值過 total，找不到該變數箱子，因此立即中止並引發 NameError。

  • 累加型變數在首次引用前，必須先有基礎初值。
  • 在前方加上 total = 0，程式變為：

```python

total = 0

total = total + 100

print(total)

```

即可順利印出 100。故選 (B)。

  1. 選項診斷：
  • (A) total 只是普通單字，不是關鍵字。
  • (C) 加號兩側或等號兩側可使用同名變數（自我更新）。
  • (D) 大寫 Print 不存在，會引發另一個 NameError。

觀察下列 Python 程式片段：

num = 10
num = 20
num = num + 5
num = 40

🎉 答對了！標準答案是 (A)
⚡ 速解

每遇到一個單等號 = 就執行一次指派覆蓋，共 4 個等號即 4 次賦值。純量變數只存最後一次的 40，秒選 (A)。

  1. 賦值次數與執行效能剖析：
  • 第 1 行 num = 10：第 1 次賦值。
  • 第 2 行 num = 20：第 2 次賦值（覆蓋舊值 10）。
  • 第 3 行 num = num + 5：右側算得 25，執行第 3 次賦值（覆蓋舊值 20）。

  • Python 的純量整數變數是「覆蓋（Overwrite）」更新，變數名牌在每次賦值時重新指向新物件，絕不會自動保留歷史數值，亦不會自動加總。最終印出 40。故選 (A)。

  • (B) 錯誤，Python 不會略過重複賦值。
  • (C) 錯誤，數值不會自動累加成 75（10 + 20 + 25 誤算）。
  • (D) 錯誤，第 3 行依然是完整的賦值動作。

下列程式欲為三個指標變數計算基準加權值，三行程式皆重複計算了算式 10 * 20 + 30：

a = 10 * 20 + 30
b = 10 * 20 + 30
c = 10 * 20 + 30

若希望在維持完全相同運算結果的前提下，減少 CPU 重複計算的開銷並提升執行效能，下列哪一種重構方案最為優良？

  • (B) 引入浮點數除法，改變型態且增加運算。

  • (D) 數值完全錯誤（分別變成 10, 20, 30）。
  1. 實戰建議：
  • 在 APCS 實作題中，若有重複使用的昂貴算式，先算好存在暫存變數（如 base）再行使用，是避免逾時（TLE）的重要好習慣。
