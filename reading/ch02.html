  • 變數 c 參照浮點數物件 12.0，type(c).__name__ 為字串 'float'。

  • type(5) 回傳 <class 'int'>。
  • type(5.0) 回傳 <class 'float'>。

  • 數值比較 x == y：
  • Python 支援跨型態數值比較（Numeric Equality）。在比對 5 == 5.0 時，直譯器會將兩者在數值軸上對齊，數學上 5 與 5.0 數值相等，故回傳 True。

a = 5

斜線除法 / 必定產生浮點數 4.0，利用 Python 浮點數內建的 avg.is_integer() 判斷小數是否為 0，若為真則轉成 int(avg) 印出 4，否則保留原小數。秒選 (D)。

Q-02-01-D02浮點數精度極限與二進位捨入誤差除錯 測試除錯

對應 單元 2.1

下列 Python 程式執行後，畫面上印出的結果為何？背後成因為何？

x = 0.1 + 0.2
if x == 0.3:
    print("Equal")
else:
    print("Not Equal")
🎉 答對了！標準答案是 (A)
⚡ 速解

電腦科學界的經典常識：在二進位浮點數標準（IEEE 754）中，0.1 與 0.2 都是無窮循環小數，相加後等於 0.30000000000000004，絕對不等於 0.3，因此印出 Not Equal。秒選 (A)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. IEEE 754 二進位浮點數限制：
  • 人類慣用十進位（分母為 10 的因數 2 與 5 才能除盡，如 $1/2 = 0.5$、$1/5 = 0.2$、$1/10 = 0.1$）。
  • 但電腦硬體是二進位（分母只能是 2 的次方才能除盡，如 $1/2 = 0.5$、$1/4 = 0.25$、$1/8 = 0.125$）。
  • 十進位的 0.1 在二進位中是無限循環小數：$0.0001100110011..._2$。
  • 在 53 位元尾數長度限制下被迫截斷，因此 0.1 + 0.2 在記憶體中的實際數值是 0.30000000000000004。
  • 執行 0.30000000000000004 == 0.3 結果為 False，進入 else 區塊印出 Not Equal。故選 (A)。
  1. 工程防範方案：
  • 若需要比較兩浮點數是否相等，絕不可直接用 ==，應使用 math.isclose(a, b) 或 abs(a - b) < 1e-9。

⚡ 速解

先乘除後加減！乘法 4 * 3 = 12，整除 6 // 2 = 3。算式簡化為 20 - 12 + 3。加減同級由左至右算：20 - 12 = 8，8 + 3 = 11。秒選 (A) 11。

  • 加法與減法具備相同的優先級，依照「由左至右結合（Left-to-Right Associativity）」規則依序運算。
  • 先算左側減法：20 - 12 = 8。
  • 再算右側加法：8 + 3 = 11。

  • (B) 27：誤以為由左至右平鋪直敘計算（20 - 4 = 16，16 * 3 = 48...）。

  • 左移 n << k：二進位所有位元向左平移 $k$ 位，右側補 $k$ 個 0。數學上嚴格等價於 $n \times 2^k$。
  • 20 << 2 = 20 * 4 = 80。
  • 右移 n >> k：二進位所有位元向右平移 $k$ 位。在 Python 中，位元右移定義為算術右移（Arithmetic Shift），最高位保留符號位，數學上等價於向負無限大取整（Floor Division）：n // (2 ** k)。

  • 若負數不能被 $2^k$ 整除（例如 (-21) >> 2），其結果為 $-21 // 4 = -6$。而本題 $-20$ 剛好能被 4 整除，故商為 $-5$。

  • (B) 誤以為負數向負無限大取整會多減 1 變成 -6（只有不能整除時才會變成 -6）。

  1. Lowbit 原理與二補數慢動作推導：
  • 電腦系統中負數採用二補數（Two's Complement）表示，其數學定義為：$-x = \sim x + 1$（反轉所有位元再加 1）。

$$x = \text{[prefix]} \ 1 \ \underbrace{00\dots0}_{k\text{ 個 0}}$$

$$\sim x = \text{[反轉 prefix]} \ 0 \ \underbrace{11\dots1}_{k\text{ 個 1}}$$

$$-x = \text{[反轉 prefix]} \ 1 \ \underbrace{00\dots0}_{k\text{ 個 0}}$$

  • 此時將 $x$ 與 $-x$ 進行位元 AND（&）：
  • 前綴部分：$\text{[prefix]} \ \& \ \text{[反轉 prefix]} = 0$（全部抵消歸零）。

  • 結果精確等於僅保留最低位 1 的數值！

⚡ 速解

位元左移 1 << k 是現代 CPU 最原生的指令之一（單週期 Barrel Shifter），Python 整數物件底層直接將數位字組向左平移，免除通用的冪次方（Exponentiation）乘法與溢位評估迴圈。秒選 (A)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. CPU 硬體支援與演算法開銷：
  • 現代 CPU（x86、ARM 等）內部皆具備專門的桶式移位器（Barrel Shifter），無論移位多少位元，都能在單一或極少 CPU 週期內瞬間完成。
  • 次方運算子 ** 是通用數學冪函式（在 CPython 底層呼叫 long_pow），需要處理負指數、浮點數轉換、大數乘方分解等分支判斷，即使有快速冪（Binary Exponentiation），其常數乘法開銷仍遠大於直接位移。
  1. CPython 大整數物件的記憶體操作：
  • Python 的 int 支援任意長度（Arbitrary-precision），其底層是由陣列 digit[] 組成。
  • 1 << k 在 C 語言層級直接呼叫 long_lshift，相當於在記憶體陣列中直接搬移記憶體位元組並補 0（類似 memmove 與位移），效率極高。
  1. 選項陷阱診斷：
  • (B) 標準 CPython 並未對 2 ** k 進行 JIT 替換。
  • (C) 直譯器不會主動將 2 ** k 語法樹改寫為移位。

Q-02-07-L01XOR 自反性與單一奇數次出現元素求解邏輯 計算邏輯

對應 單元 2.7

給定一個非空整數串列 nums，其中只有一個數字出現了奇數次（1 次），其餘所有數字皆恰好出現了兩次。程式利用位元 XOR 運算求解：

nums = [4, 7, 2, 7, 4]
res = 0

for num in nums:
    res ^= num

print("Single number:", res)

執行這段程式後印出的結果為何？背後依據的數學與邏輯性質為何？

🎉 答對了！標準答案是 (C)
⚡ 速解

XOR 的四大核心性質：$x \oplus x = 0$、$x \oplus 0 = x$、交換律與結合律。成對出現的 4 與 7 各自抵消為 0，剩下唯一未抵消的 2。秒選 (C)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. XOR（互斥或 $\oplus$）之代數性質：
  • 自反性（Self-inverse）：任何數與自己做 XOR 恆等於 0，即 $x \oplus x = 0$。
  • 單位元素（Identity）：任何數與 0 做 XOR 保持不變，即 $x \oplus 0 = x$。
  • 交換律（Commutative）：$a \oplus b = b \oplus a$。
  • 結合律（Associative）：$(a \oplus b) \oplus c = a \oplus (b \oplus c)$。
  1. 演算法執行慢動作推導：
  • 初始值 res = 0。
  • 依序對串列元素進行 XOR：

$$\text{res} = 0 \oplus 4 \oplus 7 \oplus 2 \oplus 7 \oplus 4$$

  • 根據交換律與結合律，重新分組：

$$\text{res} = (4 \oplus 4) \oplus (7 \oplus 7) \oplus 2 \oplus 0$$

  • 成對項全數抵消歸零：

$$\text{res} = 0 \oplus 0 \oplus 2 \oplus 0 = 2$$

  • 輸出為 Single number: 2。
  1. 演算法優勢：
  • 此解法時間複雜度為 $O(N)$，且空間複雜度為極致的 $O(1)$（無需建立 Hash Table 或 Dict 記數），是 LeetCode 與 APCS 經典試題！

Q-02-07-L02無額外變數之 XOR 兩數互換演算法邏輯推導 計算邏輯

對應 單元 2.7

在不宣告任何第三輔助變數（如 temp）的情況下，工程師利用三次 XOR 運算完成兩個整數變數的內容交換：

a = 29
b = 15

# 三步 XOR 交換法
a = a ^ b  # 步驟 1
b = a ^ b  # 步驟 2
a = a ^ b  # 步驟 3

print(f"a={a}, b={b}")

執行這段程式後，畫面上印出的結果為何？

🎉 答對了！標準答案是 (B)
⚡ 速解

經典 XOR 交換三部曲：第一步儲存差異，第二步還原原 $a$ 給 $b$，第三步還原原 $b$ 給 $a$。兩數值完美互換，印出 a=15, b=29。秒選 (B)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作代數推導（設初值為 $A$ 與 $B$）：
  • 初始狀態：$a = A = 29$，$b = B = 15$。
  • 步驟 1 (a = a ^ b)：
  • $a$ 的新值為 $A \oplus B$。
  • 此時 $a$ 暫存了兩個數的所有相異位元資訊。
  • 步驟 2 (b = a ^ b)：
  • $b$ 的新值為 $(A \oplus B) \oplus B$。
  • 利用結合律與自反性：$(A \oplus B) \oplus B = A \oplus (B \oplus B) = A \oplus 0 = A$。
  • 此時變數 $b$ 成功取得了變數 $a$ 的原始數值 $29$！
  • 步驟 3 (a = a ^ b)：
  • 注意此時的 $a$ 仍為 $A \oplus B$，而當前 $b$ 已經變成 $A$。
  • $a$ 的新值為 $(A \oplus B) \oplus A$。
  • 利用交換律與結合律：$(A \oplus B) \oplus A = (B \oplus A) \oplus A = B \oplus (A \oplus A) = B \oplus 0 = B$。
  • 此時變數 $a$ 成功取得了變數 $b$ 的原始數值 $15$！
  1. 最終輸出驗證：
  • $a = 15$，$b = 29$。印出 a=15, b=29。故選 (B)。
  1. 程式語言實務附註：
  • 雖然 XOR 交換法在 C/組合語言中極富巧思且能省下暫存器，但在 Python 中，推薦使用語意更直觀、由 Bytecode ROT_TWO 優化的多重指定：a, b = b, a。
