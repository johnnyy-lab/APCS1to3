Q-06-01-R02負步進倒數 range 與迴圈控制變數生命週期追蹤 運行追蹤

答案 (D)

⚡ 速解

🔍 深度詳解（點擊展開慢動作拆解與常見陷阱）
  1. 執行流程拆解：
  • 起始狀態：變數 x 初始化為 10。
  • range(9, 2, -3) 參數解析：
  • start = 9（起始值）
  • stop = 2（終止界限，不包含 2）
  • step = -3（每次遞減 3）

  • 第 1 次（i = 9）：x = 10 + 9 = 19。
  • 第 2 次（i = 6）：x = 19 + 6 = 25。
  • 第 3 次（i = 3）：x = 25 + 3 = 28。

  1. 選項逐項診斷：
  • (A) 誤以為迴圈終止條件會把 stop 的值 2 賦值給 i。
  • (B) 誤以為 range 會跑到 2（$x = 28 + 2 = 30$）。
  • (C) 誤以為迴圈在第 1 次迭代後就中斷退出。

Q-06-01-F01正步進跳步輸出等差數列之 range 參數填空 程式填空

答案 (A)

⚡ 速解

目標數列首項為 10、公差為 +4、末項為 22。由「含頭不含尾」原則，終止界限必須大於 22（若填 22 則 22 本身會被排除而只印到 18）。因此 range(10, 23, 4) 產生的序列恰好是 10、14、18、22。秒選 (A)。

🔍 深度詳解（點擊展開慢動作拆解與常見陷阱）
  1. 目標數列分析：
  • 給定數列：10, 14, 18, 22。
  • 起始值（start）：10。
  • 公差步進（step）：$14 - 10 = 4$。
  • 末項數值：22。
  • 下一項理論值：$22 + 4 = 26$。
  1. 選項逐項診斷：
  • (A) range(10, 23, 4)：起點 10，每次加 4。由於終止值 23 大於 22 且小於等於 26，產生的序列為 10, 14, 18, 22，完全符合題目要求，為正確答案。
  • (B) range(10, 22, 4)：因為 range 不包含終止值 22，當 num 到達 18 後，下一項為 22（已達終止界限停止），僅會印出 10 14 18 ，缺少最後一項 22。
  • (C) range(10, 26, 2)：步進值為 2，會印出 10 12 14 16 18 20 22 24 ，公差與項數均不符。
  • (D) range(4, 23, 10)：起點為 4，每次加 10，會印出 4 14 ，數列完全錯誤。
  1. APCS 考場心法與常見陷阱：
  • 在撰寫正向 range(start, stop, step) 時，若希望末項 $L$ 被包含在內，則 $stop$ 必須設定在區間 $(L, L + step]$ 之間。常考陷阱即是直接將末項寫成 $stop$（如選項 B），導致末項遺失。

Q-06-01-F02負步進倒序走訪邊界設定填空 程式填空

答案 (C)

⚡ 速解

倒數從 5 到 1，公差為 -1。起點是 5，末項是 1。因為「含頭不含尾」，stop 必須設為 0 才能在碰到 0 前一刻停下，剛好取到 1。秒選 (C)。

🔍 深度詳解（點擊展開慢動作拆解與常見陷阱）
  1. 執行流程拆解：
  • 目標序列：5, 4, 3, 2, 1。
  • 由於數列是遞減的，必須使用負步進值 step = -1。
  • 起始值 start = 5。
  • 終止值 stop 的判定準則：在負步進情況下，迴圈持續執行的條件為「當前值 > stop」。因此若要最後一個走訪的值為 1，stop 必須設定為 0（因為 $1 > 0$ 成立，而下一項 $0 > 0$ 不成立停止）。
  • 因此填入 range(5, 0, -1)，將精確產生 5, 4, 3, 2, 1。
  1. 選項逐項診斷：
  • (A) range(5, 1, -1)：終止界限為 1，當值減到 1 時已達到界限而不執行，只會印出 5 4 3 2，漏掉了 1。
  • (B) range(5, -1, -1)：終止界限為 -1，當值為 0 時仍滿足 $0 > -1$，會多印出 0。
  • (C) 正確答案。
  • (D) range(1, 6, -1)：起點為 1，終點為 6，但步進值為 -1。因為起點小於終點且步進向負方向前進，Python 判定為空區間，迴圈 0 次完全不執行。
  1. APCS 考場心法與常見陷阱：
  • 倒數迴圈是觀念題極常見的陷阱題。記住口訣：「正數走訪 stop 比末項多 1，倒數走訪 stop 比末項少 1」。若要倒數到 1，stop 就是 $1 - 1 = 0$。

Q-06-01-D01修正迴圈邊界差一錯誤（Off-by-one Error） 測試除錯

答案 (C)

⚡ 速解

range(1, 5) 不含 5，所以只印到 4。要印到 5，終止值必須往後延伸 1 位改為 6，即 range(1, 6)。秒選 (C)。

🔍 深度詳解（點擊展開慢動作拆解與常見陷阱）
  1. 錯誤原因剖析：
  • 原程式碼中 range(1, 5) 傳入起點 1 與終點 5。
  • 依據 Python range 的左閉右開特性，走訪的數列為集合 $\{ x \in \mathbb{Z} \mid 1 \le x < 5 \}$，即 1, 2, 3, 4。
  • 這是程式設計中最著名的「差一錯誤」（Off-by-one Error），因為將人類直覺的「數到 5」直接填入終止參數，忽略了 Python 不包含終止值的規範。
  1. 選項逐項診斷：
  • (A) 改為 range(5)：單參數形式預設從 0 開始，會印出 0 1 2 3 4 ，不僅缺少 5 還多了 0。
  • (B) 改為 print(count + 1, end=" ")：雖然最後印出了 5，但第一項會變成 $1 + 1 = 2$，印出 2 3 4 5 ，遺失了數字 1。
  • (C) 改為 range(1, 6)：起點為 1，終止值為 6（走訪到 $6 - 1 = 5$），精確印出 1 2 3 4 5 ，為最佳且符合語意之正解。
  • (D) 改為 range(1, 5, 2)：步進為 2，會印出 1 3 ，完全不符題意。
  1. APCS 考場心法與常見陷阱：
  • 解決差一錯誤的標準心法是「修改產生資料的源頭（即 range 的參數）」，而非在輸出端做補償運算（如 + 1）。在 APCS 實作與觀念題中，隨時確認「$stop = \text{目標末項} + 1$」。

Q-06-01-D02負向走訪遺漏負步進參數導致空迴圈除錯 測試除錯

答案 (A)

⚡ 速解

雙參數 range(10, 0) 預設步進是 +1，從 10 往上加不可能碰到比 10 小的 0，直接變成「空 range」靜默結束。倒數務必顯式傳入 -1 步進，改為 range(10, 0, -1)。秒選 (A)。

🔍 深度詳解（點擊展開慢動作拆解與常見陷阱）
  1. 錯誤原因剖析：
  • 函式 range(start, stop[, step]) 若未提供第三個參數 step，Python 預設 step = 1。
  • 當 step > 0 時，有效的區間必須滿足 start < stop。
  • 本題中 start = 10 且 stop = 0，顯然 $10 < 0$ 為偽（False）。
  • 在此情況下，Python 不會產生任何錯誤或例外，而是生成一個「長度為 0 的空可迭代物件（Empty Sequence）」。
  • for 迴圈向其索取第一個元素時便直接觸發迭代結束，迴圈主體 print(i) 一次都未曾執行即靜默終止。
  1. 修正方式：
  • 若希望數值遞減，必須顯式傳入負的步進值 step = -1。
  • 修正為 for i in range(10, 0, -1):，數列將順利走訪 10, 9, 8, ..., 1。
  1. 選項逐項診斷：
  • (A) 正確指出預設步進值為 +1 以及空區間的本質，修改方式完全正確。
  • (B) Python 的 range 完美支援負步進倒數，不會拋出例外。
  • (C) for 迴圈主體本來就必須正確縮排，取消縮排會導致 IndentationError。
  • (D) range 的參數純粹代表區間邊界，絕不會執行除法運算，與除以零完全無關。
  1. APCS 考場心法與常見陷阱：
  • 「空 range 不報錯、直接跳過」是初學者最容易忽視的靜態盲點。當看到 for 迴圈沒有任何輸出時，第一反應先檢查是否「起點大於終點卻忘了負步進」，或是「起點小於終點卻給了負步進」。

Q-06-01-P01等差步進迴圈迭代次數與語句執行次數分析 效能分析

答案 (B)

⚡ 速解

列出 i 的跳步值：$3, 7, 11, 15, 19$（下一個是 23，已 $\ge 20$ 停止）。數一數總共 5 個數值，因此迴圈執行 5 次。秒選 (B)。

🔍 深度詳解（點擊展開慢動作拆解與常見陷阱）
  1. 執行次數推導：
  • 迴圈參數：start = 3, stop = 20, step = 4。
  • 每次迭代 i 的具體賦值如下：
  • 第 1 次：i = 3（$3 < 20$，執行印出 *）
  • 第 2 次：i = 3 + 4 = 7（$7 < 20$，執行印出 *）
  • 第 3 次：i = 7 + 4 = 11（$11 < 20$，執行印出 *）
  • 第 4 次：i = 11 + 4 = 15（$15 < 20$，執行印出 *）
  • 第 5 次：i = 15 + 4 = 19（$19 < 20$，執行印出 *）
  • 第 6 次測試：i = 19 + 4 = 23（$23 \ge 20$，跳出迴圈）
  • 因此迴圈共完整執行 5 次，畫面上連續輸出 5 個星號 *****。
  1. 數學通用公式：
  • 對於正步進 range(start, stop, step)，若 start < stop，總迭代次數為：

$$\text{次數} = \left\lceil \frac{stop - start}{step} \right\rceil = \frac{(stop - 1) - start}{step} + 1 \quad (\text{整數除法})$$

  • 代入本題數值：

$$\lceil (20 - 3) / 4 \rceil = \lceil 17 / 4 \rceil = \lceil 4.25 \rceil = 5 \text{ 次}$$

  1. 選項逐項診斷：
  • (A) 4 次：誤用整數除法 $(20 - 3) // 4 = 17 // 4 = 4$，忽略了未整除時的無條件進位。
  • (B) 正確答案（5 次）。
  • (C) 6 次：計算範圍時多加了 1。
  • (D) 17 次：誤以為是計算區間長度 $20 - 3 = 17$ 次，忽略了步進值為 4。
  1. APCS 考場心法與常見陷阱：
  • 在 APCS 效能與執行次數分析中，面對跳步迴圈，考生可視範圍大小選擇：
  • 若數字較小（如本題 < 20），直接在草稿紙上依序手寫列舉 3, 7, 11, 15, 19 最穩健不易出錯；
  • 若數字極大，務必套用「天花板除法 $\lceil (stop - start) / step \rceil$」，切勿直接用向下取整的整數除法 //。

Q-06-01-P02空迴圈（Empty Range）邊界條件與累加次數分析 效能分析

答案 (D)

⚡ 速解

片段甲 range(7, 7) 起點等於終點，為空區間（0 次）；片段乙 range(5, 1, 2) 起點 5 大於終點 1 卻給正步進 +2，同樣為空區間（0 次）。兩迴圈皆一次都不執行，$c1 = 0, c2 = 0$，總和為 0。秒選 (D)。

🔍 深度詳解（點擊展開慢動作拆解與常見陷阱）
  1. 執行流程拆解：
  • 分析片段甲：
  • range(7, 7)：起始值為 7，終止界限為 7。
  • 因為區間為左閉右開 $[7, 7)$，在數學與程式中，滿足 $7 \le x < 7$ 的整數不存在。
  • 因此 range(7, 7) 為空序列，迴圈主體 c1 += 1 執行 0 次，迴圈結束後 c1 = 0。
  • 分析片段乙：
  • range(5, 1, 2)：起始值為 5，終止值為 1，步進為 +2。
  • 當步進值大於 0 時，要求起點必須小於終點才可能有元素。但此處起點 5 大於終點 1，向右遞增永遠無法逼近終點。
  • 因此此 range 亦直接判定為空序列，迴圈主體 c2 += 1 執行 0 次，迴圈結束後 c2 = 0。
  • 最終輸出：
  • c1 + c2 = 0 + 0 = 0，印出 0。
  1. 選項逐項診斷：
  • (A) 2：誤以為兩個迴圈至少都會無條件執行一次。
  • (B) 1：誤以為起點等於終點會執行一次。
  • (C) 7：誤把 range 內的常數 7 當作執行次數。
  • (D) 正確答案。
  1. APCS 考場心法與常見陷阱：
  • 熟記 range 產生「空集合（Empty Sequence）」的兩大經典情況：
  1. start == stop（無論步進正負，只要起點等於終點，長度必為 0）。
  2. 方向矛盾：start > stop 卻 step > 0，或 start < stop 卻 step < 0。
  • 遇到上述兩種情況，直接判斷迴圈執行 0 次，切勿花時間在紙上模擬！

Q-06-02-P02擂台盟主法求極值之最差情況與最佳情況更新賦值次數分析 效能分析

答案 (A)

⚡ 速解

遞增數列後面每個數都比前面大，每次都打破紀錄，更新 $N - 1$ 次（最差情況）；遞減數列第一個數就是全域最大，後面沒人贏得了它，更新 0 次（最佳情況）。秒選 (A)。

🔍 深度詳解（點擊展開慢動作拆解與常見陷阱）
  1. 單調遞增情況分析（最差情況 Worst-case）：
  • 數列：$x_1 < x_2 < x_3 < \dots < x_N$。
  • 初值設為第一項：max_val = x_1。
  • 走訪剩餘 $N - 1$ 個元素：
  • 遇到 $x_2$：因為 $x_2 > x_1$，條件成立，執行更新 max_val = x_2（第 1 次更新）。
  • 遇到 $x_3$：因為 $x_3 > x_2$，條件成立，執行更新 max_val = x_3（第 2 次更新）。
  • ...
  • 遇到 $x_N$：因為 $x_N > x_{N-1}$，條件成立，執行更新 max_val = x_N（第 $N - 1$ 次更新）。
  • 總共執行賦值更新 $N - 1$ 次。
  1. 單調遞減情況分析（最佳情況 Best-case）：
  • 數列：$x_1 > x_2 > x_3 > \dots > x_N$。
  • 初值設為第一項：max_val = x_1。
  • 走訪剩餘 $N - 1$ 個元素：
  • 遇到 $x_2$：因為 $x_2 < x_1$，條件不成立，不更新。
  • 遇到 $x_3$：因為 $x_3 < x_1$，條件不成立，不更新。
  • ...
  • 遇到 $x_N$：條件皆不成立。
  • 總共執行賦值更新 0 次。
  1. 選項逐項診斷：
  • (A) 正確描述單調遞增為 $N - 1$ 次、單調遞減為 0 次。
  • (B) 兩者情況顛倒。

Q-06-03-F01純數值反轉整數公式填空 程式填空

答案 (A)

⚡ 速解

🔍 深度詳解（點擊展開慢動作拆解與常見陷阱）
  1. 演算法推導分析：
  • 當前取得的個位數 digit，在反轉後將成為最高位。
  • 每處理一個新的數位時，原本已經排好的數字必須往左推移一位（相當於十進位中乘以 10），再在個位空出的位置補上最新的 digit。
  • 追蹤 rev = rev * 10 + digit：
  • 第 1 步：digit = 4 $\implies rev = 0 \times 10 + 4 = 4$
  • 第 2 步：digit = 3 $\implies rev = 4 \times 10 + 3 = 43$
  • 第 3 步：digit = 2 $\implies rev = 43 \times 10 + 2 = 432$
  • 第 4 步：digit = 1 $\implies rev = 432 \times 10 + 1 = 4321$
  • 最終 rev 正確得到 4321。
  1. 選項逐項診斷：
  • (A) 正確公式。
  • (B) rev + digit * 10：只會把當前的 digit 放大 10 倍，無法將舊的累積數值往左推進（例如第 2 步會變成 $4 + 30 = 34$ 而非 43）。

  • (D) (rev + digit) * 10：最後一位也會被乘 10，導致最後多出一個 0（變成 43210）。故選 (A)。

  • 在禁止或不適合使用字串切片（[::-1]）的數值處理情境中，「rev = rev * 10 + digit」是唯一正確的標準數值反轉解法，務必牢記於心。

  • $n = 6$ 之考拉茲變換軌跡：
  • 第 1 步（$n=6$，偶數）：$n = 6 // 2 = 3$（step = 1）
  • 第 2 步（$n=3$，奇數）：$n = 3 \times 3 + 1 = 10$（step = 2）
  • 第 3 步（$n=10$，偶數）：$n = 10 // 2 = 5$（step = 3）
  • 第 4 步（$n=5$，奇數）：$n = 3 \times 5 + 1 = 16$（step = 4）
  • 第 5 步（$n=16$，偶數）：$n = 16 // 2 = 8$（step = 5）

  • 第 8 步（$n=2$，偶數）：$n = 2 // 2 = 1$（step = 8）

  • while 條件: 括號內必須是「維持繼續執行的條件」，而非「停止的條件」！

Q-06-03-D01遺漏迴圈控制變數更新步進引發無窮迴圈除錯 測試除錯

答案 (B)

⚡ 速解

while 迴圈三大要素：「初始值、條件式、更新步進」。本題完全沒有修改 count 的值，條件 5 > 0 恆為真，造成無窮迴圈。必須在迴圈內加上 count -= 1。秒選 (B)。

🔍 深度詳解（點擊展開慢動作拆解與常見陷阱）
  1. 錯誤原因剖析：
  • while 迴圈具備「條件只要為真就重複執行」的特性。
  • 在本題中：
  • 進入前：count = 5。
  • 每次迴圈執行 print(count, end=" ") 印出 5。
  • 但迴圈內部「完全沒有任何改變 count 數值的語句」。
  • 下一次條件判定時，count 依舊是 5，5 > 0 恆為 True。


Q-06-03-D02數位剝皮誤用浮點除法導致死循環除錯 測試除錯

答案 (C)

⚡ 速解

/= 10 是浮點除法！$123 \to 12.3 \to 1.23 \to 0.123 \to 0.0123 \dots$ 浮點數會以極微小浮點數形式無限逼近 0，但永遠大於 0，導致 num > 0 恆成立。剝皮必須使用整數截斷除法 num //= 10。秒選 (C)。

🔍 深度詳解（點擊展開慢動作拆解與常見陷阱）
  1. 錯誤原因剖析：
  • 在 Python 中，單斜線 / 是浮點除法，回傳值必定是 float 型態。
  • 追蹤 num /= 10 的變化：
  • 第 1 步：123 / 10 = 12.3
  • 第 2 步：12.3 / 10 = 1.23
  • 第 3 步：1.23 / 10 = 0.123（此時已處理完 3 個數位，預期應結束）
  • 第 4 步：0.123 / 10 = 0.0123 > 0（條件依然成立！）
  • 第 5 步：0.0123 / 10 = 0.00123 > 0
  • ...
  • 直到數百甚至數千次迭代後，浮點數達到 IEEE 754 雙精度極限（約 $10^{-324}$）下溢為 0.0 之前，條件 num > 0 全部為真！
  • 這導致程式無法在 3 次後正常停下，執行成千上萬次形成實質上的死循環。
  1. 正確寫法：
  • 整數數位剝皮必須使用雙斜線整數除法（無條件捨去小數）：

```python

num = 123

digits = 0

while num > 0:

digits += 1

num //= 10 # 123 -> 12 -> 1 -> 0（3 次精準終止）

print(digits) # 正確輸出 3

```

  1. 選項逐項診斷：
  • (A) 改為 >= 0 更會將 0 納入，更不可能終止。
  • (B) 移至外部只會執行一次計數，無法統計位數。
  • (C) 精準指出浮點除法下溢與逼近特質，提出改用 //= 修正，完全正確。
  • (D) 字串不支援數值除法運算，會引發 TypeError。故選 (C)。
  1. APCS 考場心法與常見陷阱：
  • Python 3 的 /（真除法）與 //（整數商）是考場最易混淆的地雷。涉及「位數截斷」、「找因數」、「二分搜尋中點」時，請務必反射神經使用 //。

讀取第一行 $n$ 呼叫 1 次，迴圈內部讀取 100,000 行呼叫 100,000 次，總計精確呼叫 $1 + 100,000 = 100,001$ 次。在 Python 中呼叫函式具有建立訊框等開銷，高達十萬次呼叫會產生可觀的常數耗時，秒選 (D)。

🔍 深度詳解（點擊展開慢動作拆解與常見陷阱）
  1. 函式呼叫次數精確統計：
  • 第 1 行：n = int(input()) 執行 1 次 input()，讀入字串 "100000"。
  • 迴圈結構：for _ in range(n):，此處 $n = 100,000$，因此迴圈體執行 100,000 次。
  • 迴圈體內：每次執行一次 x = int(input())，共執行 100,000 次 input()。
  • 總呼叫次數：$1 + 100,000 = 100,001$ 次。故選 (D)。
  1. Python 解譯器 I/O 效能深度背景：
  • 在 Python 中，每次呼叫 input() 時，解譯器必須執行：
  1. 建立 Python 函式呼叫訊框（Call Frame）；
  2. 呼叫底層 C 語言標準 I/O 讀取一行字元；
  3. 剝除行尾的換行符號 \n；
  4. 建立並配置一個新的 Python str 物件。
  • 當資料量達數十萬筆時，這十幾萬次函式呼叫與物件建立會耗費 0.5～1.0 秒以上的時間。
  • 這也是高階競賽選手常改用 sys.stdin.read().split() 一次讀取全部字串進行極速 I/O 優化的原因。
  1. 選項逐項診斷：
  • (A) 誤以為 input() 會自動一次讀完全部。
  • (B) 無中生有的打包機制。
  • (C) 筆數有限，呼叫次數完全確定。
  • (D) 正確計算總呼叫次數並說明頻繁函式呼叫開銷。
  1. APCS 考場心法與常見陷阱：
  • 在 APCS 題型中，$N \le 10,000$ 時常規 input() 完全足夠通過；
  • 但只要看到 $N \ge 10^5$ 且面臨 1.0 秒時間限制（Time Limit Exceeded, TLE）時，必須意識到 input() 呼叫本身的常數開銷！

答案 (A)

⚡ 速解

輸入序列為 [15, 20, 5, 12, 18]，相鄰數對中兩數皆 > 10 的有：(15, 20) 滿足、(20, 5) 不滿足、(5, 12) 不滿足、(12, 18) 滿足。共滿足 2 次，最後讀入 0 退出，輸出 2，秒選 (A)。

🔍 深度詳解（點擊展開慢動作拆解與常見陷阱）
  1. 執行流程拆解（滑動視窗雙指標模型）：
  • 初始化 prev = 0, count = 0。
  • 序列追蹤慢動作：
  • 第 1 筆：curr = 15。$15 == 0$ 為假。檢查 $prev(0) > 10 \land curr(15) > 10$ 為 False。執行 prev = 15。
  • 第 2 筆：curr = 20。$20 == 0$ 為假。檢查 $prev(15) > 10 \land curr(20) > 10$ 為 True！count 累加為 1。執行 prev = 20。
  • 第 3 筆：curr = 5。$5 == 0$ 為假。檢查 $prev(20) > 10 \land curr(5) > 10$（5 不大於 10）為 False。執行 prev = 5。
  • 第 4 筆：curr = 12。$12 == 0$ 為假。檢查 $prev(5) > 10 \land curr(12) > 10$ 為 False。執行 prev = 12。
  • 第 5 筆：curr = 18。$18 == 0$ 為假。檢查 $prev(12) > 10 \land curr(18) > 10$ 為 True！count 累加為 2。執行 prev = 18。
  • 第 6 筆：curr = 0。檢查 $curr == 0$ 為 True，觸發 break 跳出迴圈！
  • 輸出 count 為 2。故選 (A)。
  1. 選項逐項診斷：
  • (A) 2：正確答案。
  • (B) 3：誤以為大於 10 的數字個數（15, 20, 12, 18 共 4 個）折半計算。
  • (C) 1：漏算了第二組 (12, 18)。
  • (D) 4：誤把單獨大於 10 的個數當成答案。
  1. APCS 考場心法與常見陷阱：
  • 本題展示了競賽中最常見的「流式前後相鄰比較（Previous-Current Pattern）」！
  • 透過在迴圈末端維護 prev = curr，可以用 $O(1)$ 的空間在不需要串列的情況下，完成任意「前後兩項相鄰關係」的邏輯判斷！

交錯運算式為：$+10 - 3 + 8 - 2 = 7 + 8 - 2 = 15 - 2 = 13$。最後讀入 -1 結束迴圈，印出 13，秒選 (D)。

  1. 執行流程拆解（二態有限狀態機）：
  • 初始化 ans = 0, is_add = True。
  • 各筆資料追蹤：
  • 讀入 x = 10：$x \ne -1$。is_add 為 True，執行 ans += 10（$ans = 10$）。執行 is_add = not is_add，狀態切換為 False。
  • 讀入 x = 3：$x \ne -1$。is_add 為 False，執行 ans -= 3（$ans = 10 - 3 = 7$）。狀態切換為 True。
  • 讀入 x = 8：$x \ne -1$。is_add 為 True，執行 ans += 8（$ans = 7 + 8 = 15$）。狀態切換為 False。
  • 讀入 x = 2：$x \ne -1$。is_add 為 False，執行 ans -= 2（$ans = 15 - 2 = 13$）。狀態切換為 True。
  • 讀入 x = -1：判斷 $x == -1$ 為真，執行 break 跳出迴圈！
  • 輸出 ans 為 13。故選 (D)。

  • (A) 23：全部直接相加（$10 + 3 + 8 + 2 = 23$）。
  • (B) 7：算到第 2 筆就提早停止。
  • (C) 15：算到第 3 筆停止。
  • (D) 13：正確答案。

  • 使用布林旗標 flag = not flag 進行二態翻轉（Toggle），是 APCS 實作與識讀題中最簡潔優雅的狀態機設計模式！
