Q-02-01-R01混合運算型態自動晉升（染紅效應）追蹤 運行追蹤

對應 單元 2.1

下列 Python 程式執行後，畫面上印出的結果為何？

a = 10
b = 2.0
c = a + b
print(type(c).__name__, c)
🎉 答對了！標準答案是 (A)
⚡ 速解

整數 a = 10 遇到浮點數 b = 2.0 相加時，會觸發「浮點染紅效應（Type Promotion）」，整數被自動晉升為浮點數，計算結果必然是浮點數 12.0，型態名稱為 float。秒選 (A) float 12.0。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 型態晉升機制（Implicit Type Conversion / Coercion）：
  • 在 Python 數值運算體系中，不同數值型態進行二元算術運算時，直譯器會遵循「向高精度型態對齊」的原則。
  • 浮點數（float）能表達實數小數，其表示範圍在概念上比整數（int）更廣泛。因此當 int 與 float 相遇時，直譯器會隱式將整數轉換為浮點數（10 $\to$ 10.0），再執行浮點加法。
  • 計算過程：10.0 + 2.0 = 12.0。
  • 變數 c 參照浮點數物件 12.0，type(c).__name__ 為字串 'float'。
  • print(type(c).__name__, c) 輸出 float 12.0。故選 (A)。
  1. 經典陷阱剖析：
  • (B) 誤以為整數加整數小數部分為 0 會維持整數型態。
  • (C) 誤以為浮點數印出時若無小數會省略 .0（Python 的 float 印出時一定至少有一位小數）。

Q-02-01-R02數值等價性 vs 物件型態等價性追蹤 運行追蹤

對應 單元 2.1

下列 Python 程式執行後，畫面上印出的結果為何？

x = 5
y = 5.0
print(type(x) == type(y), x == y)
🎉 答對了！標準答案是 (A)
⚡ 速解

type(x) 是整數 int，type(y) 是浮點數 float，兩者類別不同，前者比較為 False；但數值比較 5 == 5.0 在數值大小上完全相等，後者為 True。秒選 (A) False True。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 型態比對與數值比較的本質差異：
  • 型態比對 type(x) == type(y)：
  • type(5) 回傳 <class 'int'>。
  • type(5.0) 回傳 <class 'float'>。
  • 兩者指向不同的型態物件，故比對結果為 False。
  • 數值比較 x == y：
  • Python 支援跨型態數值比較（Numeric Equality）。在比對 5 == 5.0 時，直譯器會將兩者在數值軸上對齊，數學上 5 與 5.0 數值相等，故回傳 True。
  • 第 3 行印出 False True。故選 (A)。
  1. APCS 考場重點：
  • 數值相等不代表型態相同！在字典（dict）或集合（set）中，因為 hash(5) == hash(5.0) 且 5 == 5.0，5 與 5.0 會被視為相同鍵值（Key Collision），這是高頻進階考點。

Q-02-01-D01APCS 輸出格式除錯（4.0 vs 4 之 WA 陷阱） 測試除錯

對應 單元 2.1

APCS 與 ZeroJudge 題目要求計算兩整數平均，若結果為整數必須輸出整數格式（例如輸出 4），若為小數則保留小數（例如輸出 4.5）。小明寫了如下程式：

a = 5
b = 3
avg = (a + b) / 2
print(avg)

執行後畫面上印出 4.0，因此遭到線上評判系統判定為 **WA（Wrong Answer）**。為了徹底修復此問題並兼顧所有可能數字，下列哪一個改寫方案最嚴謹正確？

🎉 答對了！標準答案是 (A)
⚡ 速解

斜線除法 / 必定產生浮點數 4.0，利用 Python 浮點數內建的 avg.is_integer() 判斷小數是否為 0，若為真則轉成 int(avg) 印出 4，否則保留原小數。秒選 (A)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. APCS 考場最痛失分陷阱（Wrong Answer）：
  • Python 3 的單斜線除法 / 是「真除法（True Division）」，無論能否除盡，結果一律強制轉為 float。8 / 2 出來是 4.0 而非 4。
  • 許多題目對輸出格式有嚴格字元比對要求，多出 .0 會直接判定格式錯誤或答案錯誤。
  1. 最佳工程修復手段：
  • float 物件具備內建方法 .is_integer()，能精準判斷該浮點數是否沒有小數部分（例如 4.0.is_integer() 為 True，4.5.is_integer() 為 False）。
  • 搭配三元運算式：int(avg) if avg.is_integer() else avg，既能在整除時輸出 4，又能在不整除（如 (5+4)/2 = 4.5）時正確輸出 4.5。故選 (A)。
  1. 各錯誤選項風險：
  • (B) // 2 會將 4.5 截斷成 4，造成計算錯誤。
  • (C) 若數值為 10.05，字串替換會誤把 10.05 變成 15，造成嚴重災難。
  • (D) round(4.5) 會把小數四捨五入抹殺。

Q-02-01-D02浮點數精度極限與二進位捨入誤差除錯 測試除錯

對應 單元 2.1

下列 Python 程式執行後，畫面上印出的結果為何？背後成因為何？

x = 0.1 + 0.2
if x == 0.3:
    print("Equal")
else:
    print("Not Equal")
🎉 答對了！標準答案是 (A)
⚡ 速解

電腦科學界的經典常識：在二進位浮點數標準（IEEE 754）中，0.1 與 0.2 都是無窮循環小數，相加後等於 0.30000000000000004，絕對不等於 0.3，因此印出 Not Equal。秒選 (A)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. IEEE 754 二進位浮點數限制：
  • 人類慣用十進位（分母為 10 的因數 2 與 5 才能除盡，如 $1/2 = 0.5$、$1/5 = 0.2$、$1/10 = 0.1$）。
  • 但電腦硬體是二進位（分母只能是 2 的次方才能除盡，如 $1/2 = 0.5$、$1/4 = 0.25$、$1/8 = 0.125$）。
  • 十進位的 0.1 在二進位中是無限循環小數：$0.0001100110011..._2$。
  • 在 53 位元尾數長度限制下被迫截斷，因此 0.1 + 0.2 在記憶體中的實際數值是 0.30000000000000004。
  • 執行 0.30000000000000004 == 0.3 結果為 False，進入 else 區塊印出 Not Equal。故選 (A)。
  1. 工程防範方案：
  • 若需要比較兩浮點數是否相等，絕不可直接用 ==，應使用 math.isclose(a, b) 或 abs(a - b) < 1e-9。

Q-02-01-P01Python 3 大整數任意精度效能分析 效能分析

對應 單元 2.1

在 C/C++ 或 Java 等靜態語言中，32 位元有號整數最大值為 $2^{31}-1 = 2147483647$，超過即發生溢位（Overflow）。然而在 Python 3 中，執行下列程式碼卻能正確無誤印出長達 302 位的精確整數：

x = 2 ** 1000
print(x)

關於 Python 3 整數（int）的底層設計與效能表現，下列說明何者最正確？

🎉 答對了！標準答案是 (A)
⚡ 速解

Python 3 的 int 擁有「任意精度大整數」特性，只要電腦記憶體足夠，算幾千幾萬位都不會溢位！但代價是大整數運算時間會隨長度增加。秒選 (A)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 任意精度大數原理：
  • 在 Python 3 中，整數（int）不是單純的 32/64 位元 CPU 暫存器整數，而是一個完整的 C 語言結構體物件（PyLongObject）。
  • 它使用動態陣列（每 30 位元一個數位模組）來儲存大整數的每個片段。
  • 當數值需要更多空間時，Python 會自動動態擴展記憶體陣列。因此不管是 2**1000 還是 factorial(100)，都能百分之百精確計算，徹底免除了傳統語言的整數溢位 Bug。故選 (A)。
  1. 效能代價：
  • 一般落在 64 位元內的小整數運算速度極快；一旦數值達到數千位以上，乘法與除法需要依賴多精度演算法（如 Karatsuba 乘法），運算耗時與記憶體將隨位數增加。

math = 92

total = chinese + english + math
avg = total / 3
bonus = 0.5
final_score = avg + bonus

Q-02-02-R01運算子優先順序與結合性追蹤 運行追蹤

對應 單元 2.2

下列 Python 程式執行後，畫面上印出的結果為何？

ans = 20 - 4 * 3 + 6 // 2
print(ans)
🎉 答對了！標準答案是 (A)
⚡ 速解

先乘除後加減！乘法 4 * 3 = 12，整除 6 // 2 = 3。算式簡化為 20 - 12 + 3。加減同級由左至右算：20 - 12 = 8，8 + 3 = 11。秒選 (A) 11。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 運算子優先級（Operator Precedence）法則：
  • 在 Python 中，乘除運算子（*、/、//、%）的優先級高於加減運算子（+、-）。
  • 第一階段（乘除運算）：
  • 4 * 3 計算得到 12。
  • 6 // 2 整除計算得到 3。
  • 第二階段（加減運算與左結合性）：
  • 加法與減法具備相同的優先級，依照「由左至右結合（Left-to-Right Associativity）」規則依序運算。
  • 先算左側減法：20 - 12 = 8。
  • 再算右側加法：8 + 3 = 11。
  • 變數 ans 被賦值為整數 11，印出 11。故選 (A)。
  1. 經典陷阱診斷：
  • (B) 27：誤以為由左至右平鋪直敘計算（20 - 4 = 16，16 * 3 = 48...）。
  • (C) 15：誤把後面的 12 + 3 先算成 15，導致 20 - 15 = 5。

Q-02-02-R02巢狀小括號拆解與負負得正追蹤 運行追蹤

對應 單元 2.2

下列 Python 程式執行後，畫面上印出的結果為何？

a = 15
b = 5
c = 2
result = ((a - (b - c)) * 2) - -3
print(result)
🎉 答對了！標準答案是 (A)
⚡ 速解

由內而外層層拆解小括號：最內層 b - c = 5 - 2 = 3；外層 a - 3 = 15 - 3 = 12；乘 2 得到 12 * 2 = 24。最後減去負 3 等於加 3：24 - (-3) = 24 + 3 = 27。秒選 (A) 27。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 小括號的絕對優先權與巢狀計算鏈：
  • 小括號 () 擁有 Python 運算體系中的最高優先級，永遠強迫直譯器先算括號內部。
  • 遇到巢狀括號時，直譯器由最深層的內括號開始向外求值：
  • 步驟 1（最內層括號）：(b - c) = (5 - 2) = 3。
  • 步驟 2（次外層括號）：(a - 3) = (15 - 3) = 12。
  • 步驟 3（外層乘法）：12 * 2 = 24。
  • 步驟 4（單元負號與二元減法）：
  • - -3 中，前一個 - 是減法運算子，後一個 - 是負數符號（一元負號 Unary Minus）。
  • 減去負數相當於加上正數（負負得正）：24 - (-3) = 24 + 3 = 27。
  • 印出 27。故選 (A)。
  1. 選項診斷：
  • (B) 21：誤以為減去 3（24 - 3 = 21）。
  • (C) 19：內層括號拆解漏掉負號變更。

b = 4

執行後成功印出 25。

Python 中唯一的乘法運算子就是星號 *，任何變數或括號相乘絕對不能省略！秒選 (A)。

  • 數學符號常允許省略乘號（如 $2x$、$3(a+b)$），但所有主流程式語言為避免與變數識別字或函式呼叫混淆，一律嚴禁省略乘號。
  • Python 的乘法符號為星號 *。
  • 計算過程：(6 + 4) * 5 // 2 = 10 * 5 // 2 = 50 // 2 = 25。故選 (A)。
  1. 其他符號陷阱：

  • (C) .：小數點或屬性存取符號。
  • (D) ^：在 Python 中代表「位元互斥或（Bitwise XOR）」，根本不是乘方或乘法！

Q-02-02-F02一元負號連續運算填空 程式填空

對應 單元 2.2

在 Python 中，一元運算子負號（-）可以直接連續套用，達到數學上「負負得正」的效果。小明希望對整數 x = 10 連續兩次取負號以維持正值 10：

x = 10
y = [____]x
print(y)

執行後成功印出 10。空格 [____] 處應填入何種符號？

🎉 答對了！標準答案是 (A)
⚡ 速解

Python 支援一元負號串聯，--x 等同於 -(-x) = 10。秒選 (A)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 一元運算子（Unary Operators）解析機制：
  • 在 Python 中，- 置於數值或變數前方時為一元負號（Unary Negation），表示取相反數。
  • 當寫出 --x 時，Python 直譯器會由右至左解析為 -(-x)：
  • 先算內層 -x = -10。
  • 再算外層 -(-10) = 10。
  • 輸出為 10。故選 (A)。
  1. 重要語言對比警告：
  • 在 C/C++ 或 Java 中，--x 代表「前置遞減（Pre-decrement）」會改變變數 x 的值。
  • 但在 Python 中完全沒有自增（++）或自減（--）運算子！ Python 的 ++x 與 --x 純粹是連續兩次的正號與負號運算，x 本身的值完全不會被改變。

Q-02-02-D01算式巢狀括號誤用中括號引發列表重複除錯 測試除錯

對應 單元 2.2

小明習慣了數學課本上「小括號外層套中括號」的習慣，寫出了如下程式碼試圖計算 $2 \times [3 + 4 \times (5 - 2)]$：

ans = 2 * [3 + 4 * (5 - 2)]
print(ans)

請問執行這段程式時，畫面上印出的結果為何？背後原因為何？

🎉 答對了！標準答案是 (A)
⚡ 速解

Python 的數學算式中只能使用圓括號 ()！中括號 [] 會直接被 Python 當成串列（List）。中括號內算出來是 15，2 * [15] 就變成了長度為 2 的串列 [15, 15]！秒選 (A)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 括號職責與資料結構的語法衝突：
  • 在數學中，為了視覺清晰常混用 ()、[]、{} 代表不同層級的括號。
  • 但在 Python 中：
  • 圓括號 ()：唯一合法的算術優先級運算子（亦用於元組 Tuple 與函式呼叫）。
  • 方括號 []：清單（List）建構與索引切片。
  • 大括號 {}：字典（Dict）與集合（Set）。
  • 運算過程：
  • 中括號內部：3 + 4 * (5 - 2) = 3 + 4 * 3 = 3 + 12 = 15。
  • 此時運算式變為 2 * [15]。
  • Python 支援序列乘法（Sequence Repetition），整數 2 乘上含有單一元素 15 的串列，結果為新串列 [15, 15]。故選 (A)。
  1. 正確寫法：
  • 無論巢狀多深，Python 算式中一律使用圓括號：2 * (3 + 4 * (5 - 2)) 才會算出整數 30。

下列 Python 程式在第 3 行發生錯誤：

在數值後方緊貼小括號 2(...)，Python 直譯器會誤以為你要把整數 2 當成函式來呼叫（Function Call），直接拋出 TypeError: 'int' object is not callable！秒選 (A)。

對應 單元 2.2

在 Python 程式中，若要定義一天的總秒數常數，比較下列兩種寫法：

# 寫法甲：清楚展示計算公式（24小時 * 60分 * 60秒）
SECONDS_PER_DAY = 24 * 60 * 60

# 寫法乙：直接寫死計算結果
SECONDS_PER_DAY = 86400

關於寫法甲在程式執行期（Runtime）的 CPU 運算開銷與底層 Bytecode 指令集，下列說明何者最正確？

⚡ 速解

Python CPython 直譯器在編譯為 Bytecode 時有「常數折疊」功能，純數字常數的加減乘除在編譯期就直接算好變成 86400，執行期速度分毫不差！寫法甲可讀性更高。秒選 (A)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. CPython AST 最佳化器機制（Constant Folding）：
  • 當 Python 直譯器將原始碼解析成抽象語法樹（AST）時，內建的最佳化器（Peephole Optimizer / AST Optimizer）會掃描所有二元運算。
  • 若運算子的左右兩側皆為字面純常數（Literals），直譯器會在編譯階段提前求值，將整個運算節點直接替換為求值後的單一常數節點。
  • 透過 import dis; dis.dis("SECONDS = 24 * 60 * 60") 驗證，輸出的 Bytecode 只有：

```text

LOAD_CONST (86400)

STORE_NAME (SECONDS)

```

  • 執行期虛擬機完全不需要執行任何一次乘法運算！因此寫法甲既具備極高的代碼自我解釋性（Self-documenting），又享有極致的零運算負擔。故選 (A)。

在撰寫較長的多項式運算時，許多選手會猶豫是否該加入小括號（例如 (a * b) + (c * d) 對比 a * b + c * d）。下列關於冗餘小括號（Redundant Parentheses）對 Python 效能與可讀性的分析，何者最正確？

🎉 答對了！標準答案是 (A)
⚡ 速解

括號只是給語法解析器看的界定符，編譯成 Bytecode 後根本沒有括號指令！兩者指令集完全相同，勇敢加上括號提升可讀性與穩定度。秒選 (A)。

  1. 編譯期與執行期分離原理：

  1. 工程最佳實踐：
  • PEP 8 強烈建議在複雜算式中適度加上小括號，以顯式表達運算意圖，避免依賴冷門的優先級記憶。

Q-02-02-L02時分秒總秒數換算之巢狀多項式邏輯追蹤 計算邏輯

對應 單元 2.2

在計時系統與 APCS 模擬題中，常需將時（hours）、分（minutes）、秒（seconds）換算為全天的總秒數。現有時間為 2 小時 30 分 45 秒，程式使用巢狀乘加公式計算：

hours = 2
minutes = 30
seconds = 45

total_seconds = (hours * 60 + minutes) * 60 + seconds
print(total_seconds)

執行這段程式後，畫面上印出的總秒數為何？

🎉 答對了！標準答案是 (A)
⚡ 速解

先算小時換成分鐘並累加：$2 \times 60 + 30 = 150$ 分鐘；再整體乘 60 換成秒：$150 \times 60 = 9000$ 秒；最後加上 45 秒：$9000 + 45 = 9045$ 秒。秒選 (A) 9045。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 秦九韶演算法（Horner's Rule）進位累加概念：
  • 此寫法運用了多項式求值的經典巢狀展開：

$$\text{總秒數} = \text{hours} \times 3600 + \text{minutes} \times 60 + \text{seconds} = (\text{hours} \times 60 + \text{minutes}) \times 60 + \text{seconds}$$

  • 內層括號求值：
  • hours * 60 = 2 * 60 = 120。
  • 120 + minutes = 120 + 30 = 150（累計總分鐘數）。
  • 外層括號求值：
  • 150 * 60 = 9000（累計總整分鐘秒數）。
  • 最終加法：
  • 9000 + seconds = 9000 + 45 = 9045 秒。
  • 印出 9045。故選 (A)。
  1. 選項干擾分析：
  • (B) 7245：漏算了 30 分鐘（$2 \times 3600 + 45 = 7245$）。
  • (C) 9000：漏加了 45 秒。
