Q-12-01-R01sorted() 回傳新串列與 list.sort() 回傳 None 運行追蹤

對應 單元 12.1

下列 Python 程式執行後，畫面上印出的結果為何？

a = [4, 1, 3]
b = sorted(a)
c = a.sort()
print(a, b, c)
🎉 答對了！標準答案是 (C)
⚡ 速解

sorted(a) 回傳新串列 [1, 3, 4]；a.sort() 原地把 a 排好並回傳 None 給 c，秒選 (C)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作：
  • 第 1 行：a 為 [4, 1, 3]。
  • 第 2 行：sorted(a) 不改動 a，回傳全新排序串列 [1, 3, 4] 給 b。
  • 第 3 行：a.sort() 直接在原處把 a 修改為 [1, 3, 4]，並回傳 None 存入 c。
  • 第 4 行：依序印出 [1, 3, 4] [1, 3, 4] None。故選 (C)。
  1. 選項逐項診斷：
  • (A) 誤以為 a.sort() 不會修改原串列 a 且會回傳排序後的串列。
  • (B) 誤以為 a.sort() 會回傳排序後的串列給 c。原地修改方法回傳值固定為 None。
  • (C) sorted(a) 產生新串列 [1, 3, 4] 賦值給 b；接著 a.sort() 原地將 a 排成 [1, 3, 4] 並回傳 None 給 c。
  • (D) 誤以為 a.sort() 沒有修改 a 本身。
  1. APCS 考場心法與常見陷阱：
  • list.sort() 是原地修改（In-place），為了提醒開發者沒有產生新物件，Python 設計其回傳值必為 None。
  • 千萬不可寫出 a = a.sort()，否則原本的串列資料會瞬間變成 None 而遺失！

Q-12-01-R02對元組與字串呼叫 sorted() 的回傳型態 運行追蹤

對應 單元 12.1

下列 Python 程式執行後，畫面上印出的結果為何？

t = (5, 2, 8)
s = "cab"
print(sorted(t), sorted(s))
🎉 答對了！標準答案是 (A)
⚡ 速解

sorted() 不論傳入元組、字串或集合，回傳的一律是 list！所以印出兩個方括號串列，秒選 (A)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作：
  • sorted(iterable) 會將傳入的可迭代物件拆出所有元素，排好序後裝進一個全新的串列回傳。
  • sorted((5, 2, 8)) 取出 5, 2, 8 升序排列，回傳串列 [2, 5, 8]。
  • sorted('cab') 取出字元 'c', 'a', 'b' 升序排列，回傳字元串列 ['a', 'b', 'c']。
  • 印出 [2, 5, 8] ['a', 'b', 'c']。故選 (A)。
  1. 選項逐項診斷：
  • (A) sorted() 接收任何可迭代物件，回傳的永遠是全新的「串列（list）」。
  • (B) 誤以為傳入元組會回傳元組、傳入字串會回傳字串。sorted() 統一回傳 list。
  • (C) 誤以為元組經過 sorted() 後仍為元組。
  • (D) 誤以為字串經過 sorted() 後會自動合併回字串。
  1. APCS 考場心法與常見陷阱：
  • sorted() 的回傳型態永遠是 list，不會跟隨原容器型態。
  • 若想把排序後的字元串列變回字串，需搭配 ''.join(sorted(s))；想變回元組則用 tuple(sorted(t))。

Q-12-01-F02將字串字元依字母順序重組為新字串 程式填空

對應 單元 12.1

預期印出按字母順序排列的字串 abcd。空格應填入哪一個？

word = "dcba"
res = ______
print(res)
🎉 答對了！標準答案是 (D)
⚡ 速解

字串沒有 .sort()，sorted(word) 會得到串列，必須搭配 "".join(sorted(word)) 才能合回字串，秒選 (D)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作：
  • 字串屬於不可變序列，不支援原地修改，因此沒有 .sort() 方法。
  • 呼叫 sorted('dcba') 會回傳字元串列 ['a', 'b', 'c', 'd']。
  • 要將字元串列合併為單一字串，標準做法是使用空字串的 .join() 方法："".join(sorted(word))。
  • 注意 str(串列) 只會把方括號也變成字串字元，不會合併元素。故選 (D)。
  1. 選項逐項診斷：
  • (A) 字串是不可變物件，沒有 .sort() 方法，會拋出 AttributeError: 'str' object has no attribute 'sort'。
  • (B) sorted(word) 回傳的是字元串列 ['a', 'b', 'c', 'd']，印出來帶有方括號與引號，不是字串 abcd。
  • (C) str(['a', 'b', 'c', 'd']) 只是把串列的表示法轉成字串 "['a', 'b', 'c', 'd']"。
  • (D) 先用 sorted(word) 得到 ['a', 'b', 'c', 'd']，再用 "".join(...) 無縫拼接回字串 abcd。
  1. APCS 考場心法與常見陷阱：
  • "".join(sorted(s)) 是 APCS 字串題檢驗「同構詞（Anagram，字母重排）」的黃金標準公式！
  • 兩個字串 s1 與 s2 若滿足 sorted(s1) == sorted(s2)，就代表它們由完全相同的字元組成。

Q-12-01-D01誤把 list.sort() 的回傳值賦回原變數 測試除錯

對應 單元 12.1

想將成績由小到大排序並印出最低分 60。現在執行卻拋出 TypeError: 'NoneType' object is not subscriptable。只改第 2 行，哪一個改法會印出預期結果？

scores = [80, 60, 90, 70]
scores = scores.sort()
print(scores[0])
🎉 答對了！標準答案是 (C)
⚡ 速解

scores.sort() 回傳 None，寫成 scores = scores.sort() 會把 scores 蓋成 None。拿掉前面的 scores = 即可，秒選 (C)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作：
  • 現況：第 2 行 scores.sort() 雖然把串列排好了，但它的回傳值是 None。
  • 左邊寫了 scores = ...，導致 scores 變數被覆蓋為 None，第 3 行取 scores[0] 時對 None 取索引而崩潰。
  • 修正方式有兩種：一是直接寫 scores.sort()（不賦值），二是寫 scores = sorted(scores)。

  1. 選項逐項診斷：
  • (A) 串列沒有 .sorted() 方法，會拋出 AttributeError: 'list' object has no attribute 'sorted'。

  • (C) 直接呼叫 scores.sort() 原地完成排序，scores 變成 [60, 70, 80, 90]，scores[0] 正確印出 60。

  1. APCS 考場心法與常見陷阱：
  • scores.sort() 不加等號賦值；scores = sorted(scores) 必須加等號賦值。兩者切勿混搭！
  • 看到 'NoneType' object is not subscriptable，十之八九就是寫了 x = x.sort() 或 x = x.append(...)。

nums = (40, 10, 30, 20)

元組不可變，沒有 .sort() 方法，必須改用 nums = sorted(nums) 產生排序後的新串列，秒選 (A)。

Q-12-01-P01檢查子串列是否已排序並統計原地排序次數 效能分析

對應 單元 12.1

下列程式執行時，count += 1 這一行共執行幾次？

data = [[3, 1], [4, 2], [5, 0], [2, 9]]
count = 0
for row in data:
    if row != sorted(row):
        row.sort()
        count += 1
🎉 答對了！標準答案是 (D)
⚡ 速解

條件 row != sorted(row) 代表「原本沒按由小到大排好」。前三個都是前大後小，只有 [2, 9] 已經排好，共 3 次，秒選 (D)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作：
  • 逐一檢查 data 中的 4 個子串列：
  • - [3, 1]：sorted(row) 為 [1, 3]，兩者不同，進入 if，count 變 1。
  • - [4, 2]：sorted(row) 為 [2, 4]，兩者不同，進入 if，count 變 2。
  • - [5, 0]：sorted(row) 為 [0, 5]，兩者不同，進入 if，count 變 3。
  • - [2, 9]：sorted(row) 為 [2, 9]，兩者相等，不進入 if。
  • 因此 count += 1 共執行 3 次。故選 (D)。
  1. 選項逐項診斷：
  • (A) 誤以為 4 個子串列都還沒排好序。最後一個 [2, 9] 本來就是升序。
  • (B) 誤算為只有 1 個已排序，題目條件是 !=（尚未排序時才進入）。
  • (C) 少算了一個未按升序排列的子串列。
  • (D) [3, 1]、[4, 2]、[5, 0] 皆不等於升序結果，會進入 if；只有 [2, 9] 已是升序不進入，共執行 3 次。
  1. APCS 考場心法與常見陷阱：
  • row == sorted(row) 是判斷一個串列「是否已經由小到大排好（非嚴格遞增）」最直觀的寫法。

Q-12-01-P02相鄰比較交換排序的交換次數追蹤 效能分析

對應 單元 12.1

下列程式執行完畢後，swaps 的值為何（即相鄰元素交換了幾次）？

nums = [5, 3, 1, 4, 2]
n = len(nums)
swaps = 0
for i in range(n):
    for j in range(0, n - 1 - i):
        if nums[j] > nums[j + 1]:
            nums[j], nums[j + 1] = nums[j + 1], nums[j]
            swaps += 1
🎉 答對了！標準答案是 (B)
⚡ 速解

每次相鄰交換消除一個逆序對。5 後面有 4 個比它小(4)、3 後面有 1,2 比它小(2)、4 後面有 2 比它小(1)：4 + 2 + 1 = 7 次，秒選 (B)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作：
  • 初始串列為 [5, 3, 1, 4, 2]：
  • - i = 0：5 一路向右與 3, 1, 4, 2 交換（4 次），變成 [3, 1, 4, 2, 5]。
  • - i = 1：3 與 1 交換變成 [1, 3, 4, 2, 5]，接著 4 與 2 交換變成 [1, 3, 2, 4, 5]（2 次）。
  • - i = 2：3 與 2 交換變成 [1, 2, 3, 4, 5]（1 次）。
  • - i = 3：已全部排好，無交換（0 次）。
  • 總交換次數為 4 + 2 + 1 = 7 次。故選 (B)。
  1. 選項逐項診斷：
  • (A) 這是內層 if 比較條件執行的總次數（4 + 3 + 2 + 1 = 10），不是交換次數。
  • (B) 第一輪 5 移到最右交換 4 次，狀態變 [3, 1, 4, 2, 5]；第二輪交換 (3,1) 與 (4,2) 共 2 次；第三輪交換 (3,2) 共 1 次。4 + 2 + 1 = 7。
  • (C) 誤將串列長度 5 當成交換次數。
  • (D) 只算了第一輪 i = 0 的 4 次交換，漏掉後續輪次。
  1. APCS 考場心法與常見陷阱：
  • 相鄰交換排序（氣泡排序）的總交換次數，剛好等於原序列的「逆序對（Inversion Pairs）」個數（即左大右小的數對個數）。
  • 數每個數右邊有幾個比它小的數再加總，比一輪一輪模擬更快且不易算錯！

Q-12-01-L01別名參照、原地排序與新串列的身分識別 計算邏輯

對應 單元 12.1

下列程式印出 True True False。哪一句描述 a、b、c 的關係，換成其他非空串列也成立？

a = [3, 1, 2]
b = a
c = sorted(a)
a.sort()
print(b == c, b is a, c is a)
🎉 答對了！標準答案是 (A)
⚡ 速解

b = a 是同一個物件（b is a 為 True），c = sorted(a) 是全新物件（c is a 為 False），但兩邊排完內容一樣（b == c 為 True），秒選 (A)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作：
  • b = a 沒有複製串列，只是讓 b 與 a 指向同一個串列，因此 b is a 恆為 True。
  • c = sorted(a) 永遠會建立一個新的串列物件，因此 c is a 恆為 False（就算原本 a 已經排好序也一樣）。
  • 接著 a.sort() 把 a（也就是 b）原地排成升序，其元素內容與 c 完全相同，因此 b == c 為 True。故選 (A)。
  1. 選項逐項診斷：
  • (A) b = a 為別名參照，故 b is a 為 True；c = sorted(a) 產生新串列，故 c is a 為 False，但兩者排序後內容相同 b == c 為 True。
  • (B) sorted(a) 從一開始就配置全新的串列記憶體，c 從未與 a 指向同一物件。
  • (C) 即使原串列已經排好序，sorted(a) 依然會建立並回傳一份全新的獨立串列，c is a 永遠為 False。
  • (D) == 比較的是串列元素內容是否相等，is 比較的是是否為記憶體中的同一個物件，兩者完全不同。
  1. APCS 考場心法與常見陷阱：
  • 區分 ==（值相等）與 is（同一記憶體物件）：sorted(a) == a 在已排序時為 True，但 sorted(a) is a 永遠為 False。

Q-12-01-L02結合 set 去重與 sorted 求嚴格次小值 計算邏輯

對應 單元 12.1

下列程式印出 2。只要傳入的串列至少有兩種不同的數，哪一句描述 f(nums) 的計算結果也成立？

def f(nums):
    s = sorted(set(nums))
    return s[1]

print(f([4, 1, 2, 1, 3]))
🎉 答對了！標準答案是 (C)
⚡ 速解

set(nums) 先把重複數字刪掉，sorted(...) 再由小到大排成串列，s[1] 就是嚴格第二小的值，秒選 (C)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作：
  • set(nums) 會先消除所有重複出現的數字。
  • sorted(...) 接收集合後，直接回傳由小到大排好序的無重複串列 s。
  • s[0] 是最小值，s[1] 就是「不計重複的嚴格次小值」。
  • 代入 [5, 5, 8, 9, 5]：去重排序後 s 為 [5, 8, 9]，s[1] 為 8。故選 (C)。
  1. 選項逐項診斷：
  • (A) 函式先做了 set 去重與 sorted 排序，並非取原串列下標 1。
  • (B) 因為有先經過 set(nums) 去除重複值，重複的最小數 5 只會留下一個，s 為 [5, 8, 9]。
  • (C) set([5, 5, 8, 9, 5]) 去重得到 {5, 8, 9}，sorted 後為 [5, 8, 9]，s[1] 為嚴格次小值 8。

Q-12-02-R01數字字串的字典序排序陷阱 運行追蹤

對應 單元 12.2

下列 Python 程式執行後，畫面上印出的結果為何？

print(items)
🎉 答對了！標準答案是 (B)
⚡ 速解

字串排序比的是字典序（從左邊第一個字元開始比）：'1' 開頭最小，第 2 字元 '0' < '5'，所以 '100' 排第一，秒選 (B)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作：
  • items 的元素全是字串（帶有引號），呼叫 .sort() 會依字典序（Lexicographical Order）由小到大排列。
  • 先比第 0 個字元：'1' < '2' < '3'，因此 '100'、'15' 排在前面，接著是 '2'，最後是 '30'。
  • 再比 '100' 與 '15' 的第 1 個字元：'0' < '5'，所以 '100' 排在 '15' 前面。
  • 最終印出 ['100', '15', '2', '30']。故選 (B)。
  1. 選項逐項診斷：
  • (A) 誤將字串當成整數比大小。字串排序是逐字元比對 ASCII 編碼（字典序）。
  • (B) 字串按左起字元依序比對：'1' 開頭的 '100' 與 '15' 排在 '2' 與 '30' 前面，且 '100' < '15'（因第 2 字元 '0' < '5'）。
  • (C) 雖然知道 '1' 開頭排前面，但誤以為 '15' 比 '100' 小。第 2 個字元 '0' 比 '5' 小，故 '100' 在前。

  1. APCS 考場心法與常見陷阱：
  • APCS 讀入單行多個數字時，若只寫 input().split() 而忘記轉成 int，排序時就會踩中 '100' < '2' 的字典序大陷阱！

⚡ 速解

  • (C) 忽略了大小寫 ASCII 差異，誤按不分大小寫的字母反序排列。
  • (D) 小寫字母 ASCII (97~122) 大於大寫字母 (65~90)。升序為 ['Banana', 'Cat', 'ant', 'apple']，加上 reverse=True 降序反轉為 ['apple', 'ant', 'Cat', 'Banana']。

  • 記住口訣：「大寫編碼小（65 起），小寫編碼大（97 起）」。升序時大寫排前面，降序（reverse=True）時小寫排前面。

calls = 0

    return abs(x)

data.sort(key=key_fn)

⚡ 速解

Python 排序採用「裝飾-排序-去裝飾」機制，key 函式對每個元素只會算 1 次！6 個元素就剛好呼叫 6 次，秒選 (C)。

  1. 慢動作：
  • Python 的 sort() 與 sorted() 在開始兩兩比較之前，會先走訪串列一次，對每個元素呼叫 key_fn(x) 並將結果暫存起來。

  • (A) 誤以為每次兩兩比較時都會重新呼叫 key_fn。Python 排序會先對每個元素預先算好一次 key 值並快取起來。

  • (C) Python 的 sort / sorted 對長度為 $N$ 的串列，只會對每個元素各呼叫 key 函式恰好 1 次（共 6 次）。
  • (D) 誤以為對整個串列只呼叫 1 次。key_fn 是逐元素呼叫的。
  1. APCS 考場心法與常見陷阱：
  • 不論排序過程比較了多少次，長度為 $N$ 的串列在一次 sort(key=...) 中，key 函式永遠只會被呼叫恰好 $N$ 次！

Q-12-03-P02以二進位迴圈函式作為 key 時的總迭代次數 效能分析

對應 單元 12.3

下列程式執行時，c += n % 2 這一行共執行幾次？

def count_ones(n):
    c = 0
    while n > 0:
        c += n % 2
        n //= 2
    return c

nums = [6, 1, 5]
nums.sort(key=count_ones)
🎉 答對了！標準答案是 (B)
⚡ 速解

count_ones 對每個數只呼叫 1 次：6 除以 2 需 3 步歸零，1 需 1 步，5 需 3 步。3 + 1 + 3 = 7 次，秒選 (B)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作：
  • nums 有 3 個元素，count_ones 會依序對 6、1、5 各呼叫 1 次：
  • - n = 6：6 → 3 → 1 → 0，while 迴圈執行 3 次。
  • - n = 1：1 → 0，while 迴圈執行 1 次。
  • - n = 5：5 → 2 → 1 → 0，while 迴圈執行 3 次。
  • 總共執行 3 + 1 + 3 = 7 次。故選 (B)。
  1. 選項逐項診斷：
  • (A) 這是 count_ones 函式被呼叫的次數（3 個元素各呼叫 1 次），不是內部 while 迴圈的執行總次數。

  • (C) 這是 6、1、5 二進位中 1 的總個數（2 + 1 + 2 = 5），不是迴圈執行的次數。
  • (D) 誤將數字本身相加（6 + 1 + 5 = 12）。迴圈每次是 n //= 2 減半。
  1. APCS 考場心法與常見陷阱：
  • 因為 key 函式對每個元素只呼叫一次，計算內部語句次數時，只需將每個元素單獨呼叫一次的圈數相加即可。

Q-12-03-L01依與基準值距離排序及穩定排序保序性 計算邏輯

對應 單元 12.3

下列程式印出 [5, 4, 2, 8]。哪一句描述 sorted(nums, key=dist_to_5) 的排序規則，換成其他整數串列也成立？

def dist_to_5(x):
    return abs(x - 5)

nums = [2, 8, 4, 5]
print(sorted(nums, key=dist_to_5))
🎉 答對了！標準答案是 (B)
⚡ 速解

特徵值是 abs(x - 5)（與 5 的距離），距離相同時 Python 穩定排序會保留原本誰先誰後的順序，秒選 (B)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作：
  • dist_to_5(x) 計算 x 到 5 的絕對距離。
  • 範例 [2, 8, 4, 5] 與 5 的距離分別為 3, 3, 1, 0，由小到大排為 0 (5), 1 (4), 3 (2, 8)。
  • 特別注意：2 與 8 的距離同為 3，因為 dist_to_5 沒有給第二排序條件，Python 的穩定排序（Stable Sort）會保留它們在原串列的相對位置。
  • 因此換成 [9, 1, 6]（距離分別為 4, 4, 1）時，9 與 1 同距且 9 原在 1 前，排完必為 [6, 9, 1]。故選 (B)。
  1. 選項逐項診斷：
  • (A) 範例中 2 與 8 距離 5 都是 3，2 在前是因為原本 2 就在 8 前面（穩定排序），並非因為 2 比 8 小。[9, 1, 6] 中 9 與 1 距離皆為 4，9 原在 1 前面，故排完為 [6, 9, 1]。
  • (B) dist_to_5 只回傳單一數值 abs(x - 5)，當兩數距離相等時，Python 穩定排序保證維持它們原本的先後次序。
  • (C) 函式用了 abs(x - 5) 取絕對值，不是帶正負號的差值。
  • (D) sorted 回傳的是原始元素，不會替換成距離值。
  1. APCS 考場心法與常見陷阱：
  • 這是 APCS 最愛考的觀念：當 key 函式只回傳單一數值且發生同分（Tie）時，同分元素一定「維持原串列相對順序（先來的先排）」，不會自動按數值大小排！

Q-12-04-R01lambda 複合鍵值：分數降序、同分座號升序 運行追蹤

對應 單元 12.4

下列 Python 程式執行後，畫面上印出的結果為何？

🎉 答對了！標準答案是 (D)
⚡ 速解

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作：
  • key=lambda x: (-x[1], x[0]) 將每個 (座號, 分數) 投射為 (-分數, 座號)：
  • - (3, 80) → (-80, 3)
  • - (1, 95) → (-95, 1)
  • - (2, 80) → (-80, 2)
  • - (4, 95) → (-95, 4)
  • 按元組升序排列：(-95, 1) < (-95, 4) < (-80, 2) < (-80, 3)。
  • 對應回原元組為 [(1, 95), (4, 95), (2, 80), (3, 80)]。故選 (D)。

  • (A) 誤以為 -x[1] 是分數由小到大排列。加了負號後 -95 < -80，高分 95 會排在前面。

  • key=lambda x: (-x[1], x[0]) 是 APCS 排行榜題目的萬用標準公式：想降序的數值欄位加負號，想升序的欄位保持正號！

    global cnt

  1. 慢動作：
  • 許多人會誤以為「只有第一欄同分時才會去算第二欄 check(p[0])」。

  • 元組不是短路運算（and / or）：建立 (a, b) 元組時，a 與 b 兩個運算式都會在建立當下立刻算完！

Q-12-04-L01矩形依面積升序、同面積依寬度降序排列 計算邏輯

對應 單元 12.4

下列程式印出 [(1, 8), (4, 3), (3, 4), (2, 6)]。哪一句描述 sort_box(boxes) 的排序規則，換成其他正整數二元組串列也成立？

def sort_box(boxes):
    return sorted(boxes, key=lambda b: (b[0] * b[1], -b[0]))

print(sort_box([(2, 6), (3, 4), (1, 8), (4, 3)]))
🎉 答對了！標準答案是 (A)
⚡ 速解

元組 (b[0] * b[1], -b[0]) 第一項是乘積升序，第二項 -b[0] 是第 0 欄降序（數字大者在前），秒選 (A)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作：
  • 拆解 lambda b: (b[0] * b[1], -b[0])：
  • - 首要條件 b[0] * b[1]（正號）：按兩數乘積由小到大排列。(1, 8) 乘積為 8 最小排第一。
  • - 次要條件 -b[0]（負號）：當乘積相同（如 (2, 6), (3, 4), (4, 3) 乘積皆為 12）時，b[0] 越大則 -b[0] 越小，越排前面，故依序為 (4, 3), (3, 4), (2, 6)。

  1. 選項逐項診斷：
  • (A) 主鍵 b[0] * b[1] 為乘積升序（8 在 12 前）；次鍵 -b[0] 為第 0 欄降序（同為乘積 12 時，4 > 3 > 2）。
  • (B) 雖然當乘積固定時 b[0] 越大代表 b[1] 越小，因此 -b[0] 是讓 b[0] 大者在前（即 (5, 2) 在 (2, 5) 前），而非 b[1] 大者在前。
  • (C) b[0] * b[1] 是乘法不是加法。
  • (D) 元組第 0 個位置放的是 b[0] * b[1]，因此乘積才是首要條件。
  1. APCS 考場心法與常見陷阱：
  • 解讀複合鍵 lambda 時，順著元組由左到右看：正號就是「由小到大」，負號就是「由大到小」。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作：
  • 這是 APCS 非常經典的「分群排序」技巧：
  • - 主鍵 x % 2：偶數餘 0，奇數餘 1。升序時所有餘 0 的偶數都會排在餘 1 的奇數前面。
  • - 次鍵 x：在偶數群內與奇數群內，各自按數值 x 由小到大排列。
  • 代入 [7, 8, 2, 9]：偶數 2, 8 排前，奇數 7, 9 排後，結果為 [2, 8, 7, 9]。故選 (C)。
  1. 選項逐項診斷：
  • (A) 範例中最後的 6 被移到前半，並非按位置切半。
  • (B) 偶數 x % 2 為 0，奇數 x % 2 為 1。因為 0 < 1，偶數會排在奇數前面！
  • (C) 偶數的 x % 2 為 0，奇數為 1，故偶數全部排在奇數前；同為偶數或同為奇數時，依第 2 欄 x 由小到大排。
  • (D) 第二欄 x 為正號，不論偶數或奇數內部都是由小到大升序排列。
  1. APCS 考場心法與常見陷阱：
  • 想把滿足某條件的元素排在前面，只需將主鍵設為 0（前面）與 1（後面），例如偶數在前用 x % 2、奇數在前用 1 - x % 2（或 x % 2 == 0）！

Q-12-05-R01APCS 經典線段覆蓋長度：依起點排序合併重疊區間 運行追蹤

對應 單元 12.5

下列 Python 程式執行後，畫面上印出的結果為何？

segs = [(7, 10), (1, 4), (2, 6)]
segs.sort()
L, R = segs[0]
total = 0
for s, e in segs[1:]:
    if s <= R:
        R = max(R, e)
    else:
        total += R - L
        L, R = s, e
total += R - L
print(total)
🎉 答對了！標準答案是 (B)
⚡ 速解

排完序 (1,4) 與 (2,6) 重疊合成 (1,6) 長度 5；(7,10) 不重疊長度 3，合計 5 + 3 = 8，秒選 (B)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作：
  • segs.sort() 依線段左端點升序排為 [(1, 4), (2, 6), (7, 10)]。
  • 初始目前線段 L, R = 1, 4。
  • 第 1 圈 (2, 6)：左端點 2 <= 4 有重疊，右端點延伸為 R = max(4, 6) = 6（合併為 [1, 6]）。
  • 第 2 圈 (7, 10)：左端點 7 <= 6 不成立（斷開），先結算前一段 total += 6 - 1 = 5，再重設 L, R = 7, 10。
  • 迴圈結束後結算最後一段：total += 10 - 7 = 8。故選 (B)。
  1. 選項逐項診斷：
  • (A) 把三條線段長度直接相加 (10-7)+(4-1)+(6-2) = 3+3+4 = 10，未扣除 (1, 4) 與 (2, 6) 重疊的 [2, 4]。

  • (C) 漏看了迴圈結束後的最後一行 total += R - L，少加了最後一段 (7, 10) 的長度 3。
  • (D) 誤把 (1, 6) 與 (7, 10) 當成連在一起，直接算 10 - 1 = 9（中間 [6, 7] 並未被覆蓋）。
  1. APCS 考場心法與常見陷阱：
  • 這是 APCS 實作第 3 題經典題「線段覆蓋長度」的標準模板：先 .sort() 按左端點排，重疊就 R = max(R, e)，斷開就結算 R - L！

下列 Python 程式執行後，畫面上印出的結果為何？

for s, e in jobs:
    if s >= last_end:
        cnt += 1
        last_end = e
print(cnt, last_end)
🎉 答對了！標準答案是 (C)
⚡ 速解

按結束時間排為 (2,4), (1,6), (4,7), (7,9)：選 (2,4)、跳過 (1,6)、選 (4,7)、選 (7,9)，共 3 個且最後結束於 9，秒選 (C)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作：
  • jobs.sort(key=lambda x: x[1]) 按結束時間由早到晚排為：[(2, 4), (1, 6), (4, 7), (7, 9)]。
  • 逐一檢查 s >= last_end：
  • - (2, 4)：2 >= 0 成立，cnt = 1，last_end = 4。
  • - (1, 6)：1 >= 4 不成立（與前一場衝突），跳過。
  • - (4, 7)：4 >= 4 成立，cnt = 2，last_end = 7。
  • - (7, 9)：7 >= 7 成立，cnt = 3，last_end = 9。
  • 印出 3 9。故選 (C)。
  1. 選項逐項診斷：
  • (A) 誤按原順序先選了 (1, 6)，導致只選到 (1, 6) 與 (7, 9) 共 2 個。程式第 2 行已先按結束時間 x[1] 排序。
  • (B) 誤以為 4 個活動都能選。(1, 6) 的起點 1 小於已選 (2, 4) 的結束時間 4，會被跳過。
  • (C) 按結束時間排序後為 (2, 4), (1, 6), (4, 7), (7, 9)。依序選入 (2, 4)、跳過 (1, 6)、選入 (4, 7)、選入 (7, 9)，共 3 個，最後結束時間為 9。
  • (D) 少更新了最後一個選入區間 (7, 9) 的結束時間 9。
  1. APCS 考場心法與常見陷阱：
  • 區間題兩大排序口訣：「合併覆蓋區間」按起點 x[0] 排；「選最多不重疊活動」按終點 x[1] 排！

對應 單元 12.5

nums.sort()
ans = nums[1] - nums[0]
for i in range(1, len(nums)):
    ans = min(ans, ______)
print(ans)
🎉 答對了！標準答案是 (D)
⚡ 速解

由小到大排完 [3, 8, 12, 19] 後，差值最小的一對一定相鄰，且後項減前項 nums[i] - nums[i - 1] 為正，秒選 (D)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作：
  • 未排序時求最近兩點需要 $O(N^2)$ 兩兩配對；但只要先 .sort() 排成 [3, 8, 12, 19]，最接近的兩數必定相鄰！

  • - 8 - 3 = 5
  • - 12 - 8 = 4
  • - 19 - 12 = 7
  • 取最小值即得 4。故選 (D)。

  • (A) 每次都拿 nums[i] 減去最小值 nums[0]，沒比較相鄰兩數，算出來是 8 - 3 = 5。
  • (B) 因為已經由小到大排序，nums[i - 1] - nums[i] 會是負數，導致 ans 變成 -11。
  • (C) 這是最大值減最小值的全距 19 - 3 = 16。
  • (D) 由小到大排序後，距離最近的兩個數必定排在相鄰位置，檢查每對 nums[i] - nums[i - 1] 即可找出最小差值 4。
  1. APCS 考場心法與常見陷阱：
  • 「排序後只看相鄰項 nums[i] - nums[i - 1]」能把 $O(N^2)$ 暴力配對降為 $O(N \log N)$，是 APCS 第 2、3 題必備技巧。

  1. 慢動作：
  • 雙指標初始在最左 L = 0 (1) 與最右 R = 4 (12)：
  • - 1 + 12 = 13 > 11（太大），走 else 將右指標左移 R -= 1（指向 7）。

    if s <= R:
        R = e
print(L, R)
🎉 答對了！標準答案是 (C)

Q-12-05-P01雙指標相向移動直到交會的總步數 效能分析

對應 單元 12.5

下列程式執行時，steps += 1 這一行共執行幾次？

target = 10
L, R = 0, len(nums) - 1
steps = 0
while L < R:
    steps += 1
    s = nums[L] + nums[R]
    if s <= target:
        L += 1
    else:
        R -= 1
🎉 答對了！標準答案是 (A)
⚡ 速解

初始 L = 0, R = 5，每圈只移動 L += 1 或 R -= 1 其中一個，距離 R - L 從 5 每次減 1 到 0 結束，固定就是 5 次，秒選 (A)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作：
  • 不用逐圈算加法！觀察指標距離 R - L：
  • - 一開始 L = 0, R = 5，差距 R - L = 5。
  • - 迴圈內沒有 break，且每圈走 if（L += 1）或 else（R -= 1）二選一，因此每圈 R - L 必定剛好減 1。
  • - 當執行 5 次後，L == R，while L < R 結束。
  • 故不論串列數字為何，長度為 $N$ 的無 break 相向雙指標一定執行 $N - 1 = 5$ 次。故選 (A)。
  1. 選項逐項診斷：
  • (A) 初始 L = 0, R = 5（距離為 5）。每圈迴圈不是 L += 1 就是 R -= 1，兩指標距離每圈固定減少 1，直到 L == R 停止，必執行 5 次。
  • (B) 當兩指標相遇 L == R 時，while L < R 不成立，第 6 次不會進入迴圈。
  • (C) 誤以為每圈 L 與 R 同時移動。每圈 if-else 只會移動其中一個指標。
  • (D) 誤將雙指標當成雙層迴圈 $6 \times 5 / 2 = 15$ 次。雙指標是線性 $O(N)$。
  1. APCS 考場心法與常見陷阱：
  • 相向雙指標為線性時間 $O(N)$ 的鐵證：R - L 初始為 $N - 1$，每步至少縮減 1，最多只會走 $N - 1$ 步！

Q-12-05-L01雙指標統計兩數之和小於等於上限的數對個數 計算邏輯

對應 單元 12.5

下列程式印出 4。哪一句描述 count_pairs(nums, limit) 的計算功能，換成其他串列與 limit 也成立？

def count_pairs(nums, limit):
    nums = sorted(nums)
    L, R = 0, len(nums) - 1
    ans = 0
    while L < R:
        if nums[L] + nums[R] <= limit:
            ans += R - L
            L += 1
        else:
            R -= 1
    return ans

print(count_pairs([4, 1, 2, 3], 5))
🎉 答對了！標準答案是 (B)
⚡ 速解

當 nums[L] + nums[R] <= limit 時，代表 L 配上 L+1 到 R 的這 R - L 個數全都 <= limit，是在算「兩數之和 <= limit」的數對總數，秒選 (B)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作：
  • 排序後 nums 由小到大排列。
  • 若最小的 nums[L] 加上目前的 nums[R] 已經 <= limit，則 nums[L] 加上中間任何一個 nums[k]（L < k <= R）必然也都 <= limit！
  • 這樣的 k 共有 R - L 個，因此 ans += R - L 一次把與 L 配對的所有合格數對收錄完畢，再將 L += 1。
  • 代入 [1, 2, 5, 6] 與 limit = 7：合格數對為 (1,2), (1,5), (1,6), (2,5) 共 4 對。故選 (B)。
  1. 選項逐項診斷：
  • (A) 在 [1, 2, 5, 6] 中，(1,2), (1,5), (1,6), (2,5) 四對的和都 <= 7，函式回傳 4 而非 2。
  • (B) 排序後當 nums[L] + nums[R] <= limit 時，nums[L] 與 L+1 ... R 之間的所有數相加都 <= limit，一次累加 R - L 對。
  • (C) R - L 是索引差距（配對數量），不是數值長度相減。
  • (D) 條件式是 nums[L] + nums[R] <= limit（兩數之和），不是兩數之差。
  1. APCS 考場心法與常見陷阱：
  • ans += R - L 是雙指標統計「兩數之和 $\le K$ 的數對個數」的經典公式，將 $O(N^2)$ 枚舉加速為 $O(N \log N)$。

Q-12-05-L02依起點排序檢查所有會議時間是否完全不重疊 計算邏輯

對應 單元 12.5

下列程式印出 True（端點相接如 (1, 3) 與 (3, 5) 視為不衝突）。哪一句描述 check_rooms(meetings) 的判斷功能，換成其他區間串列也成立？

    meetings = sorted(meetings)
    for i in range(1, len(meetings)):
        if meetings[i][0] < meetings[i - 1][1]:

    return True

⚡ 速解

按起點排好後，只要下一場的開始時間 < 前一場的結束時間就是撞期（回傳 False），全都沒撞期才回傳 True，秒選 (C)。

  1. 慢動作：
  • meetings = sorted(meetings) 將所有會議依開始時間由早到晚排列。
  • 排好後，若存在任何兩場會議時間重疊，必定會發生在相鄰的兩場之間。

  1. 選項逐項診斷：
  • (A) 函式第一行已經主動呼叫 sorted(meetings) 排好序，且 [(1, 4), (3, 6)] 中 3 < 4 時間重疊，會回傳 False。
  • (B) [(1, 2), (5, 6)] 中 5 < 2 不成立，迴圈走完會回傳 True（代表彼此不衝突）。
  • (C) 按開始時間排序後，只要有任何一場的開始時間 meetings[i][0] 嚴格小於前一場的結束時間 meetings[i - 1][1]，就代表時間衝突回傳 False。
  • (D) 迴圈比較的是相鄰兩場 i 與 i - 1，是檢查有無任何重疊衝突。
  1. APCS 考場心法與常見陷阱：
  • 檢查 $N$ 個區間是否有重疊：先按起點排序，再檢查相鄰區間是否滿足 next_start < prev_end！

  1. APCS 考場心法與常見陷阱：
  • 判讀二分搜尋函式先抓三件事：迴圈條件、mid 算法、邊界更新有沒有 ± 1。三處都對，才是可用的精確比對版本。

Q-12-07-L02二分搜尋的排序前提 計算邏輯

對應 單元 12.7

下列程式印出 3 -1。哪一句描述這個結果的原因，換成其他串列也成立？

def bsearch(nums, target):
    left, right = 0, len(nums) - 1
    while left <= right:
        mid = (left + right) // 2
        if nums[mid] == target:
            return mid
        if nums[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return -1

print(bsearch([1, 2, 3, 4, 5], 4), bsearch([5, 4, 3, 2, 1], 4))
🎉 答對了！標準答案是 (B)
⚡ 速解

「比小就往右、比大就往左」只在升序串列上成立；餵進降序串列，目標會被整塊誤棄而回傳 -1，秒選 (B)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作：
  • 第一個呼叫 [1, 2, 3, 4, 5] 已升序：mid = 2 比 3 < 4 往右，mid = 3 命中，回傳 3。
  • 第二個呼叫 [5, 4, 3, 2, 1] 降序：mid = 2 比到 3 < 4，程式據此把左半丟掉，但 4 正在左半，於是越找越偏，最後回傳 -1。
  • 代入 [2, 1] 找 1：mid = 0 比到 2 > 1，右邊界左移成 -1，區間空了，回傳 -1。故選 (B)。
  1. 選項逐項診斷：
  • (A) 二分搜尋每一步都依賴「右半比左半大」的事實，順序錯就會誤棄半邊。
  • (B) 排序是二分搜尋的硬前提；未排序時不會當機，而是可能安靜地回傳錯誤答案 -1。
  • (C) 函式內沒有任何會拋出 ValueError 的操作，index() 不在這裡。
  • (D) 邊界每圈仍縮小（mid ± 1），迴圈一定結束，只是答案錯。
  1. APCS 考場心法與常見陷阱：
  • 未排序資料要嘛先 sort()，要嘛改用線性搜尋。二分搜尋在亂序資料上最危險的不是慢，而是「看起來有跑完，答案卻是錯的」。

Q-12-08-R01lower_bound 追蹤：第一個大於或等於目標的索引 運行追蹤

對應 單元 12.8

下列 Python 程式執行後，畫面上印出的結果為何？

def lower_bound(nums, target):
    left, right = 0, len(nums)
    while left < right:
        mid = (left + right) // 2
        if nums[mid] < target:

        else:
            right = mid
    return left

print(lower_bound(nums, 3), lower_bound(nums, 4), lower_bound(nums, 9))
🎉 答對了！標準答案是 (C)
⚡ 速解

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作：
  • lower_bound(nums, 3)：mid = 2 比到 3，3 < 3 不成立，right = 2；mid = 0 比到 1 < 3，left = 1；mid = 1 比到 3 不小於 3，right = 1，區間 [1, 1] 結束，回傳 1。

  1. 選項逐項診斷：
  • (A) 第三格錯。目標比全部元素大時，插入位置是 len(nums)，不是最後一個索引。

  • [1, 2, 2, 2, 5, 5] 中 2 佔索引 1 到 3：lower_bound = 1、upper_bound = 4，差為 3。
  • 5 佔索引 4 到 5：lower_bound = 4、upper_bound = 6，差為 2。

  • (A) 第一個索引是 lower_bound 本身，不是兩者的差；且 [1, 3, 5] 的 lower 是 1 不是 0。
  • (B) 最後一個索引要再減 1，且 [1, 3, 5] 根本沒有 2。
  • (C) 兩個邊界夾住全部等於 target 的元素，差值即個數；target 不存在時兩邊界重合，差值為 0。
  • (D) 函式完全沒看大於 target 的元素，差值只涵蓋等於 target 的區段。
  1. APCS 考場心法與常見陷阱：
  • 「已排序＋統計次數」不用雜湊表也行：upper - lower 兩趟 $O(\log N)$ 就能數完，還順便得到左端與右端位置。

下列程式印出 [1, 3, 5, 7, 9] None。哪一句描述 bisect.insort(a, x) 的行為，換成其他已排序串列也成立？

import bisect

a = [1, 5, 9]
bisect.insort(a, 7)
b = bisect.insort(a, 3)
print(a, b)
🎉 答對了！標準答案是 (A)
⚡ 速解

insort = a.insert(bisect_right(a, x), x)，就地修改、回傳 None，重複值插右側，秒選 (A)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作：
  • 第一次 insort(a, 7)：7 的插入位置在 5 和 9 之間，a 變成 [1, 5, 7, 9]。
  • 第二次 insort(a, 3)：3 插在 1 和 5 之間，a 變成 [1, 3, 5, 7, 9]；回傳值 None 存進 b。
  • 代入 [2, 4] 插入 4：insort 等同 insort_right，插在既有 4 的右邊，得 [2, 4, 4]。故選 (A)。
  1. 選項逐項診斷：
  • (A) insort 先以 bisect_right 定位再 insert，就地修改且回傳 None，所以 b 是 None。
  • (B) 函式回傳值是 None 不是索引；b 印出來是 None 而不是 1。
  • (C) insort 不會回傳新串列，而是直接改原串列；也沒有「先加再全排」的行為。
  • (D) 任何值都會插入，「只在最大時才插入」是錯的，3 比很多元素小也成功插入。
  1. APCS 考場心法與常見陷阱：
  • 需要重複值插在左側時改用 insort_left；兩者都回傳 None。寫 a = bisect.insort(a, x) 會讓 a 瞬間變成 None。
