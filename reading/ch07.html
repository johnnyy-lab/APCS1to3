Q-07-01-R01跳脫字元換行與跳格之輸出格式追蹤 運行追蹤

對應 單元 7.1

下列 Python 程式執行後，畫面上總共會印出幾行文字？

s = "A\nB\tC\nD"
print(s)
🎉 答對了！標準答案是 (C)
⚡ 速解

跳脫字元 \n 代表換行，字串 s 中共出現 2 個 \n，分別在 A 之後與 C 之後，因此輸出會被切成 3 行（第 1 行 A、第 2 行 B C、第 3 行 D）。\t 為水平跳格不會換行，秒選 (C)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 執行流程拆解：
  • 字串字面值 "A\nB\tC\nD" 的組成解析：
  • 'A'：一般字元，印在第 1 行。
  • '\n'：換行字元（Line Feed），游標移至下一行開頭。
  • 'B'：一般字元，印在第 2 行開頭。
  • '\t'：跳格字元（Tab），游標跳至下一個 Tab 停駐點（通常為 4 或 8 個空格寬度）。
  • 'C'：一般字元，印在第 2 行跳格之後。
  • '\n'：第 2 個換行字元，游標移至第 3 行開頭。
  • 'D'：一般字元，印在第 3 行。
  • 終端機最終呈現：

```text

A

B C

D

```

  • 總行數為 3 行。故選 (C)。
  1. 選項逐項診斷：
  • (A) 1 行：誤以為 print() 只呼叫一次就只會印出一行，忽略了字串內部的 \n 具有強制換行效果。
  • (B) 2 行：漏算了第二個 \n。
  • (C) 3 行：正確答案。
  • (D) 4 行：誤以為 \t 也會換行。
  1. APCS 考場心法與常見陷阱：
  • 在 Python 字串中，反斜線 \ 是跳脫前綴：
  • \n：換行（Newline）
  • \t：水平跳格（Tab）
  • \\：純反斜線字元
  • 遇到輸出追蹤題時，看到幾個 \n 就代表換行幾次（產生 $N + 1$ 行），切勿與 print() 的預設換行混淆！

Q-07-01-R02反斜線自身跳脫與字串長度追蹤 運行追蹤

對應 單元 7.1

下列 Python 程式執行後，畫面上印出的結果為何？

s1 = "A\\nB"
s2 = "A\nB"
print(len(s1), len(s2))
🎉 答對了！標準答案是 (B)
⚡ 速解

"A\\nB" 中的 \\ 是跳脫反斜線自身（代表 1 個字元 \），後方的 n 是一般字元，加上 A 與 B 總長度為 4；而 "A\nB" 中的 \n 是換行跳脫字元，佔 1 個字元，總長度為 3。輸出為 4 3，秒選 (B)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 執行流程拆解與記憶體字元分析：
  • 字串 s1 = "A\\nB"：
  • 解譯器解析時，雙反斜線 \\ 會被轉譯為「單一反斜線字元 \」。
  • 隨後的字母 'n' 不再具有特殊跳脫語意，恢復為普通英文字母 'n'。
  • 記憶體中儲存的字元序列為：'A', '\\', 'n', 'B'，共 4 個字元。
  • len(s1) 回傳 4。印出時呈現為 A\nB。
  • 字串 s2 = "A\nB"：
  • 反斜線與字母 n 結合成「單一換行字元 \n（ASCII 代碼 10）」。
  • 記憶體中儲存的字元序列為：'A', '\n', 'B'，共 3 個字元。
  • len(s2) 回傳 3。
  • 兩者長度分別為 4 與 3，輸出 4 3。故選 (B)。
  1. 選項逐項診斷：
  • (A) 4 4：誤以為 \n 在長度計算時佔用 2 個字元（誤把原始碼字元數當作記憶體字元數）。
  • (B) 4 3：正確答案。
  • (C) 3 3：誤以為 \\n 也會被當成換行。
  • (D) 5 3：計算 s1 時多算了反斜線。
  1. APCS 考場心法與常見陷阱：
  • 「跳脫字元在長度 len() 中只佔 1 個字元」！
  • 無論是 \n、\t、\'、\" 還是 \\，轉譯後在記憶體中皆代表單一字元，長度一律為 1！
  • 但如果是 \\n，前面兩個反斜線結合成一個 \（長度 1），後面 n 是獨立字元（長度 1），兩者合計長度為 2。

Q-07-01-F01引號巢狀包夾合法語法填空 程式填空

對應 單元 7.1

小華希望在 Python 程式中將字串變數 msg 賦值，使其印出下列包含英文雙引號的語句：

He said, "Python is great!"
msg = [ 填空處 ]
print(msg)

在不使用任何反斜線跳脫字元的情況下，請問 [ 填空處 ] 應填入下列何者才能完全符合語法且正確印出？

🎉 答對了！標準答案是 (A)
⚡ 速解

若字串內部需要包含雙引號 "，最外層應使用單引號 '...' 包夾，內部雙引號便會自動視為普通文字，無需任何反斜線跳脫，秒選 (A)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 執行流程拆解與引號包夾原則：
  • Python 支援單引號 '...' 與雙引號 "..." 定義字串，兩者在功能上完全等價。
  • 引號巢狀包夾準則（Quotation Nesting Rule）：
  • 若字串內部包含雙引號 "，外層使用單引號 '...' 包夾；
  • 若字串內部包含單引號 '（如英文縮寫 It's），外層使用雙引號 "..." 包夾；
  • 只要內外引號種類不同，內部引號即可直接作為一般文字顯示，無需額外跳脫。
  • 檢視選項 (A)：'He said, "Python is great!"' 外層為單引號，內部雙引號安全保留，不含任何反斜線跳脫，語法完全合法且最為簡潔乾淨。故選 (A)。
  1. 選項逐項診斷：
  • (A) 正確使用「外單內雙」達到無跳脫安全包夾。
  • (B) 外層雙引號遇到內部的第一個雙引號即提早閉合（"He said, "），導致後方的 Python is great!"" 產生 SyntaxError: invalid syntax。
  • (C) 外層單引號遇到內部的單引號提早閉合，引發語法錯誤。
  • (D) 違背題意「在不使用任何反斜線跳脫字元的情況下」，且前後引號未對稱（前雙後單）。
  1. APCS 考場心法與常見陷阱：
  • 牢記口訣：「外單內雙，外雙內單」！
  • 善用此特性可免去書寫一堆反斜線 \" 或 \' 的繁瑣，提高程式可讀性。

Q-07-01-F02Windows 檔案路徑反斜線跳脫修復填空 程式填空

對應 單元 7.1

小明要在 Python 程式中儲存 Windows 檔案路徑字串：

C:\new\test

若直接寫 path = "C:\new\test"，因為 \n 會被解譯為換行、\t 會被解譯為跳格 Tab，導致印出路徑完全損毀。

path = [ 填空處 ]
print(path)

若要使用標準跳脫字元安全修復此路徑，請問 [ 填空處 ] 應填入下列何者？

🎉 答對了！標準答案是 (D)
⚡ 速解

在一般字串中，反斜線是跳脫前綴符號。若要保留單純的反斜線字元 \，必須寫成雙反斜線 \\ 進行自我跳脫。因此 C:\new\test 必須寫成 "C:\\new\\test"，秒選 (D)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 執行流程拆解與除錯：
  • 原始錯誤寫法分析：
  • 若寫 "C:\new\test"：
  • \n 被解譯為換行符號（Newline）；
  • \t 被解譯為水平跳格（Tab）；
  • print(path) 實際印出結果會慘烈崩潰成兩行：

```text

C:

ew est

```

  • 正確跳脫防禦機制：
  • 遇到第一個反斜線寫成 \\，解譯器轉譯為單一反斜線 \，後面的字母 n 恢復為普通英文字母；
  • 遇到第二個反斜線寫成 \\，解譯器轉譯為單一反斜線 \，後面的字母 t 恢復為普通英文字母；
  • 完整字面值為 "C:\\new\\test"。
  • 印出時完整還原：C:\new\test。故選 (D)。
  1. 選項逐項診斷：
  • (A) 原始錯誤代碼，\n 與 \t 會被誤當跳脫字元。
  • (B) 改用正斜線 /，雖然在部分跨平台系統可行，但改變了題目原本的反斜線規格且非本題跳脫考點。
  • (C) 只跳脫了第一個反斜線，第二個 \t 依然會被解譯為跳格。
  • (D) 正確對所有反斜線進行自我跳脫修復。
  1. APCS 考場心法與常見陷阱：
  • Windows 路徑是 APCS 與工程實務中最著名的字串陷阱之一。
  • 只要字串中出現反斜線 \，務必第一眼檢查它後方是否接著 n、t、r、b、\ 等跳脫字元！

Q-07-01-D01引號未成對閉合引發之語法錯誤排查 測試除錯

對應 單元 7.1

觀察下列 Python 程式碼：

text = "APCS'
print(text)

執行此程式時，Python 解譯器會回報何種錯誤？

🎉 答對了！標準答案是 (C)
⚡ 速解

字串開頭使用雙引號 "，結尾卻使用單引號 '，引號未成對匹配閉合，Python 在掃描到行尾時發現字串尚未結束，會拋出 SyntaxError: unterminated string literal，秒選 (C)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 執行流程拆解與錯誤分析：
  • Python 字串在定義時，前後的邊界引號必須型態一致：
  • 單引號必須由單引號閉合：'APCS'
  • 雙引號必須由雙引號閉合："APCS"
  • 在本題中：
  • 第 1 行以雙引號 " 開頭，解譯器進入「字串字面值讀取狀態」，在此狀態下它會持續尋找匹配的「雙引號」作為結束標記。
  • 後續遇到單引號 ' 時，解譯器僅將其視為字串內容的一部分，繼續往後讀取。
  • 讀到行尾（End of Line, EOL）換行時，依然沒有找到匹配的雙引號，語法解析器立即中斷並拋出語法錯誤：

SyntaxError: unterminated string literal (detected at line 1)

  • 該錯誤發生在編譯語法解析階段，程式一行都不會執行。故選 (C)。
  1. 選項逐項診斷：
  • (A) NameError：當讀取未被定義宣告的變數名稱時拋出，此處根本未進入執行階段。
  • (B) TypeError：型態不匹配時拋出。
  • (C) SyntaxError: unterminated string literal：正確指出引號未閉合之未終止字串字面值語法錯誤。
  • (D) ValueError：數值轉換無效時拋出。
  1. APCS 考場心法與常見陷阱：
  • 在紙筆測驗或電腦上遇到手滑寫錯前後引號，例如 "Hello' 或 'World"，直覺秒選 SyntaxError！
  • 牢記 Python 的字串成對原則：單配單、雙配雙、三單配三單、三雙配三雙。

Q-07-01-D02三引號多行字串內部包含換行字元排查 測試除錯

對應 單元 7.1

小華寫了以下三引號多行字串程式，希望精確計算字元總數：

s = """Hello
World"""
print(len(s))

小華原本預期長度應該是 10（單字 "Hello" 5 個字母加上 "World" 5 個字母），但程式執行後印出的結果卻是 11。

請問造成字串長度為 11 的主要原因為何？

🎉 答對了！標準答案是 (B)
⚡ 速解

三引號（"""...""" 或 '''...'''）的特性就是會原汁原味完整保留所有換行與縮排排版。第一行 Hello 與第二行 World 之間的「Enter 換行鍵」會被轉換為 1 個換行字元 \n 存入字串中，長度為 $5 + 1 + 5 = 11$，秒選 (B)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 執行流程拆解與三引號記憶體本質：
  • 三引號字串（Triple-Quoted String）專門用於處理多行文字或長段落。
  • 在原始碼中按下 Enter 換行時，該換行動作會直接被編譯為換行字元 \n。
  • 因此變數 s 在記憶體中的實際內容等價於：

s = "Hello\nWorld"

  • 字元明細清單：
  1. 'H'（第 1 個）
  2. 'e'（第 2 個）
  3. 'l'（第 3 個）
  4. 'l'（第 4 個）
  5. 'o'（第 5 個）
  6. '\n'（第 6 個，換行字元佔 1 位）
  7. 'W'（第 7 個）
  8. 'o'（第 8 個）
  9. 'r'（第 9 個）
  10. 'l'（第 10 個）
  11. 'd'（第 11 個）
  • len(s) 計算結果為 $5 + 1 + 5 = 11$。故選 (B)。
  1. 選項逐項診斷：
  • (A) C/C++ 語言的字串常有 \0 終止符號，但 Python 的 str 物件紀錄顯式長度，len() 絕不會多加 1。
  • (B) 正確指出三引號保留換行字元 \n 的本質。
  • (C) 邊界引號只用於界定語法範圍，不計入字串內容。
  • (D) 換行就是換行字元 \n，絕非空格字元 ' '。
  1. APCS 考場心法與常見陷阱：
  • 計算三引號多行字串長度時，「每一行結尾的換行鍵都算 1 個字元」！
  • 若開頭 """ 後立刻按 Enter 換行，則開頭就會包含一個 \n；若不想包含該換行，可在行尾加上反斜線 \ 進行折行消除。

Q-07-01-P01各類跳脫字元於記憶體中之字元數長度計算 效能分析

對應 單元 7.1

在 Python 中，下列 4 個字串變數各自的 len() 運算結果分別為何？

w1 = "Python"
w2 = "Py\nthon"
w3 = "Py\\nthon"
w4 = "Py\'\"thon"
print(len(w1), len(w2), len(w3), len(w4))
🎉 答對了！標準答案是 (C)
⚡ 速解

w1 純字母長度 6；w2 包含 1 個 \n，長度 $6 + 1 = 7$；w3 包含 \\ 與 n 兩個獨立字元，長度 $6 + 2 = 8$；w4 包含 \' 與 \" 兩個跳脫引號，長度 $6 + 2 = 8$。輸出為 6 7 8 8，秒選 (C)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 各字串長度逐一拆解：
  • w1 = "Python"：
  • 6 個普通英文字母，長度為 6。
  • w2 = "Py\nthon"：
  • 'P', 'y'（2）+ '\n'（1）+ 't', 'h', 'o', 'n'（4）。
  • 總字元數：$2 + 1 + 4 = 7$。
  • w3 = "Py\\nthon"：
  • 'P', 'y'（2）+ '\\'（1）+ 'n'（1）+ 't', 'h', 'o', 'n'（4）。
  • 雙反斜線轉為 1 個反斜線，n 為普通字母，總字元數：$2 + 1 + 1 + 4 = 8$。
  • w4 = "Py\'\"thon"：
  • 'P', 'y'（2）+ '\''（1）+ '\"'（1）+ 't', 'h', 'o', 'n'（4）。
  • 包含 1 個跳脫單引號與 1 個跳脫雙引號，總字元數：$2 + 1 + 1 + 4 = 8$。
  • 因此輸出為 6 7 8 8。故選 (C)。
  1. 選項逐項診斷：
  • (A) 6 8 9 9：誤把跳脫字元當成原始碼中的 2 個字元計數。
  • (B) 6 7 7 8：誤以為 w3 的長度與 w2 相同。
  • (C) 6 7 8 8：正確答案。
  • (D) 6 6 8 8：誤以為 \n 不佔長度。
  1. APCS 考場心法與常見陷阱：
  • 遇到計算字串長度題時，在考卷上可使用筆尖逐一標註記憶體字元：

P(1) y(2) \(3) n(4) t(5) h(6) o(7) n(8)

  • 清楚分開「跳脫字元組合（2 個原始碼字元轉為 1 個字元）」與「一般字元」，長度計算絕對萬無一失！

Q-07-01-P02三引號多行排版換行符號統計分析 效能分析

對應 單元 7.1

觀察下列三引號字串宣告與走訪計數程式：

text = """
A
B
C
"""
count = 0
for ch in text:
    if ch == "\n":
        count += 1
print(count)

畫面上印出的結果為何？

🎉 答對了！標準答案是 (B)
⚡ 速解

檢視三引號字串中的每一處換行：開頭 """ 後換行（第 1 個）、A 後換行（第 2 個）、B 後換行（第 3 個）、C 後換行（第 4 個），隨後遇到結尾 """。總共有 4 個換行符號 \n，輸出 4，秒選 (B)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 執行流程拆解與換行位置精確標註：
  • 在原始碼中展開 text 的每個字元：

```text

"""\n <- 第 1 個 \n（開頭三引號後換行）

A\n <- 第 2 個 \n（A 之後換行）

B\n <- 第 3 個 \n（B 之後換行）

C\n <- 第 4 個 \n（C 之後換行）

""" <- 結尾三引號閉合

```

  • 變數 text 在記憶體中的實際內容為："\nA\nB\nC\n"。
  • 迴圈 for ch in text: 依序走訪所有字元：
  1. ch = '\n'：count 累加為 1。
  2. ch = 'A'：不累加。
  3. ch = '\n'：count 累加為 2。
  4. ch = 'B'：不累加。
  5. ch = '\n'：count 累加為 3。
  6. ch = 'C'：不累加。
  7. ch = '\n'：count 累加為 4。

Q-07-02-R01字串乘法與加法之運算子優先級追蹤 運行追蹤

對應 單元 7.2

下列 Python 程式執行後，畫面上印出的結果為何？

print(s1, s2)
🎉 答對了！標準答案是 (B)
⚡ 速解

字串乘法 *（重複）優先級高於加法 +（串接）。s1 先算 "B" * 3 得到 "BBB"，再與 "A" 串接成 "ABBB"；s2 有括號優先，先算 "A" + "B" 得到 "AB"，再重複 3 次得到 "ABABAB"。輸出為 ABBB ABABAB，秒選 (B)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 執行流程拆解與優先級分析：
  • 在 Python 算術與序列運算子優先級體系中，乘法 * 的優先順序高於加法 +。
  • **計算 s1 = "A" + "B" * 3**：
  • 先計算乘法項："B" * 3 執行字串重複運算，生成 "BBB"。
  • 再計算加法項："A" + "BBB" 執行字串串接運算，生成 "ABBB"。
  • 賦值給變數 s1。
  • **計算 s2 = ("A" + "B") * 3**：
  • 小括號 (...) 擁有最高優先權。
  • 先計算括號內："A" + "B" 得到 "AB"。
  • 再計算括號外乘法："AB" * 3 將整個二字元序列重複 3 次，生成 "ABABAB"。
  • 賦值給變數 s2。
  • 執行 print(s1, s2)，輸出為 ABBB ABABAB。故選 (B)。
  1. 選項逐項診斷：
  • (A) ABABAB ABBB：將 s1 與 s2 的運算結果顛倒。
  • (B) ABBB ABABAB：正確答案。
  • (C) ABBB ABBB：誤以為括號沒有發揮改變運算優先級的作用。
  • (D) ABABAB ABABAB：誤以為 s1 的加法會先做（由左至右平鋪直敘計算）。
  1. APCS 考場心法與常見陷阱：
  • 「先乘除後加減」的運算優先級法則在字串運算中完全一體適用！
  • 字串乘法是「重複造字」，字串加法是「端點縫合」；若要將整組複合字串重複，務必加上小括號保護！

  • 在一般字串中，特殊字元使用反斜線 \ 跳脫；
  • 但在 f-string 中，大括號 { 與 } 的跳脫規則是「雙寫（Double Braces）」：

  • 中間字串為 ", "；
  • 接著動態插入變數 b 的值，寫成 {b}；
  • 結尾要印出一個實體 }，需寫成 }}；
  • 兩者連在一起即為 {b}}}。
  • 組合結果為：The set is {{{a}, {b}}}。

Q-07-03-L01浮點數格式化銀行家捨入法邊界邏輯解析 計算邏輯

在 Python 中，下列 f-string 浮點數格式化程式執行後的輸出為何？

  1. 執行流程拆解與銀行家捨入法（Banker's Rounding）：
  • 在國小數學常規的「四捨五入」中，.5 一律進位（2.5 變 3，3.5 變 4）。
  • 但在電腦科學與現代程式語言（Python、C# 等）中，為了避免大量浮點數累加運算時長期向上進位導致統計偏差，採用了 IEEE 754 標準的 「Round-half-to-even（五成雙／偶數捨入法）」：
  • 當欲捨去的部分剛好等於 0.5（剛好在兩整數的正中間）時：
  • 若前一位是 偶數，則 捨去（保持偶數）；
  • 若前一位是 奇數，則 進位（變成偶數）。
  • 分析 v1 = 2.5 格式化 :.0f：
  • 介於整數 2 與 3 之間，小數為剛好 0.5。
  • 2 是偶數，因此捨入至最接近的偶數 2。
  • 格式化結果為 "2"。
  • 分析 v2 = 3.5 格式化 :.0f：
  • 介於整數 3 與 4 之間，小數為剛好 0.5。
  • 4 是偶數，因此進位至最接近的偶數 4。
  • 格式化結果為 "4"。
  • 最終合成字串為 "2 and 4"。故選 (A)。
  1. 選項逐項診斷：
  • (A) 2 and 4：正確答案，完全符合 Python 底層銀行家捨入規則。
  • (B) 3 and 4：傳統數學四捨五入的直覺誤區（誤以為 2.5 會進位成 3）。
  • (C) 2 and 3：誤以為一律無條件捨去。
  • (D) 3 and 3：隨機臆測選項。
  1. APCS 考場心法與常見陷阱：
  • 「Python 裡逢 5 看偶數」！
  • 無論是內建的 round(x) 還是 f-string 的 :.0f、:.1f，遇到剛好是 5 的邊界時，一律朝「偶數」靠攏！

Q-07-04-R01正負索引雙向對應與單字元存取追蹤 運行追蹤

下列 Python 程式執行後，畫面上印出的結果為何？

last = s[-1]
mid = s[-4]
print(first + mid + last)
🎉 答對了！標準答案是 (B)
⚡ 速解

s[0] 是第 1 個字元 'P'；s[-1] 是最後 1 個字元 'N'；s[-4] 是倒數第 4 個字元（依序為 -1:'N', -2:'O', -3:'H', -4:'T'）得到 'T'。串接後為 'P' + 'T' + 'N' = 'PTN'，秒選 (B)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 執行流程拆解與正負索引雙向對照表：
  • 字串 s = "PYTHON" 的長度為 $\text{len}(s) = 6$。

| 字元 | 'P' | 'Y' | 'T' | 'H' | 'O' | 'N' |

| :--- | :---: | :---: | :---: | :---: | :---: | :---: |

| 正向索引 | 0 | 1 | 2 | 3 | 4 | 5 |

| 負向索引 | -6 | -5 | -4 | -3 | -2 | -1 |

  • first = s[0]：取出正向下標 0 的字元 'P'。

  • (A) PYN：誤將倒數第 4 個字元看成 'Y'（把 -4 當成 -5）。

  • (C) PHN：誤將倒數第 4 個字元看成 'H'（把 -4 當成 -3）。

Q-07-04-R02索引下標走訪與交錯字元條件篩選追蹤 運行追蹤

對應 單元 7.4

下列 Python 程式執行後，畫面上印出的字串為何？

for i in range(len(word)):

print(ans)
🎉 答對了！標準答案是 (C)
⚡ 速解

range(len(word)) 產生索引 0 到 5。i % 2 == 0 挑選偶數索引：$i = 0$ 挑 'A'、$i = 2$ 挑 'C'、$i = 4$ 挑 'E'，串接得到 "ACE"，秒選 (C)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 執行流程拆解與索引走訪追蹤：
  • word = "ABCDEF"，長度 $\text{len}(word) = 6$。
  • range(6) 依序走訪索引 $i = 0, 1, 2, 3, 4, 5$：
  • $i = 0$：$0 \% 2 == 0$ 為真，ans += word[0]（'A'），ans = "A"。
  • $i = 1$：$1 \% 2 == 0$ 為假，跳過。
  • $i = 2$：$2 \% 2 == 0$ 為真，ans += word[2]（'C'），ans = "AC"。
  • $i = 3$：$3 \% 2 == 0$ 為假，跳過。
  • $i = 4$：$4 \% 2 == 0$ 為真，ans += word[4]（'E'），ans = "ACE"。

Q-07-04-L02正負索引等價轉換代數關係解析 計算邏輯

對應 單元 7.4

對於任意非空字串 s（$\text{len}(s) > 0$），下列哪一組正向索引與負向索引所指向的**永遠是完全相同的同一個字元**？

🎉 答對了！標準答案是 (D)
⚡ 速解

字串最後一個字元的正向索引是 len(s) - 1，負向倒數索引是 -1，兩者永遠都精確指向字串的最後一個字元，秒選 (D)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 正負索引的數學代數轉換公式：
  • 設字串長度為 $N = \text{len}(s)$。
  • Python 規定負向下標 $-k$ 的實體位址等價於正向下標 $N - k$：

$$\text{負向索引 } -k \iff \text{正向索引 } N - k$$

  • 當 $k = 1$（指向最後一個字元）時：
  • 負向表示法：s[-1]
  • 正向表示法：s[N - 1]（即 s[len(s) - 1]）
  • 兩者必定指向完全相同的字元位置。故 (D) 恆成立。
  1. 選項逐項診斷：
  • (A) s[i] 與 s[-i]：當 $i=1$ 時，$s[1]$ 是第二個字元，而 $s[-1]$ 是最後一個字元，絕不相同（除非長度為 2 且字元相同）。
  • (B) s[0] 的負向等價下標是 s[-len(s)]，而非 s[-len(s) + 1]。
  • (C) s[1] 是第二個字元，$s[-1]$ 是最後一個字元，長度不為 2 時指向不同字元。
  • (D) 正確對應末尾字元之正負索引代數式。
  1. APCS 考場心法與常見陷阱：
  • 熟記兩大端點的雙向對照：
  • 第一個字元：s[0] $\iff$ s[-len(s)]
  • 最後一個字元：s[len(s) - 1] $\iff$ s[-1]

Q-07-05-L02負向步長省略邊界的隱含邊界值解析 計算邏輯

對應 單元 7.5

當切片步長為負數時（例如 s[::-1]），起點與終點若被省略，Python 直譯器所套用的**隱含預設值**分別為何？

若步長為負數，走訪方向是由右向左。因此起點預設必須是「最右端（最後一個字元）」，終點必須一路倒退走到「最左端且包含索引 0」，秒選 (D)。

  1. 慢動作底層邏輯與直譯器規則：
  • 切片運算式的預設值並非固定不變，而是根據 step 的正負號進行動態切換：
  • 當 step > 0（正向走訪）：
  • start 預設為 0（開頭）。
  • end 預設為 len(s)（結尾，左閉右開故包含到 len(s)-1）。
  • 當 step < 0（反向走訪）：
  • start 預設為字串最後一個元素（索引 len(s)-1 或 -1）。

  • 如果終點設為 0（例如寫成 s[-1:0:-1]），因為左閉右開不含終點，索引 0 的第一個字元反而會被硬生生丟棄！
  • 因此，直譯器內部設計的隱含終點是特殊標記（None），代表一路倒退走到底，完整保留索引 0。
  • 故 (D) 的描述最符合 Python 直譯器的底層規範。故選 (D)。
  1. 選項逐項診斷：
  • (A) 這是步長為正數時的預設值，若套用到負步長會直接因方向矛盾回傳空字串。
  • (B) 終點若是 0，則索引 0 不會被包含進來，反轉字串會少一個字元。
  • (C) 錯誤認為不包含索引 0。
  • (D) 完整且精準說明負步長時起點與終點的直譯器行為與邊界包含性。
  1. APCS 考場心法與常見陷阱：
  • 為何自己手寫 s[5:0:-1] 永遠無法反轉整條長度為 6 的字串？因為下標 0 不會被包含！
  • 要反轉整條字串，最安全乾淨的寫法就是「省略起點與終點」，直接寫 s[::-1]，讓直譯器自動幫你處理索引 0 的包含問題！

  • 找到時：回傳該子字串第一次出現的索引值（$\ge 0$）。
  • 找不到時：直接引發 ValueError: substring not found，導致程式崩潰中斷！
  • 錯誤成因分析：
  • 小華在第 2 行執行 s.index("z") 時，因為 "apple" 中不存在 'z'，直譯器立即丟出 ValueError。
  • 程式在第 2 行即刻死當，根本沒有機會執行到第 3 行的 if pos == -1:。
  • 修正方案：
  • 方案一：將 s.index("z") 改為 s.find("z")，找不到時 pos 為 -1，順利印出 "Not found"。
  • 方案二：直接使用 Pythonic 的成員運算式 if "z" not in s:。
  • 因此 (C) 診斷精準且修正合理。故選 (C)。
  1. 選項逐項診斷：
  • (A) .index() 從不回傳布林值。
  • (B) 回傳 0 代表目標出現在第 0 個索引位置（開頭），而非找不到。
  • (C) 精確指出 .index() 拋出 ValueError 之關鍵差異與最佳修正。
  • (D) Python 中單雙引號完全等價相容，混用非報錯原因。
  1. APCS 考場心法與常見陷阱：
  • find vs index 記憶口訣：
  • 想找索引且「保證存在」時，可用 .index()。
  • 「不確定是否存在」且想靠條件判斷處理時，務必使用 .find() 或先用 in 做安全檢查！

Q-07-06-D02count 方法不重疊匹配機制除錯 測試除錯

對應 單元 7.6

小明想計算字串 s = "AAAA" 中總共包含幾個子字串 "AA"。他寫下了下列程式，原本預期會印出 3（因為索引 0~1、1~2、2~3 各有一組 "AA"），但執行後畫面卻印出 2。

s = "AAAA"
count = s.count("AA")
print(count)

請問導致印出結果為 2 而非 3 的**根本原因**為何？

🎉 答對了！標準答案是 (B)
⚡ 速解

.count() 的底層匹配原則是「不重疊（Non-overlapping）」！從左至右貪婪匹配，取走索引 0~1 的 "AA" 後，搜尋游標直接跳到索引 2，接著取走索引 2~3 的 "AA"，總共只有 2 次，秒選 (B)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作底層匹配演算法追蹤：
  • 字串 s = "AAAA"，長度為 4，索引 0, 1, 2, 3。
  • 呼叫 s.count("AA") 時，直譯器採用從左到右的不重疊貪婪比對：
  • 第一步：從索引 0 開始向右搜尋，在索引 0~1 成功找到第一組 "AA"。
  • 第二步（關鍵跳步）：直譯器為避免重疊計算，將搜尋指標移動至已匹配子字串的尾端之後，即指標跳至索引 2！
  • 第三步：從索引 2 繼續向右搜尋，在索引 2~3 成功找到第二組 "AA"。
  • 第四步：搜尋指標移動至索引 4，已達字串結尾，比對終止。
  • 總計成功計數次數為 $1 + 1 = 2$ 次。
  • 索引 1~2 雖然在肉眼看似也是 "AA"，但因其包含了已被第一組吃掉的索引 1 字元，直譯器依規範絕不重複採計！
  • 故選 (B)。
  1. 選項逐項診斷：
  • (A) 誤以為這只是巧合的整除現象，若 s = "AAAAA"，s.count("AA") 依然是 2（$5//2 = 2$），真正原因是非重疊比對而非純除法。
  • (B) 精確闡明 Python 官方所定義之「Non-overlapping matching」底層機制。
  • (C) 無稽之談，字串比對與快取無關。
  • (D) 語法完全合法，.count() 本來就是原生字串方法。
  1. APCS 考場心法與常見陷阱：
  • 在 APCS 競賽或學科中，若題目要求計算「所有可能出現（包含重疊）」的子字串次數，千萬不能直接呼叫 .count()！
  • 若要計算包含重疊的次數，必須自己撰寫 for i in range(len(s) - len(sub) + 1) 搭配切片 s[i:i+len(sub)] == sub 逐格比對！

Q-07-06-P01子字串成員運算 in 之最壞情況比對效能分析 效能分析

對應 單元 7.6

已知字串 s 的長度為 $N$，欲搜尋之子字串 sub 的長度為 $M$（其中 $N \ge M \ge 1$）。若在最壞情況下（Worst Case，例如原始字串為 s = "AAAAAB"，而搜尋目標為 sub = "AAB"），執行成員運算式 sub in s 進行樸素比對時，其時間複雜度量級最壞可能達到下列何者？

🎉 答對了！標準答案是 (D)
⚡ 速解

在最壞情況下，字串 s 中共有約 $N$ 個起始比對點，每個起點都要比對到子字串末尾 $M$ 個字元才發現不符並回溯，總比對次數達到 $N \times M$，時間複雜度為 $O(N \times M)$，秒選 (D)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作最壞情況比對模型推導：
  • 設主字串長度為 $N$，目標子字串長度為 $M$。
  • 主字串中所有可能的起始滑動窗口起點共有：

$$\text{起點總數} = N - M + 1$$

  • 考慮極端惡劣的比對資料（例如 $s = \text{"AAAAAAAAAB"}$，$sub = \text{"AAAB"}$）：
  • 在第 0 個起點：比對前 3 個字元皆為 'A'，直到比對第 4 個字元 'B' 時才宣告失敗（消耗 $M$ 次比對）。
  • 在第 1 個起點：再度比對前 3 個字元皆為 'A'，第 4 個字元再度失敗（再度消耗 $M$ 次比對）。
  • ...依此類推，在每一個起點都幾乎比對完全部 $M$ 個字元才發現失配。
  • 總比對次數上限為：

$$(N - M + 1) \times M = N \cdot M - M^2 + M$$

  • 以大 $O$ 漸近符號表示時，最高次項為 $N \times M$，故最壞情況時間複雜度為 $O(N \times M)$。故選 (D)。
  1. 選項逐項診斷：
  • (A) $O(1)$ 為雜湊表常數查詢，長字串比對不可能 $O(1)$。
  • (B) $O(\log N)$ 為二分搜尋量級，未經索引處理的字串無法對數搜尋。
  • (C) $O(N + M)$ 為高級演算法（如 KMP 或 Boyer-Moore 演算法）經過預處理後的線性時間，非樸素滑動窗口之最壞狀況。
  • (D) 精準符合字串滑動比對最壞情況之多項式時間複雜度。
  1. APCS 考場心法與常見陷阱：
  • 雖然 Python 內部實作採用了改良的快速字串搜尋演算法（Boyer-Moore-Horspool 變形），在平均情況下逼近 $O(N)$；但在學科理論分析與最壞情況下，兩個字串的樸素暴力搜尋始終是 $O(N \times M)$，這是演算法基礎理論的經典考題！

Q-07-06-P02迴圈不可變累加 vs 內建方法一次性轉換效能分析 效能分析

對應 單元 7.6

在 Python 中，考慮下列兩段將字串 s（長度為 $N$）中所有字元轉為大寫並產生新字串的寫法：

# 寫法甲：迴圈逐字累加字串
result = ""
for ch in s:
    result += ch.upper()

# 寫法乙：呼叫原生字串方法
result = s.upper()

有關這兩種寫法在時間效能與記憶體操作上的對比，下列敘述何者**最正確**？

🎉 答對了！標準答案是 (C)
⚡ 速解

字串具有不可變性，在迴圈中使用 += 拼接字串常導致反覆重新配置記憶體並複製內容，時間成本易退化；而原生方法 s.upper() 是 C 語言底層一次性配置剛好大小的記憶體區塊進行快速轉換，執行效能遠遠狂勝迴圈，秒選 (C)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作底層機制與效能差異剖析：
  • 寫法甲（迴圈逐步累加）：
  • 因為字串是不可變物件，每次執行 result += ... 時，直譯器理論上無法在原地擴充字串長度。
  • 必須重新在記憶體中配置一塊「長度為當前字串 + 1」的新空間，將舊字串所有字元逐一複製過去，再加上新字元。
  • 累加 $N$ 次總共涉及的字元複製次數為：

$$1 + 2 + 3 + \dots + N = \frac{N(N+1)}{2} \approx O(N^2)$$

  • 雖然 CPython 對某些特定情況有進行小幅度的緩衝區重複利用最佳化，但在大多數複雜情境下仍會造成嚴重的記憶體碎片化與龐大負擔。
  • 寫法乙（原生字串方法 s.upper()）：
  • 原生方法是以底層 C 語言直接實作。
  • 進入函式時已知字串長度為 $N$，立即一次性精確配置剛好大小為 $N$ 的字串記憶體空間。
  • 利用 CPU 高速指令集（SIMD / 記憶體管線化）一口氣進行字元大小寫位元轉換，整個過程只走訪一次記憶體，時間複雜度為嚴格的 $O(N)$。
  • 綜合比較：寫法乙在執行速度、CPU 使用率與記憶體管理效率上皆遠遠超越寫法甲。故選 (C)。
  1. 選項逐項診斷：
  • (A) 寫法甲不斷建立臨時物件，效能極差。
  • (B) 直譯器不會也不可能自動把自訂 for 迴圈重寫為 C 函式呼叫。
  • (C) 完整切中字串不可變性造成的物件複製成本與 C 底層批量最佳化差異。
  • (D) s.upper() 長度在字串物件標頭已快取（$O(1)$ 取得），只需線性 $O(N)$ 遍歷一次。
  1. APCS 考場心法與常見陷阱：
  • APCS 程式寫作效能心法：
  • 能用內建字串方法（如 .upper(), .lower(), .replace(), .strip()）解決的，絕不手寫 Python 迴圈！
  • 若非得在迴圈中組合大量字串，應先用列表 .append() 收集，最後再呼叫 "".join(list) 一次合併，避免 $O(N^2)$ 的累加災難！

Q-07-06-L01連續方法鏈結呼叫 Method Chaining 執行邏輯分析 計算邏輯

對應 單元 7.6

下列 Python 程式執行後，畫面上會印出什麼結果？

text = "  python_is_FUN!  "
result = text.strip().replace("_", " ").lower()
print(result)
🎉 答對了！標準答案是 (A)
⚡ 速解

方法鏈結（Method Chaining）由左至右依序執行：

  1. .strip() 去掉前後空白 $\to$ "python_is_FUN!"
  2. .replace("_", " ") 底線換空格 $\to$ "python is FUN!"
  3. .lower() 全轉小寫 $\to$ "python is fun!"

輸出為 python is fun!，秒選 (A)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作鏈結呼叫執行流程剖析：
  • 原始變數：text = " python_is_FUN! "
  • 第一棒呼叫：text.strip()
  • 作用：剝除字串最前端與最末端的所有空格。
  • 產出中間產物字串："python_is_FUN!"。
  • 第二棒呼叫："python_is_FUN!".replace("_", " ")
  • 作用：將該字串中所有出現的底線字元 "_" 替換為單一空格 " "。
  • 產出中間產物字串："python is FUN!"。
  • 第三棒呼叫："python is FUN!".lower()
  • 作用：將字串中所有大寫英文字母轉為小寫（'F', 'U', 'N' 轉為 'f', 'u', 'n'，非字母字元如驚嘆號與空格保持不變）。
  • 產出最終結果字串："python is fun!"。
  • 變數 result 接收最終產物 "python is fun!" 並印出。故選 (A)。
  1. 選項逐項診斷：
  • (A) 正確依序追蹤三道方法轉換之最終乾淨字串。
  • (B) 忽略了第一步 .strip() 的去空白功能。
  • (C) 忽略了第二步 .replace("_", " ") 將底線替換為空格的功能。
  • (D) 誤將 .lower() 當成了 .upper()。
  1. APCS 考場心法與常見陷阱：
  • 「方法鏈結（Method Chaining）」是物件導向程式設計的重要特性。因為字串方法執行後回傳的依然是字串物件（str），因此可以直接在後面繼續點出下一個字串方法！
  • 閱讀這類長式子時，只要由左至右像流水線（Pipeline）一樣一步步推進，題目便能迎刃而解。

Q-07-06-L02指定分隔符號與預設空白切割之空字串保留邏輯解析 計算邏輯

對應 單元 7.6

觀察下列 Python 程式碼，執行後畫面上印出的兩個整數長度分別為何？

s = "A,,B"
list1 = s.split(",")
list2 = "A  B".split()
print(len(list1), len(list2))
🎉 答對了！標準答案是 (D)
⚡ 速解

s.split(",") 指定了分隔符號，遇到連續兩個逗號時，中間會如實保留一個「空字串 ""」，因此切出 ['A', '', 'B'] 共 3 個元素；而 "A B".split() 未指定參數時，連續空白會被自動合併為單一分隔符，切出 ['A', 'B'] 共 2 個元素。輸出為 3 2，秒選 (D)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作底層切割邏輯差異剖析：
  • 案例一：list1 = "A,,B".split(",")
  • 呼叫方式：明確傳入分隔符號參數 sep=","。
  • Python 規範：當指定具體分隔符號時，直譯器嚴格以該字元為刀刃進行劃分。
  • 第一刀在索引 1（第 1 個逗號處）：刀刃左側為 "A"。
  • 第二刀在索引 2（第 2 個逗號處）：兩刀緊鄰相接，兩刀之間沒有任何字元，直譯器會如實保留並產生一個空字串 ""！
  • 第二刀右側為 "B"。
  • 因此 list1 = ['A', '', 'B']，元素個數 len(list1) = 3。
  • 案例二：list2 = "A B".split()
  • 呼叫方式：未傳入任何參數（sep=None，預設空白模式）。
  • Python 規範：採用演算法級空白合併機制，將所有連續相鄰的空格、跳格或換行打包視為單一邊界，且自動過濾掉空片段。
  • 因此即使 'A' 與 'B' 之間有 2 個（甚至 10 個）空格，也僅會被切成兩份。
  • 因此 list2 = ['A', 'B']，元素個數 len(list2) = 2。
  • print(len(list1), len(list2)) 輸出結果為 3 2。故選 (D)。
  1. 選項逐項診斷：
  • (A) 誤以為 split(",") 會自動吃掉中間的空字串。
  • (B) 誤以為 split() 會將多餘空格也保留為空字串。
  • (C) 兩者長度完全顛倒。
  • (D) 精準掌握「指定分隔符號保留空字串」與「預設模式合併空白」之底層本質差異。
  1. APCS 考場心法與常見陷阱：
  • 這是 Python 最具隱蔽性的高難度觀念陷阱之一！
  • 處理 CSV 試算表格式時（逗號分隔），空欄位（如 "1,,3"）必須被保留為空字串，以維持表格欄位對齊；而處理終端文字輸入時，連續空格只是排版間距，必須被合併。Python 透過是否有傳入參數巧妙區分了這兩種真實世界的應用場景！
