Q-05-01-R01運算子優先級：先算術運算再進行大小比較追蹤 運行追蹤

答案 (C)

⚡ 速解

牢記優先級鐵律：「先乘除、後加減、最後比大小」。ans1 先算 $3 \times 2 = 6$，加 5 得 11，$11 > 10$ 為 True；ans2 先算兩端乘除與加法 $5 \times 2 = 10$ 及 $3 + 7 = 10$，$10 == 10$ 為 True。兩者皆真。秒選 (C)。

🔍 深度詳解（點擊展開慢動作拆解與常見陷阱）
  1. 運算子優先級（Operator Precedence）層級體系：
  • 在 Python 表達式中，各類運算子的結合順序有嚴格的高低層級：
  • 高階：乘除算術運算子（*, /, //, %）
  • 次高：加減算術運算子（+, -）
  • 中階：比較運算子（>, <, >=, <=, ==, !=）
  • 低階：賦值運算子（=）
  1. 逐步推演驗證：
  • 第 3 行：ans1 = x + y * 2 > 10
  • 先算乘法：y * 2 = 3 * 2 = 6。
  • 再算加法：x + 6 = 5 + 6 = 11。
  • 最後進行大於比較：11 > 10，條件成立，回傳布林值 True。
  • 第 4 行：ans2 = x * 2 == y + 7
  • 左側算術求值：x * 2 = 5 * 2 = 10。
  • 右側算術求值：y + 7 = 3 + 7 = 10。
  • 執行相等比較：10 == 10，條件成立，回傳布林值 True。
  • 第 5 行以空格隔開印出 True True。
  1. 錯誤選項逐項診斷：
  • (A) 誤以為 ans1 是由左至右先加後乘（$(5 + 3) \times 2 = 16$），但判斷為 False 則是算術錯誤。
  • (B) 誤以為 ans2 兩邊不等。
  • (D) 兩者皆真，不可能皆為 False。故選 (C)。

Q-05-01-R02Python 連續比較式（Chained Comparisons）多重鏈結求值追蹤 運行追蹤

答案 (A)

⚡ 速解

連續比較等價於隱含的「且（AND）」連接。res1 三者皆為 15（True）；res2 中 $5 < 8 < 10 \le 15$ 全程遞增成立（True）；res3 中 $10 < 8$ 首關即不成立（False）。輸出 True True False。秒選 (A)。

🔍 深度詳解（點擊展開慢動作拆解與常見陷阱）
  1. 連續比較式語法糖（Syntactic Sugar）：
  • 在 C/C++ 或 Java 中，5 < x < 10 會先計算 5 < x 得 1，再拿 1 < 10 比較，產生違背直覺的結果。
  • 但在 Python 中，連續比較被嚴格實作為連鎖邏輯：
  • a == b == c 等價於 (a == b) and (b == c)。因為 $15 == 15$ 且 $15 == 15$ 皆為真，res1 為 True。
  • 5 < x < 10 <= a 等價於 (5 < x) and (x < 10) and (10 <= a)。代入 $x=8, a=15$，三者分別為 $5 < 8$（真）、$8 < 10$（真）、$10 \le 15$（真），全體皆真，res2 為 True。
  • 10 < x < 20 等價於 (10 < x) and (x < 20)。第一項 $10 < 8$ 即為假，res3 為 False。
  1. 錯誤選項逐項診斷：
  • (B) 誤以為 res3 中 $x < 20$ 成立整串就成立，忽略了第一段 $10 < 8$ 違背。
  • (C) 誤以為多等號比較 a == b == c 語法錯誤或回傳 False。
  • (D) 連續比較是 Python 的獨家原生核心特性，絕非語法錯誤。故選 (A)。

Q-05-01-F01字串字典序比較（ASCII 編碼大小）判斷填空 程式填空

答案 (B)

⚡ 速解

字串由左至右逐字元比對 ASCII 編碼。大寫 'A' 的編碼為 65，小寫 'a' 的編碼為 97。因為 $65 < 97$，所以在 Python 中 "Apple" < "apple" 為 True。空格填入 <。秒選 (B)。

🔍 深度詳解（點擊展開慢動作拆解與常見陷阱）
  1. 字串字典序比對演算法：
  • 直譯器會從兩個字串的第一個字元開始比對：
  • s1[0] 為 'A'，其 ASCII 碼為 ord('A') = 65。
  • s2[0] 為 'a'，其 ASCII 碼為 ord('a') = 97。
  • 因為在首字元就分出了勝負（$65 < 97$），直譯器立刻得出 "Apple" < "apple" 為 True，後續字元完全無需比對。
  1. 錯誤選項逐項診斷：
  • (A) >：$65 > 97$ 為假，輸出會變成 False。
  • (C) ==：兩字串大小寫不同，嚴格相等比較為 False。
  • (D) >=：輸出亦為 False。故選 (B)。

Q-05-01-F02閉區間範圍檢驗連續比較式填空 程式填空

答案 (D)

⚡ 速解

數學上的閉區間 $60 \le \text{score} \le 100$ 包含邊界端點。在 Python 中可一對一直接寫出連續比較式 60 <= score <= 100。兩處皆應填入 <=。秒選 (D)。

🔍 深度詳解（點擊展開慢動作拆解與常見陷阱）
  1. 數學區間與連續比較映射：
  • 開區間 $(60, 100)$：不含邊界端點，寫作 60 < score < 100。
  • 半開半閉區間 $[60, 100)$：含 60 不含 100，寫作 60 <= score < 100。
  • 閉區間 $[60, 100]$：兩端點皆包含，寫作 60 <= score <= 100。
  1. 錯誤選項逐項診斷：
  • (A) < 與 <：若成績恰好考 60 分或 100 分，會被誤判為 False。
  • (B) <= 與 <：漏掉了滿分 100 分的端點。
  • (C) > 與 <：方向混亂，語意完全扭曲。故選 (D)。

Q-05-01-D01單等號指定 = 與雙等號比較 == 混淆之 SyntaxError 診斷 測試除錯

答案 (C)

⚡ 速解

單等號 = 是「賦值指派（Assignment）」；雙等號 == 才是「相等比較（Equality Check）」。在小括號運算式內寫 x = 10 會直接觸發 SyntaxError: invalid syntax. Maybe you meant '=='?！秒選 (C)。

🔍 深度詳解（點擊展開慢動作拆解與常見陷阱）
  1. 語法錯誤成因剖析：
  • 在 Python 中，指派語句（Assignment Statement）如 x = 10 是一條陳述句（Statement），而不是表達式（Expression），它本身不具備回傳值。
  • 當直譯器在等號右側的小括號內看到單等號 (x = 10) 時，語法解析器判定該位置需要一個可求值的表達式，因此拋出語法錯誤：

SyntaxError: invalid syntax. Maybe you meant '==' or ':=' instead of '='?

  1. 正確寫法：
  • 欲進行數值相等比較，必須使用比較運算子雙等號：

check = (x == 10)

此時 x == 10 求得布林值 True 並指派給 check。

  1. 錯誤選項逐項診斷：
  • (A) 這是編譯時期的語法結構錯誤（SyntaxError），並非執行時期的型態錯誤（TypeError）。
  • (B) 誤將 C 語言（賦值表達式回傳右側值）的特性套用至 Python。
  • (D) 變數重複賦值完全合法，並非 NameError。故選 (C)。

Q-05-01-D02異質型態數值與字串相等比較之型態陷阱診斷 測試除錯

答案 (B)

⚡ 速解

Python 具備嚴格的型態安全性。整數 100 與字串 "100" 型態完全不同（int vs str），直譯器絕不會自動轉型！因此 100 == "100" 必為 False，而 != 必為 True。秒選 (B)。

🔍 深度詳解（點擊展開慢動作拆解與常見陷阱）
  1. 相等運算子（== 與 !=）的型態比較規則：
  • 在 Python 中，相等運算子 == 支援跨型態比對而不會拋出 TypeError。
  • 當比對的兩個物件屬於完全不相容的型態（例如數值型態 int 與序列文字型態 str）時，直譯器判定兩者身分與本質皆不相同，直接回傳 False。
  • 同理，不相等運算子 != 判定兩者確實不相等，直接回傳 True。
  1. 常見考場隱蔽天坑：
  • 初學者若使用 input() 讀入使用者輸入而忘記用 int() 轉型，寫下 if ans == 100:，條件將永遠無法成立，成為完全不報錯的幽靈 Bug！
  1. 錯誤選項逐項診斷：
  • (A) 誤將弱型別語言（如 JavaScript 的 == 隱式轉換）的規則混淆進來。
  • (C) 相等比較（==, !=）支援跨型態比較不會噴錯；只有大小比較（如 100 < "100"）才會拋出 TypeError。
  • (D) 兩者不可能同時相等又同時不相等。故選 (B)。

Q-05-01-P01連續比較式中間運算式求值次數與暫存最佳化分析 效能分析

答案 (A)

⚡ 速解

Python 連續比較式的精妙之處：中間運算式只會被求值「恰好 1 次」！直譯器求出 7 + 5 = 12 後暫存在虛擬機器堆疊上，依序比對 $10 < 12$ 與 $12 < 20$。免除了重複計算開銷。秒選 (A)。

🔍 深度詳解（點擊展開慢動作拆解與常見陷阱）
  1. 連續比較的官方語言規範（Python Language Reference）：
  • 根據 Python 官方語言定義第 6.10 節：

比較式 a < exp < b 在語意上等價於 a < exp and exp < b，但是表達式 exp 保證只會被評估（Evaluated）一次。

  • 這項設計徹底消除了重複計算中間繁重複雜算式（甚至是帶有副作用之函式調用）的效能浪費。
  1. 錯誤選項逐項診斷：
  • (B) 誤以為像傳統手工寫 10 < x + 5 and x + 5 < 20 那樣會計算 2 次加法。
  • (C) 運算次數為 1 次，非 3 次。
  • (D) 連續比較式完全原生支援任意算術表達式。故選 (A)。

Q-05-01-P02連續比較式短路求值（Short-circuit）執行步數分析 效能分析

答案 (D)

⚡ 速解

連續比較 A < B < C 在底層具備短路特性。由左向右先看第一段：$100 < 50$ 為 False。第一道關卡沒過，後面再也不必浪費 CPU 時間去比，立刻收工回傳 False。秒選 (D)。

🔍 深度詳解（點擊展開慢動作拆解與常見陷阱）
  1. 短路求值在連續比較中的具體運作：
  • 表達式 100 < x < 200 等價於 (100 < x) and (x < 200)。
  • 直譯器由左向右求值：
  • 第 1 步：比較 100 < x $\rightarrow 100 < 50 \rightarrow$ 判定為 False。
  • 第 2 步：因為連鎖關係屬於邏輯交集（AND），只要出現一個 False，後續所有項目的真假已完全不影響最終結果必為 False。
  • 因此直譯器立刻短路終止評估，跳過 x < 200，省下運算步驟。
  1. 錯誤選項逐項診斷：
  • (A) 忽略了短路機制。
  • (B) Python 比較式的結合順序一律是由左至右。
  • (C) 連續比較式在 Python 底層原生落實短路。故選 (D)。

Q-05-01-L01鋸齒狀雙向比較（a < b > c）局部極大值邏輯推演 計算邏輯

答案 (B)

⚡ 速解

Python 的連續比較「完全不限制方向必須一致」！a < b > c 的語意嚴格等於 (a < b) and (b > c)。$10 < 25$（真）且 $25 > 15$（真），兩者皆真，代表 $b$ 是局部高峰，回傳 True。秒選 (B)。

🔍 深度詳解（點擊展開慢動作拆解與常見陷阱）
  1. 非單向連續比較的邏輯本質：
  • 許多初學者誤以為連續比較只能寫成遞增（< <）或遞減（> >）。
  • 事實上，在 Python 中任意方向的比較運算子皆可合法鏈結：

a < b > c 嚴格轉換為：(a < b) and (b > c)

  • 幾何意義：
  • $a < b$：從 $a$ 往 $b$ 上升。
  • $b > c$：從 $b$ 往 $c$ 下降。
  • 這正是典型「山峰點（峰值）」的數學判定式！
  1. 數值求值：
  • $10 < 25$ 為 True。
  • $25 > 15$ 為 True。
  • 兩者取交集得出 True。
  1. 錯誤選項逐項診斷：
  • (A) 誤以為運算子方向相反會語法報錯；在 Python 中完全合法。
  • (C) 判斷結果為真，非假。
  • (D) 表達式會被評估為布林值，不會原樣輸出。故選 (B)。

Q-05-01-L02數字字串字典序 vs 數值大小比較之邏輯辨析 計算邏輯

答案 (C)

⚡ 速解

ans1 是字串比字典序，從第一個字元開比：'1' 的 ASCII 碼 (49) 小於 '2' 的 ASCII 碼 (50)，所以 "100" < "20" 為 True！而 ans2 是轉為整數比數值，$100 < 20$ 為 False。輸出 True False。秒選 (C)。

🔍 深度詳解（點擊展開慢動作拆解與常見陷阱）
  1. 字串字典序比對的「字元逐位盲點」：
  • 字串比大小完全不看字串長度！
  • 比對 s1 = "100" 與 s2 = "20" 時，直譯器首先比對兩者的第 0 位字元：

ord('1') = 49，ord('2') = 50。

  • 因為 $49 < 50$，直譯器立刻判定 s1 < s2 為 True，根本不理會 "100" 有三位數而 "20" 只有兩位數。
  1. 純數值大小比對：
  • 透過 int() 轉型後，$100$ 與 $20$ 恢復數學上的整數大小。
  • $100 < 20$ 不成立，回傳 False。
  1. 錯誤選項逐項診斷：
  • (A) 誤以為 "100" < "20" 為假。
  • (B) 誤以為整數 $100 < 20$ 為真。
  • (D) 兩者結果顛倒。故選 (C)。
