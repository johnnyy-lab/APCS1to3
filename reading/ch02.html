Q-02-01-R01混合運算型態自動晉升（染紅效應）追蹤 運行追蹤

對應 單元 2.1

下列 Python 程式執行後，畫面上印出的結果為何？

a = 10
b = 2.0
c = a + b
print(type(c).__name__, c)
🎉 答對了！標準答案是 (A)
⚡ 速解

整數 a = 10 遇到浮點數 b = 2.0 相加時，會觸發「浮點染紅效應（Type Promotion）」，整數被自動晉升為浮點數，計算結果必然是浮點數 12.0，型態名稱為 float。秒選 (A) float 12.0。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 型態晉升機制（Implicit Type Conversion / Coercion）：
  • 在 Python 數值運算體系中，不同數值型態進行二元算術運算時，直譯器會遵循「向高精度型態對齊」的原則。
  • 浮點數（float）能表達實數小數，其表示範圍在概念上比整數（int）更廣泛。因此當 int 與 float 相遇時，直譯器會隱式將整數轉換為浮點數（10 $\to$ 10.0），再執行浮點加法。
  • 計算過程：10.0 + 2.0 = 12.0。
  • 變數 c 參照浮點數物件 12.0，type(c).__name__ 為字串 'float'。
  • print(type(c).__name__, c) 輸出 float 12.0。故選 (A)。
  1. 經典陷阱剖析：
  • (B) 誤以為整數加整數小數部分為 0 會維持整數型態。
  • (C) 誤以為浮點數印出時若無小數會省略 .0（Python 的 float 印出時一定至少有一位小數）。

Q-02-01-R02數值等價性 vs 物件型態等價性追蹤 運行追蹤

對應 單元 2.1

下列 Python 程式執行後，畫面上印出的結果為何？

x = 5
y = 5.0
print(type(x) == type(y), x == y)
🎉 答對了！標準答案是 (A)
⚡ 速解

type(x) 是整數 int，type(y) 是浮點數 float，兩者類別不同，前者比較為 False；但數值比較 5 == 5.0 在數值大小上完全相等，後者為 True。秒選 (A) False True。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 型態比對與數值比較的本質差異：
  • 型態比對 type(x) == type(y)：
  • type(5) 回傳 <class 'int'>。
  • type(5.0) 回傳 <class 'float'>。
  • 兩者指向不同的型態物件，故比對結果為 False。
  • 數值比較 x == y：
  • Python 支援跨型態數值比較（Numeric Equality）。在比對 5 == 5.0 時，直譯器會將兩者在數值軸上對齊，數學上 5 與 5.0 數值相等，故回傳 True。
  • 第 3 行印出 False True。故選 (A)。
  1. APCS 考場重點：
  • 數值相等不代表型態相同！在字典（dict）或集合（set）中，因為 hash(5) == hash(5.0) 且 5 == 5.0，5 與 5.0 會被視為相同鍵值（Key Collision），這是高頻進階考點。

val = 42.0
if [____](val) == float:

執行後成功印出 42 int。空格 [____] 處應填入何種 Python 內建函式？

Python 查詢物件類別型態的內建函式為 type()。秒選 (A)。

  • 當傳入 val = 42.0 時，type(val) 回傳 <class 'float'>，與等號右側的內建型態名稱 float 比對結果為 True。

Q-02-01-F02浮點數科學記號字面常數標記填空 程式填空

對應 單元 2.1

在科學計算與 APCS 題目中，常需要表示極大或極小的浮點數常數。例如表示 1.5 毫克（$1.5 \times 10^{-3}$ 公克）：

mass = 1.5[____]-3
print(mass, type(mass).__name__)

執行後成功印出 0.0015 float。空格 [____] 處應填入何種字母（大小寫皆可）？

🎉 答對了！標準答案是 (A)
⚡ 速解

科學記號的 10 的次方指數記號為 e 或 E（Exponent），表示浮點數字面值。秒選 (A)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 科學記號浮點常數（Scientific Notation Literals）：
  • Python 語法支援以 e 或 E 作為底數 10 的指數部分，格式為 數字e指數，相當於 $\text{數字} \times 10^{\text{指數}}$。
  • 1.5e-3 代表 $1.5 \times 10^{-3} = 0.0015$。
  • 只要常數中包含 e 或小數點 .，Python 直譯器一律自動將其解析為雙精度浮點數（float）。
  • 輸出 0.0015 float。故選 (A)。
  1. 延伸常識：
  • 1e6 代表 $10^6 = 1000000.0$（請注意型態依然是 float 而非 int！）。

Q-02-01-D01APCS 輸出格式除錯（4.0 vs 4 之 WA 陷阱） 測試除錯

對應 單元 2.1

APCS 與 ZeroJudge 題目要求計算兩整數平均，若結果為整數必須輸出整數格式（例如輸出 4），若為小數則保留小數（例如輸出 4.5）。小明寫了如下程式：

a = 5
b = 3
avg = (a + b) / 2
print(avg)

執行後畫面上印出 4.0，因此遭到線上評判系統判定為 **WA（Wrong Answer）**。為了徹底修復此問題並兼顧所有可能數字，下列哪一個改寫方案最嚴謹正確？

🎉 答對了！標準答案是 (A)
⚡ 速解

斜線除法 / 必定產生浮點數 4.0，利用 Python 浮點數內建的 avg.is_integer() 判斷小數是否為 0，若為真則轉成 int(avg) 印出 4，否則保留原小數。秒選 (A)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. APCS 考場最痛失分陷阱（Wrong Answer）：
  • Python 3 的單斜線除法 / 是「真除法（True Division）」，無論能否除盡，結果一律強制轉為 float。8 / 2 出來是 4.0 而非 4。
  • 許多題目對輸出格式有嚴格字元比對要求，多出 .0 會直接判定格式錯誤或答案錯誤。
  1. 最佳工程修復手段：
  • float 物件具備內建方法 .is_integer()，能精準判斷該浮點數是否沒有小數部分（例如 4.0.is_integer() 為 True，4.5.is_integer() 為 False）。
  • 搭配三元運算式：int(avg) if avg.is_integer() else avg，既能在整除時輸出 4，又能在不整除（如 (5+4)/2 = 4.5）時正確輸出 4.5。故選 (A)。
  1. 各錯誤選項風險：
  • (B) // 2 會將 4.5 截斷成 4，造成計算錯誤。
  • (C) 若數值為 10.05，字串替換會誤把 10.05 變成 15，造成嚴重災難。
  • (D) round(4.5) 會把小數四捨五入抹殺。

Q-02-01-D02浮點數精度極限與二進位捨入誤差除錯 測試除錯

對應 單元 2.1

下列 Python 程式執行後，畫面上印出的結果為何？背後成因為何？

x = 0.1 + 0.2
if x == 0.3:
    print("Equal")
else:
    print("Not Equal")
🎉 答對了！標準答案是 (A)
⚡ 速解

電腦科學界的經典常識：在二進位浮點數標準（IEEE 754）中，0.1 與 0.2 都是無窮循環小數，相加後等於 0.30000000000000004，絕對不等於 0.3，因此印出 Not Equal。秒選 (A)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. IEEE 754 二進位浮點數限制：
  • 人類慣用十進位（分母為 10 的因數 2 與 5 才能除盡，如 $1/2 = 0.5$、$1/5 = 0.2$、$1/10 = 0.1$）。
  • 但電腦硬體是二進位（分母只能是 2 的次方才能除盡，如 $1/2 = 0.5$、$1/4 = 0.25$、$1/8 = 0.125$）。
  • 十進位的 0.1 在二進位中是無限循環小數：$0.0001100110011..._2$。
  • 在 53 位元尾數長度限制下被迫截斷，因此 0.1 + 0.2 在記憶體中的實際數值是 0.30000000000000004。
  • 執行 0.30000000000000004 == 0.3 結果為 False，進入 else 區塊印出 Not Equal。故選 (A)。
  1. 工程防範方案：
  • 若需要比較兩浮點數是否相等，絕不可直接用 ==，應使用 math.isclose(a, b) 或 abs(a - b) < 1e-9。

Q-02-01-P01Python 3 大整數任意精度效能分析 效能分析

對應 單元 2.1

在 C/C++ 或 Java 等靜態語言中，32 位元有號整數最大值為 $2^{31}-1 = 2147483647$，超過即發生溢位（Overflow）。然而在 Python 3 中，執行下列程式碼卻能正確無誤印出長達 302 位的精確整數：

x = 2 ** 1000
print(x)

關於 Python 3 整數（int）的底層設計與效能表現，下列說明何者最正確？

🎉 答對了！標準答案是 (A)
⚡ 速解

Python 3 的 int 擁有「任意精度大整數」特性，只要電腦記憶體足夠，算幾千幾萬位都不會溢位！但代價是大整數運算時間會隨長度增加。秒選 (A)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 任意精度大數原理：
  • 在 Python 3 中，整數（int）不是單純的 32/64 位元 CPU 暫存器整數，而是一個完整的 C 語言結構體物件（PyLongObject）。
  • 它使用動態陣列（每 30 位元一個數位模組）來儲存大整數的每個片段。
  • 當數值需要更多空間時，Python 會自動動態擴展記憶體陣列。因此不管是 2**1000 還是 factorial(100)，都能百分之百精確計算，徹底免除了傳統語言的整數溢位 Bug。故選 (A)。
  1. 效能代價：
  • 一般落在 64 位元內的小整數運算速度極快；一旦數值達到數千位以上，乘法與除法需要依賴多精度演算法（如 Karatsuba 乘法），運算耗時與記憶體將隨位數增加。

對應 單元 2.1

在 APCS 程式檢定的大規模迴圈（如 $10^7$ 次迭代）與圖論/動態規劃中，優秀的選手會刻意將所有狀態與計算保持為純整數（int），避免過早引入浮點數（float）。下列關於此策略優勢的敘述何者最正確？

🎉 答對了！標準答案是 (A)
⚡ 速解

整數運算在 CPU 邏輯單元（ALU）中完全精確、絕無誤差，又能使用位元運算加速，是競賽演算法最穩定可靠的基石！秒選 (A)。

  • 浮點數伴隨累積捨入誤差，容易在判斷邊界條件（如 if x == target:）時因微小偏差導致死迴圈或 WA。

  • 整數可以直接進行位元操作（>>、<<、&、|、^），在狀態壓縮 DP、進位制轉換與奇偶性判定時具備極限效能優勢。故選 (A)。

Q-02-01-L01浮點數截斷導致「少 1 元」的找零邏輯陷阱 計算邏輯

對應 單元 2.1

超商結帳系統需要將美元金額換算為「分（cents，1 美元 = 100 分）」，商品單價為 1.15 美元，工程師撰寫了如下程式：

price = 1.15
cents = int(price * 100)
print(cents)

執行這段程式後，畫面上印出的結果為何？

🎉 答對了！標準答案是 (A)
⚡ 速解

1.15 * 100 在二進位浮點數乘法後實際為 114.99999999999999！隨後被 int() 無條件捨去小數，結果慘痛變成 114，白白少算 1 分錢！秒選 (A) 114。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 浮點數截斷血淚史：
  • 十進位小數 1.15 在 IEEE 754 二進位表示中存在微小下溢。
  • 執行 1.15 * 100 時，底層算出的浮點數值實為 114.99999999999999。
  • Python 的 int() 函式轉換規則是「無條件捨去小數點後的所有位數（Truncate towards zero）」，因此 int(114.99999999999999) 直接被無情截斷為 114！
  • 輸出為 114。故選 (A)。
  1. 金融與 APCS 演算法修復方式：
  • 方案一（四捨五入）：round(price * 100) 得到正確的 115。
  • 方案二（純整數換算）：輸入時直接以整數讀入分（例如以字串拆解，讀入 1 與 15，計算 1 * 100 + 15），全程避開 float。
  • 方案三：使用 Python 內建的高精度小數模組 from decimal import Decimal。

Q-02-01-L02多科成績總分、平均與型態轉換鏈綜合追蹤 計算邏輯

對應 單元 2.1

學生成績計算系統處理國文、英文與數學成績，並加上平時獎勵分 0.5 分：

chinese = 90
english = 85
math = 92

total = chinese + english + math
avg = total / 3
bonus = 0.5
final_score = avg + bonus
is_passed = final_score >= 60

print(type(total).__name__, type(avg).__name__, final_score, is_passed)

執行這段程式後，畫面上印出的結果為何？

🎉 答對了！標準答案是 (A)
⚡ 速解

total = 90 + 85 + 92 = 267（三整數相加為 int）。avg = 267 / 3 = 89.0（單斜線除法必為 float）。final_score = 89.0 + 0.5 = 89.5。89.5 >= 60 為 True。秒選 (A) int float 89.5 True。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 數值型態演變鏈逐行拆解：
  • 總分計算：total = 90 + 85 + 92 = 267。參與運算的皆為整數，結果為 int。
  • 平均計算：avg = total / 3 = 267 / 3 = 89.0。在 Python 3 中，/ 永遠回傳 float，即使能整除也必然帶有 .0。
  • 獎勵分加總：final_score = avg + bonus = 89.0 + 0.5 = 89.5。浮點加法，型態為 float。
  • 及格檢驗：is_passed = 89.5 >= 60，比較運算子傳回布林值 True。
  • 格式化列印：print(type(total).__name__, type(avg).__name__, final_score, is_passed)
  • type(total).__name__ 為 'int'。
  • type(avg).__name__ 為 'float'。
  • 輸出 int float 89.5 True。故選 (A)。
