Q-13-01-R01input() 的提示文字也會進入 stdout 運行追蹤

對應 單元 13.1

在線上評判系統（OJ）上，下列程式讀到測資 2 與 3，期望輸出只有 5。OJ 實際收到的輸出內容為何？

a = int(input("請輸入第一個數字："))
b = int(input("請輸入第二個數字："))
print(a + b)
🎉 答對了！標準答案是 (B)
⚡ 速解

input() 的提示字串寫進 stdout，OJ 只看 stdout 比對，所以提示文字會混在輸出裡造成 WA，秒選 (B)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作：
  • OJ 把測資接到程式的 stdin，只攔截 stdout 與期望輸出逐字元比對。
  • input("請輸入第一個數字：") 會先把提示文字印到 stdout（不加換行），再讀入一行。
  • 因此 stdout 的實際內容是提示文字與 print 的結果串在一起：請輸入第一個數字：請輸入第二個數字：5。
  • 與期望輸出 5 比對不符，判定為 WA。故選 (B)。
  1. 選項逐項診斷：
  • (A) 只有把提示文字誤以為「只出現在螢幕、不進輸出串流」才會這樣選。
  • (B) 提示字串屬於 stdout，與 print 的輸出一起被 OJ 收走，逐字元比對後判定 WA。
  • (C) 順序錯誤。提示文字在讀入當下就寫出，一定出現在對應 print 之前。
  • (D) OJ 完全允許 input()，測資就是透過 stdin 餵進來的。
  1. APCS 考場心法與常見陷阱：
  • 考場寫 input() 絕對不加提示文字，寫成光禿禿的 input()；提示字是本地練習的方便功能，上了 OJ 就是 WA 元凶。

Q-13-01-R02索引越界時畫面印出的內容 運行追蹤

對應 單元 13.1

下列程式在 OJ 上讀到測資 5，執行後畫面印出的結果為何？

data = [1, 2, 3]
n = int(input())
print(data[n])
🎉 答對了！標準答案是 (D)
⚡ 速解

data[5] 超出 0 到 2 的範圍，程式拋出 IndexError 後中止，OJ 判定 RE，秒選 (D)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作：
  • data = [1, 2, 3] 只有索引 0、1、2 可用。
  • n = 5，data[5] 瞬間拋出 IndexError: list index out of range。
  • 程式在此中斷，print 來不及執行，OJ 以「非零結束碼」判 RE。
  • 畫面上留下的就是 Traceback 最後一行的錯誤訊息。故選 (D)。
  1. 選項逐項診斷：
  • (A) 誤把索引值當成元素值印出來。
  • (B) 誤以為越界會自動夾到最後一個元素。Python 不會自動截斷索引。
  • (C) Traceback 屬於 stderr，但題目問的是畫面印出的內容，錯誤訊息確實會出現。
  • (D) 越界存取串列會拋出 IndexError，程式中止且 OJ 判 RE。
  1. APCS 考場心法與常見陷阱：
  • 走訪前先確認索引範圍：for i in range(len(data)) 或使用 for x in data，是防堵 IndexError 的兩條鐵律。

Q-13-01-F01補上同一行多個數值的讀取寫法 程式填空

對應 單元 13.1

OJ 測資把兩個數字放在同一行（3 5），想讓程式印出 8，空格應填入哪一個？

______
print(a + b)
🎉 答對了！標準答案是 (A)
⚡ 速解

同一行的多個數值要先用 split() 切開再逐一轉整數，map(int, ...) 一次搞定，秒選 (A)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作：
  • input() 一次只讀一行，"3 5".split() 切成 ['3', '5']。
  • map(int, ...) 把每個字串轉成整數，左邊 a, b 依序接收，得到 a = 3, b = 5。
  • print(a + b) 印出 8，與期望輸出一致而得 AC。故選 (A)。
  1. 選項逐項診斷：
  • (A) split() 依空白切割、map(int, ...) 批量轉型、左側解包接收，是同行多數的標準寫法。
  • (B) 兩個 input() 會各讀一行，同一行的 3 5 會被第一個 int() 轉失敗，拋出 ValueError 判 RE。
  • (C) int("3 5") 同樣無法轉換，拋出 ValueError。
  • (D) input() 回傳整串字串，解包成兩個字元會得到 a = '3'、b = ' '，後面字串相加印出 3 而非 8。
  1. APCS 考場心法與常見陷阱：
  • 先看測資格式再決定讀法：一行一值用 int(input())，一行多值用 map(int, input().split())，行數不定才搭配迴圈或 try。

Q-13-01-F02修掉讓程式無法啟動的全形冒號 程式填空

對應 單元 13.1

下列程式執行時發生 SyntaxError: invalid character '：' (U+FF1A)，導致 OJ 判定 CE。想印出 positive，空格（第 2 行結尾）應填入哪一個？

n = int(input())
if n > 0______
    print("positive")
🎉 答對了！標準答案是 (C)
⚡ 速解

結構控制句尾必須是半形冒號 :；全形冒號在 Python 裡是非法字元，連執行的機會都沒有，秒選 (C)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作：
  • 中文輸入法最常留下全形冒號 ：（U+FF1A），Python 直譯器在編譯檢查期就拒收。
  • 錯誤訊息 SyntaxError: invalid character '：' (U+FF1A) 直接點名這個字元。
  • 換成半形冒號 : 後，if n > 0: 語法完整，測資給正數就會印出 positive。故選 (C)。
  1. 選項逐項診斷：
  • (A) 全形分號同樣是非法字元，只會把 CE 的訊息換一個字。
  • (B) 補括號不會補齊 if 結構，仍然是 SyntaxError。
  • (C) 半形冒號 : 是 if 句的唯一合法結尾，改完即可正常執行。
  • (D) 逗號無法結束 if 句，仍然 SyntaxError。
  1. APCS 考場心法與常見陷阱：
  • CE 是「程式還沒開始跑就陣亡」，最常見兇手是全形標點與 Tab／空格混用；送出前用眼睛掃一遍冒號、引號、括號是不是半形。

Q-13-01-D01迴圈內重複線性搜尋導致 TLE 測試除錯

對應 單元 13.1

想判斷 target 是否存在於 nums 並印出 True。現在執行程式超出時間限制（TLE）。只改一行，哪一個改法會印出預期結果？

nums = list(range(100000))
target = 99999
found = False
for x in nums:
    if x in nums:
        found = True
        break
print(found)
🎉 答對了！標準答案是 (A)
⚡ 速解

x in nums 每圈都要掃完整串，10 萬乘 10 萬直接爆量；改成跟 target 比相等就只是線性掃描，秒選 (A)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作：
  • 現況：外圈 10 萬次，每圈的 x in nums 又內部掃描最多 10 萬次，總操作數約 $10^{10}$，遠超過 1 秒約 $10^7$ 的上限。
  • 題目要判斷的是「走訪到的元素是不是目標」，直接 x == target 即可，每圈只做一次比較。
  • 改成 if x == target 後，掃到 99999 就 break，印出 True。故選 (A)。
  1. 選項逐項診斷：
  • (A) 移除迴圈內的 $O(N)$ 操作，整體從 $O(N^2)$ 降為 $O(N)$，10 萬筆輕鬆在時限內跑完。
  • (B) 換成 range 只是換個走訪來源，x in nums 的內部掃描還在，仍然 TLE。
  • (C) 初始值改成 None 不影響運算量，時限照樣爆。
  • (D) 改輸出內容不減少任何運算，還是 TLE，而且輸出也不對。
  1. APCS 考場心法與常見陷阱：
  • TLE 先數圈數：外圈乘內圈。迴圈裡出現 in list、insert(0)、pop(0)、字串 +，每一項都是把線性掃描藏進迴圈的隱形地雷。

Q-13-01-D02整數輸出成浮點數導致 WA 測試除錯

對應 單元 13.1

OJ 測資為 8 與 2，期望輸出 4。現在執行程式印出 4.0，判定 WA。只改第 3 行，哪一個改法會印出預期結果？

a = int(input())
b = int(input())
print(a / b)
🎉 答對了！標準答案是 (B)
⚡ 速解

期望是整數商，要用整數除法 //；/ 一定給浮點數，印出 4.0 就會被判 WA，秒選 (B)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作：
  • Python 3 的 / 一律回傳浮點數，8 / 2 的結果是 4.0，印出來多一個小數點。
  • OJ 逐字元比對，4.0 與 4 不同，直接 WA。
  • 改成 a // b 取整數商，印出 4，與期望一致。故選 (B)。
  1. 選項逐項診斷：
  • (A) 取餘數，8 % 2 是 0，不是期望的 4。
  • (B) 整數除法 // 回傳整數，8 // 2 印出 4，格式與數值都對。
  • (C) 相乘得 16，數值錯誤。
  • (D) 次方得 64，數值錯誤。
  1. APCS 考場心法與常見陷阱：
  • 「答案對卻 WA」最常見的就是型態：要求整數卻印出 4.0、要求小數卻印出 4。看清題目的輸出範例有幾位小數。

Q-13-01-P01雙重迴圈的運算次數量級 效能分析

對應 單元 13.1

下列程式執行時，cnt += 1 這一行共執行幾次？

n = 100000
cnt = 0
for i in range(n):
    for j in range(n):
        cnt += 1
print(cnt)
🎉 答對了！標準答案是 (C)
⚡ 速解

外圈 10 萬次、每圈內圈再 10 萬次，$10^5 \times 10^5 = 10^{10}$，在 OJ 上必定 TLE，秒選 (C)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作：
  • 外圈執行 $10^5$ 次，每進入一次外圈，內圈完整跑 $10^5$ 次。
  • 總次數 = $10^5 \times 10^5 = 10^{10}$。
  • APCS 考場 1 秒約可做 $10^7$ 次操作，$10^{10}$ 是上限的 1000 倍，連跑完的機會都沒有。故選 (C)。
  1. 選項逐項診斷：
  • (A) 只數了外圈次數，漏掉內圈的放大效應。
  • (B) 這是 1 秒的上限量級 $10^7$，不是這個程式的總次數。
  • (C) 雙重迴圈總次數為兩層圈數相乘，$10^5 \times 10^5 = 10^{10}$，判定 TLE。
  • (D) 誤把兩層圈數相加。巢狀迴圈是乘法關係不是加法。
  1. APCS 考場心法與常見陷阱：
  • 送出前先做量級心算：$N = 10^5$ 時 $O(N)$ 約 0.02 秒可過，$O(N^2)$ 要 100 秒必死；$N \le 10^3$ 才輪得到 $O(N^2)$ 出場。

Q-13-01-P02線性累加的運算次數量級 效能分析

對應 單元 13.1

下列程式執行時，total += i 這一行共執行幾次？

n = 1000000
total = 0
for i in range(n):
    total += i
print(total)
🎉 答對了！標準答案是 (A)
⚡ 速解

單層迴圈跑 $N$ 次就是 $10^6$ 次，遠在 1 秒的 $10^7$ 上限之內，不會 TLE，秒選 (A)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作：
  • range(n) 讓迴圈剛好執行 $n = 10^6$ 次，每圈一次 total += i。
  • 總次數 = $10^6$，量級寫成 $O(N)$。
  • 與 $10^7$ 的上限相比只占十分之一，正常情況下可 AC。故選 (A)。
  1. 選項逐項診斷：
  • (A) 單層迴圈次數等於圈數上限 $10^6$，是線性時間 $O(N)$ 的典型代表。
  • (B) 誤加成兩層的量級，這裡只有一層迴圈。
  • (C) 誤以為是平方級，只有巢狀迴圈才會跳到這個量級。
  • (D) 把次數砍半沒有根據，range(n) 不會少跑一半。
  1. APCS 考場心法與常見陷阱：
  • 同樣是 10 的冪次，$10^6$ 與 $10^{10}$ 在考場上是生與死的差別；判斷 TLE 的順序永遠是「先數有幾層迴圈，再估每層幾次」。

Q-13-01-L01解包數量不符時的評判結果 計算邏輯

對應 單元 13.1

下列程式在 OJ 上讀到只含一個數字的測資 3（期望輸出兩數之和）。這個程式最可能得到哪一個評判結果？

a, b = map(int, input().split())
print(a + b)
🎉 答對了！標準答案是 (D)
⚡ 速解

測資只有一個值，左邊卻有兩個變數要接，拋出 ValueError 讓程式中止，OJ 判 RE，秒選 (D)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作：
  • input().split() 對 3 只切出一個元素，map(int, ...) 產生一個值。
  • 左邊 a, b 需要兩個值，數量不符立刻拋出 ValueError: not enough values to unpack (expected 2, got 1)。
  • 程式在計算前就中止，沒有任何輸出，OJ 以非零結束碼判 RE。
  • 代入三個數的測資 3 5 7 同樣是 ValueError: too many values to unpack (expected 2)，一樣 RE。故選 (D)。
  1. 選項逐項診斷：
  • (A) 語法完全合法，問題發生在執行期的資料量，不可能 AC。
  • (B) WA 是「有輸出但內容不符」；這個程式根本來不及印出任何東西。
  • (C) 程式可以正常啟動並讀到測資，不是編譯期的語法問題。
  • (D) 解包數量與測資欄數不符屬執行時期錯誤，OJ 判 RE。
  1. APCS 考場心法與常見陷阱：
  • 讀取寫法要對準測資格式：欄數固定的同行多值用 a, b = map(int, input().split())；欄數可能不同時，先用 nums = list(map(int, input().split())) 再接長度處理。

Q-13-01-L02答案數字大不會直接導致 TLE 計算邏輯

對應 單元 13.1

下列程式在 OJ 上讀到 100000 並印出一個很大的數。為什麼它不會因為「答案太大」而 TLE？

n = int(input())
print(n * n)
🎉 答對了！標準答案是 (B)
⚡ 速解

Python 整數沒有上限，一次乘法就得到答案；TLE 只問「做了幾次運算」，秒選 (B)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作：
  • 程式的運算量是常數級：讀入一次、相乘一次、印出一次，與 $n$ 的大小無關。
  • Python 的整數是任意精度，$10^{10}$ 只占幾十個位元，既不爆範圍也不爆記憶體。
  • 因此只要輸出格式正確，這個程式可以拿到 AC。故選 (B)。
  1. 選項逐項診斷：
  • (A) 答案的數字大小與 TLE 無關；TLE 的唯一原因是運算次數超過時限。
  • (B) 常數次運算對上 1 秒的 $10^7$ 上限綽綽有餘，Python 大整數也不會溢出。
  • (C) MLE 要看實際配置的記憶體，一個大整數遠不足以觸發。
  • (D) OJ 比對的是輸出內容，不是數值範圍；印出 $10^{10}$ 完全合法。
  1. APCS 考場心法與常見陷阱：
  • 把「答案很大」和「算很久」分開：前者頂多擔心輸出長度與浮點格式，後者才是 TLE。診斷 TLE 請回到圈數與量級。

## 單元 13.2 語法錯誤深度排查與 Traceback 閱讀心法

Q-13-02-R01未閉合方括號的 Traceback 座標 運行追蹤

對應 單元 13.2

下列程式執行時發生 SyntaxError。以 Python 3.13 實跑，Traceback 顯示的內容為何？

nums = [1, 2, 3
print(nums[1])
🎉 答對了！標準答案是 (C)
⚡ 速解

Python 3.13 會直接點名哪個括號沒關、它在第幾行，所以錯誤指在行號 1 的 [，秒選 (C)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作：
  • 第 1 行的 [ 沒有對應的 ]，直譯器在編譯檢查期就發現串列字面值沒有收尾。
  • 3.13 的訊息格式是 SyntaxError: '[' was never closed，行號停在開括號的第 1 行，游標對準 [ 的正下方。
  • 修法是在第 1 行結尾補上 ]，而不是去改第 2 行。故選 (C)。
  1. 選項逐項診斷：
  • (A) 舊版 Python 才會把未閉括號的錯誤丟到下一行；3.13 已改為指向開括號的行。
  • (B) IndentationError 是縮排問題，這個程式兩行都沒有區塊結構，不會出現這個訊息。
  • (C) 3.13 直接告知「'[' 從未被關閉」並標出所在行與游標位置，修補目標明確。
  • (D) NameError 是執行期錯誤；這個程式連編譯都沒過，不會有變數未定義的問題。
  1. APCS 考場心法與常見陷阱：
  • 看到 was never closed 就沿著行號去找那個括號，把對應的 ]、)、} 補上；別被「錯誤出現在下一行」的舊經驗帶走。

Q-13-02-R02多重語法錯誤的掩蓋現象 運行追蹤

  • (B) 裸露 except 雖然接得到，但會連程式錯誤、中斷訊號一起吞掉，考場上難以定位真正問題，不算是好解法。
  • (C) 改成不轉型就沒有例外，但 n 會是字串 "abc"，後面拿它運算仍會出錯，而且印出的不是 0。

(D) 只改預設值，型別不符的問題沒解決，程式照樣中止。

  1. APCS 考場心法與常見陷阱：
  • 寫 except 前先確認那行程式「可能拋哪一種錯」；接錯型別等於沒寫防守，這是 try 最常見的假安全。

Q-13-04-D02except 只寫 pass 讓變數沒被定義 測試除錯

對應 單元 13.4

測資為 abc 時，預期印出 0。現在執行程式拋出 NameError: name 'result' is not defined。只改第 5 行，哪一個改法會印出預期結果？

try:
    n = int(input())
    result = n * 2
except ValueError:
    pass
print(result)
🎉 答對了！標準答案是 (B)
⚡ 速解

例外路徑也要給 result 一個值，把 pass 改成 result = 0，兩條路就都有定義，秒選 (B)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作：
  • 測資 abc：int() 拋出 ValueError，result = n * 2 根本沒被執行。
  • except ValueError: pass 什麼都沒做，result 從未誕生。
  • print(result) 於是拋出 NameError: name 'result' is not defined。
  • 改成 result = 0 後，例外路徑也有值，印出 0。故選 (B)。
  1. 選項逐項診斷：
  • (A) 改成接 NameError 接不住 ValueError，程式還是在 int() 就中止。
  • (B) try 內賦值的變數在例外路徑可能不存在，except 要補上預設值。
  • (C) n 在例外路徑同樣沒有被賦值，改成印 n 只是換一個 NameError。

(D) 成功路徑也會變成印 0，運算結果不見了，不符合預期。

  1. APCS 考場心法與常見陷阱：
  • 在 try 之前先給變數初始值（例如 result = 0），或是在每個 except 裡補值；原則是「不管走哪條路，後面用到的變數都要有定義」。

Q-13-04-P01例外路徑與成功路徑的執行次數 效能分析

對應 單元 13.4

下列程式執行時，ok += 1 這一行共執行幾次？

data = [1, 2, "x", 4]
total = 0
ok = 0
for x in data:
    try:
        total += int(x)
        ok += 1
    except ValueError:
        continue
print(total, ok)
🎉 答對了！標準答案是 (D)
⚡ 速解

四個元素裡只有 "x" 轉不動，其餘三次都成功，ok += 1 共執行 3 次，秒選 (D)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作：
  • x = 1：int(1) = 1，total = 1，ok = 1。
  • x = 2：total = 3，ok = 2。
  • x = "x"：int("x") 拋出 ValueError，跳到 except 執行 continue，ok 不增加。
  • x = 4：total = 7，ok = 3。
  • 印出 7 3，ok += 1 共 3 次。故選 (D)。
  1. 選項逐項診斷：
  • (A) 誤以為四個元素全成功。"x" 轉型失敗走了例外路徑。
  • (B) 漏算後面成功的 4。continue 只跳過當圈，迴圈還會繼續。
  • (C) 這是把例外路徑當成全部，忽略三次成功。

(D) 三次成功、一次例外，成功次數 3，total 為 7。

  1. APCS 考場心法與常見陷阱：
  • continue 在 except 裡只結束「這一圈」，不是結束整個迴圈；數次數時要把每個元素依序代一遍，標出誰走例外路徑。

Q-13-04-P02except 與 finally 的觸發次數差別 效能分析

對應 單元 13.4

下列程式執行時，except 區塊內的 count += 1 共執行幾次？

count = 0
for i in range(3):
    try:
        if i == 1:
            raise ValueError
    except ValueError:
        count += 1
    finally:
        count += 10
print(count)
🎉 答對了！標準答案是 (A)
⚡ 速解

只有 i = 1 拋出例外，except 只跑那一次；finally 則是每圈都跑共 3 次，秒選 (A)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作：
  • i = 0：try 沒有拋錯，except 不執行，finally 執行，count = 10。
  • i = 1：raise ValueError 觸發例外，except 執行 count += 1（此時 11），finally 再執行 count += 10（此時 21）。
  • i = 2：沒有拋錯，只走 finally，count = 31。
  • 印出 31；except 內只執行 1 次，finally 內執行 3 次。故選 (A)。
  1. 選項逐項診斷：
  • (A) 三圈裡只有一圈拋出例外，except 只被觸發一次。
  • (B) 這是 finally 的次數。finally 每圈必定執行，與有沒有拋錯無關。
  • (C) 誤以為例外沒有發生。i == 1 時確實 raise 了。

(D) 沒有第二圈拋錯，沒有第二次 except。

  1. APCS 考場心法與常見陷阱：
  • except 看「有沒有拋錯」，finally 看「有幾圈」；把兩個次數分開數，是最容易拿分的地方。

Q-13-04-L01if 防守與 try 防守的選擇準則 計算邏輯

對應 單元 13.4

下列程式印出 3。哪一句描述這個寫法的取捨，換成其他資料也成立？

data = ["1", "2", "x", "4"]
nums = []
for s in data:
    if s.isdigit():
        nums.append(int(s))
print(len(nums))
🎉 答對了！標準答案是 (B)
⚡ 速解

isdigit() 一看就知道能不能轉，用 if 擋掉最乾淨；try 留給 EOF 這類事前問不出來的狀況，秒選 (B)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作：
  • "1".isdigit()、"2".isdigit()、"4".isdigit() 都為真，三個值進入 nums。
  • "x".isdigit() 為假，直接跳過，不會碰到會拋錯的 int()。
  • len(nums) 印出 3。故選 (B)。
  1. 選項逐項診斷：
  • (A) 能簡單事前判斷時用 try 反而模糊意圖，也會讓真正沒料到的錯誤被順手吞掉。
  • (B) 原則：可檢查就先檢查（if、isdigit()、in），不可檢查才捕捉（EOFError、外部資源失敗）。
  • (C) 字串正是 if 最好處理的對象，isdigit() 就是現成的檢查器。

(D) try 的設定成本高於一次布林判斷，且語意不同；兩者不等價。

  1. APCS 考場心法與常見陷阱：
  • 判斷順序：先問「這個錯我能不能用一個條件事先避開？」可以就用 if；不行（例如檔案結尾）才用 try／except，並且只接特定例外。

Q-13-04-L02try、except、else、finally 的完整語意 計算邏輯

對應 單元 13.4

下列程式執行後，畫面上印出的結果為何？

def g(n):
    try:
        r = 10 // n
    except ZeroDivisionError:
        return "E"
    else:
        return "OK" + str(r)
    finally:
        print("F")

print(g(2), g(0))
🎉 答對了！標準答案是 (C)
⚡ 速解

兩次呼叫的 finally 都先印出 F，回傳值最後才一起印，所以是 F、F、OK5 E，秒選 (C)。

🔍 深度詳解（慢動作拆解與常見陷阱）
  1. 慢動作：
  • g(2)：10 // 2 = 5 沒有出錯，try 成功；else 在沒出錯時執行，準備回傳 "OK5"；finally 先跑，印出 F；接著 "OK5" 交還。
  • g(0)：10 // 0 拋出 ZeroDivisionError，except 接住並準備回傳 "E"；finally 先跑，印出 F；接著 "E" 交還。
  • 最後 print("OK5", "E") 印出 OK5 E，畫面順序為 F、F、OK5 E。故選 (C)。
  1. 選項逐項診斷：
  • (A) 漏掉兩次 finally 的輸出。
  • (B) 順序錯誤。finally 在回傳值交給呼叫端之前就跑完，不會排在回傳值後面。
  • (C) else 只在 try 完全成功時執行，finally 則兩次都執行，且都早於回傳值交還。
  • (D) 兩次呼叫的順序固定為先 g(2) 再 g(0)，結果不會對調。
  1. APCS 考場心法與常見陷阱：
  • 四塊記憶法：try 放手做、except 接特定錯、else 沒錯才做、finally 怎樣都做；計算輸出順序時，把每次 finally 插在回傳值之前就對了。
